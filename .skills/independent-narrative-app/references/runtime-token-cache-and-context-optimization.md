## 作用

这本分册只收口两件事：

1. 由 AI/实现者预估并核对一次模型请求会使用多少 token。
2. 在不改变 Prompt 语义、世界书命中和玩家体验的前提下，独立优化供应商 Prompt Cache 或同类 token 缓存的命中率。

它不是要求小白学习 tokenizer、缓存键或供应商计费规则的教程。技术判断默认由 Skill 中的 AI 完成，作者只确认模型、成本、隐私和是否允许缓存等产品边界。

## 读取条件

- 项目开始接入真实模型，需要确认上下文上限和输出预留。
- Prompt、世界书、历史、COT 或状态逐渐增多，需要预估请求规模。
- 供应商支持 Prompt Cache、cached input、cache read/write token 或显式缓存断点。
- 同样的固定 Prompt 每轮重复发送，但缓存命中低、费用或首 token 延迟异常。
- 修改 Prompt/Lore/Profile 后，需要判断哪些缓存应继续复用、哪些必须失效。

如果目标模型没有缓存能力，本册仍执行 Token 预估，但跳过命中优化并记录“不支持”，不让作者为了缓存更换作品设计。

## 前置输入

- `Prompt Assembly Contract`、`COT Assembly Plan`、`Lore Runtime Contract`。
- 目标供应商、模型/Profile、上下文上限和真实 usage 字段。
- Prompt 模块、世界书、历史、状态、宏展开和输出协议的版本/指纹。
- 作者确认的费用上限、隐私边界、缓存开关和允许的降级方式。

## 用户与 AI 的职责

| 参与者 | 需要决定什么 | 不需要承担什么 |
|---|---|---|
| 作者/用户 | 使用哪个模型或接口、费用大致上限、敏感内容是否允许供应商缓存、是否优先成本或延迟 | 不需要计算 token、设计缓存键、判断稳定前缀或手工调顺序 |
| Skill/AI | 读取模型能力、估算 token、识别稳定/动态区块、制定缓存命中方案、记录失效条件和解释结果 | 不替作者改变剧情、角色、世界书或玩家主权 |
| 实现者 | 落实供应商协议、usage 解析、缓存断点、Trace 和测试 | 不用缓存命中率证明语义正确 |

用户回答“不知道”时，AI采用保守默认：保留足够输出空间、不缓存敏感动态内容、不改变既有 Prompt 顺序，只给出可验证的建议方案。

## Token 预估

### 1. AI 自动收集输入

AI先列出本次请求的实际区块：系统/安全、AI 职责、角色与世界、世界书命中、正式状态、历史/Memory、COT、当前玩家输入、输出协议和供应商包装。宏必须先求值，再计算最终长度。

### 2. 区分精确值与估算值

- 能获得目标 tokenizer 或供应商 usage 时，使用精确值并记录模型/版本。
- 只能估算时，标记为估算，保留安全余量，不能把字符数伪装成 token。
- 分别记录输入、输出预留、缓存读取、缓存写入和未缓存输入；不同供应商字段不能混成一个数字。

### 3. 输出简单报告

AI向小白只报告必要结果：预计输入、预计输出、总上限占用、最大的三类区块、是否存在超限风险和推荐动作。详细区块表留在 `Token Trace`，不要求用户逐项理解。

## 缓存命中的独立优化

### 1. 先识别缓存机制

AI必须从目标模型/Profile 的真实证据确认：是否自动缓存、是否只缓存公共前缀、是否支持显式断点、最小缓存长度、保留时间、命中计费、跨请求/会话范围和 usage 返回方式。不能根据相似模型或供应商名称猜测。

### 2. 把 Prompt 分为稳定前缀和动态尾部

常见稳定区块：安全边界、AI 职责、玩家主权、基础预设、固定世界/角色核心、输出协议和长期不变的格式规则。

常见动态区块：当前用户输入、最近历史、实时状态、条件命中的 Lore、会话摘要、临时 COT 模块和宏展开结果。

AI应给每块记录 `blockId`、内容指纹、版本、Token 估算、稳定等级和失效来源。只有在不改变语义优先级和消息 role 的情况下，才把稳定块整理为可缓存前缀；不能为了命中率随意移动安全规则、当前命令或 Lore。

### 3. 为高级 Prompt 建立缓存段

当普通 COT 升级为高级 COT 时，AI把模块分成：

- 跨回合稳定：基础职责、玩家主权、固定输出协议、长期风格和模型适配。
- 条件稳定：某个内容模式、玩法阶段、角色组合或世界区域持续期间不变。
- 每回合动态：玩家输入、热事务、在场状态、命中 Lore 和候选变化。

供应商支持多个缓存断点时，可分别标记长期前缀和条件前缀；只支持单一公共前缀时，优先保护最长且真正稳定的前缀。

### 4. 建立失效条件

影响内容或权限的变化必须让相关缓存失效：Prompt 模块版本、世界/角色核心、内容模式、Profile、模型、宏结果、语言、认知作用域、安全策略、Output Contract 和内容包版本。

当前状态、最近历史和玩家输入通常只改变动态尾部，不应让整个稳定前缀失效；但如果它们参与固定块的宏展开，就必须重新计算对应块指纹。

### 5. 用真实数据判断是否优化成功

AI对比优化前后的：缓存读取 token、缓存写入 token、未缓存输入、命中/未命中原因、首 token 延迟、总费用和最终 Prompt 指纹。没有供应商 usage 证据时，只能标记“结构已优化，命中未验证”。

缓存命中很高但使用了旧世界书、旧状态或错误模式，属于严重失败。正确性、认知隔离和玩家体验永远高于命中率。

## AI 自动执行流程

```text
读取模型/Profile 的真实缓存能力
→ 展开宏并生成实际 Prompt 区块
→ 预估或精确计算每块 token
→ 标记稳定、条件稳定和动态块
→ 检查是否能在不改变语义下形成公共前缀/缓存断点
→ 生成缓存键、指纹和失效表
→ 用固定夹具发起命中/未命中验证
→ 比较 usage、延迟和费用
→ 向作者输出简短结论与风险
```

AI可以自主完成技术分析，但以下情况必须停下询问：需要把敏感内容交给供应商缓存、需要改变 Prompt 语义顺序、需要更换模型/供应商、可能增加费用，或必须牺牲世界书/历史内容才能满足上限。

## 唯一产物

`Token Estimate & Cache Hit Plan`：模型/供应商证据、区块 Token 预估、输出预留、稳定/条件/动态块、缓存前缀或断点、指纹、失效表、隐私边界、命中验证、费用/延迟对比和面向作者的简短说明。

## 轻量路径与升级

- 无缓存能力：只做 Token 预估、输出预留和超限提醒，明确记录“不支持缓存命中优化”。
- 自动前缀缓存：保持稳定模块和顺序，减少无意义变化，验证 cached input usage。
- 显式断点或高级 COT：建立长期/条件缓存段、版本指纹和命中回归。
- 多模型/多模式：每个 Profile 和内容模式独立统计，禁止跨权限、跨模式或跨作品复用缓存。

## 交接与验证

- Prompt Assembly/COT 提供区块与语义顺序；本册只能在不改变其含义的条件下优化缓存结构。
- Macro Compatibility 提供展开结果；Settings 只暴露必要的缓存开关和简短统计；Gateway 采集真实 usage、费用和延迟。
- 验证精确/估算 token、输出预留、首次写缓存、连续命中、单块变化、版本失效、模式隔离、宏变化、模型切换和供应商不支持。

## 不负责

不要求小白设计缓存算法，不创作或删改 Prompt/COT/世界书正文，不为了命中率改变消息语义，不把缓存当作存档或记忆，也不在没有 usage 证据时声称已经命中。
