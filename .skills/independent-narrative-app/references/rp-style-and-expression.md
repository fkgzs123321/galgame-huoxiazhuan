# 文风、视角与表达方向

## 作用

记录作品默认或可选的文风、视角和角色表现方向。这里是轻量方向卡，不是最终 Prompt、COT 或模型参数。

## 读取条件

需要确定默认表达、叙事视角、多视角切换、对话/动作密度或不同模式的表达差异时读取。

## 前置输入

- `Discovery Draft Package`、`Character Portfolio`、`Content Mode Contract`。
- 作者喜欢/不喜欢的作品表达和现有样文。

## 方法

### 1. 把选择视为默认方向

文风和视角通常是可选项，不是永不改变的项目铁律。记录默认方案、允许切换的情境和禁止混用的情况。

### 2. 选择视角

- 第一人称：适合强主观体验，需明确叙述者知识边界。
- 第二人称：适合直接代入，但要避免替玩家决定意图和台词。
- 第三人称限知：适合角色主体与认知隔离。
- 第三人称全知或多视角：需定义切换标记、段落边界和秘密处理。

### 3. 记录表达轴

按项目需要选择少量轴：简洁/细腻、日常/戏剧、对白/动作/环境比例、幽默/严肃、感官密度、节奏、镜头距离。用正向要求配合避免项，少用互相冲突的形容词堆叠。

### 4. 角色表现方向

只记录作品层面的表现：是否强调动作、微表情、内心、潜台词、群像切换。角色个人语言和行为事实继续由 Character Portfolio 定义。

### 5. 模式差异

如果不同内容模式、剧情阶段或界面入口需要不同表达，只记录切换意图和不变量；具体模块由 Prompt Policy/Profile 组装。

## 唯一产物

`Expression Direction Card`：默认文风、视角、表达轴、对白/动作方向、切换条件、避免项和模式差异意图。

## 轻量路径与升级

- 基础项目：默认视角 + 3–5 条表达方向 + 3 条避免项。
- 多视角、多模式、多个模型或强类型文风时升级变体表和行为案例。

## 交接与验证

- 交给 Prompt Policy 与 Behavior Spec。
- 验证视角不漂移、角色语言不被全局风格抹平、不同模式不串扰。

## 不负责

不写具体 Prompt/COT 模板，不定义角色个人语料，不选择采样参数或消息插入位置。
