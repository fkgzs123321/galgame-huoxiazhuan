# 阶段、交付与变更控制

## 作用

把已确认设计拆成可运行、可路由、可验证的垂直切片，并管理实施、回退、验收和交付。只提供 gate criteria/evidence/建议；`SKILL.md` 更新 Gate State。

## 读取条件

- 完整设计确认后进入路线图、阶段计划、实施或交付。
- 已有项目需要按风险渐进迁移。
- 新证据要求回修上游产物。

## 前置输入

- `Design Gate Package`。
- 真实代码库、目标环境、依赖、权限和质量证据。
- 当前 Artifact Index / Gate State。

## 方法

### 1. 按垂直能力拆阶段

阶段必须从用户动作走到可观察结果，不能按“先写完全部 RP，再写全部运行时”横向铺开。一个切片至少说明：

- 用户入口与成功体验。
- 需要读取的最少 references。
- 内容、Command、状态、模型、UI、Save 和验证中真正受影响的部分。
- 失败语义、回退方法和本阶段非目标。

首个基础切片优先覆盖：单作品、单角色、单模型、一个受约束事实变化、一次耐久提交、保存重开和最小行为/Trace 证据。

### 2. 只为当前阶段写实施计划

计划写清文件、接口、步骤、测试和完成条件。后续阶段只保留路线图粒度，避免在证据不足时过度设计。

### 3. 实施门

- 当前切片未通过结构、路由、行为、集成和恢复检查，不开启下一切片。
- Card-to-App、Worldbook、Macro/Preset、玩法联动分别形成独立切片。
- 未启用的条件能力不反向阻塞基础闭环。

### 4. 受控回退

新证据推翻假设时：暂停受影响实施 → 定位 owner 产物 → 记录差异和影响 → 请求确认 → 更新设计和路线图 → 重新验证。不得只改代码而让文档继续描述旧行为。

### 5. 收口

每阶段输出证据摘要、未解决风险和下一门建议；全局交付再检查跨阶段兼容、旧档、回滚、已知限制和用户可用入口。

## 唯一产物

`Stage Control Record`：阶段路线图、当前阶段实施计划、验证证据引用、变更记录、门建议、回退入口和交付摘要。

使用 `../assets/templates/stage-roadmap.md` 与 `../assets/templates/acceptance-report.md`。

## 轻量路径与升级

- 单阶段小项目仍保留设计确认、实施和验收三段，不制造额外仪式。
- 多仓库、数据迁移、兼容旧档、外部发布或不可逆变化时增加 dry-run、备份和回滚演练。

## 交接与验证

- 按当前切片读取实际涉及的 RP、Runtime、Bridge 和 Quality 分册。
- 验证每个阶段独立可运行，跨阶段事实和版本不分叉，失败后能回到已知状态。

## 不负责

不替领域分册定义业务规则，不替质量分册伪造证据，不一次性规划所有未来文件。
