# 场景、开局、剧情与结局

## 作用

从作品来源、玩家身份和目标体验推导合理开局，并设计剧情控制权、事件、阶段、失败和收束。结构术语只在边界明确后用于实现参考。

## 读取条件

设计开局、场景、主线、事件、阶段、伏笔、失败、结局或长期循环时读取。

## 前置输入

- `Discovery Draft Package`、`World Contract`、`Agency Contract`、`Character Portfolio`。
- `Content Mode Contract`（存在尺度或模式差异时）。
- 同人来源时间点或原创世界当前局势。

## 方法

### 1. 推导开局依据

同人作品先确认：原著开局、某角色原著节点、改写节点、平行时间线还是原创事件。原创作品先确认：玩家为什么在场、此刻发生什么、关键角色为何相遇、第一轮能做什么。

开局至少提供：地点与时间、在场主体、当前局势、可观察矛盾、玩家行动空间和最小推进钩子。不要只写背景说明，也不要强迫玩家接受未确认的重大过去或关系。

### 2. 先分四种控制力量

| 力量 | 负责 |
|---|---|
| 作者预设 | 已成立事实、希望提供的机会、必然世界事件、允许变化的范围 |
| 玩家影响 | 能拒绝什么、能改变过程什么、最终能改变哪些世界/关系结果 |
| 程序裁定 | 确定性规则、状态条件、资源、冷却、幂等和不可逆门槛 |
| AI 即兴 | 在边界内演绎场景、对话、细节、局部反应和未预写路径 |

面向用户用白话询问，不直接展示内部分类表。先确认控制权和变化空间，再推荐线性、分支、事件池、沙盒、循环或混合结构。

### 3. 写事件职责契约

每个关键事件记录：

- 叙事目的与参与角色。
- 前置条件、触发来源和可拒绝/替代路径。
- 已知信息、秘密、伏笔和揭示条件。
- 允许 AI 即兴的部分与必须由规则裁定的部分。
- 候选状态变化、重复触发保护、失败和恢复。
- 对主剧情、角色关系、玩法系统、Memory 和 Save 的影响。

### 4. 阶段与偏离

阶段描述局势和可用机会，不把玩家锁死在脚本。玩家偏离时选择：接受新路线、延迟机会、用世界事件推进、或明确说明限制；不得伪造选择后无条件拉回。

### 5. 失败、不可逆与结局

区分可恢复失败、代价性失败、路线关闭、角色退场和全局结束。不可逆结果需要清晰前兆、规则依据和存档/确认策略。

结局可以是封闭收束、关系/路线结局、阶段结局后继续游玩、循环重启或开放状态。长期/无限结构仍需要局部目标、变化、记忆和周期收束，不能只有无尽随机事件。

## 唯一产物

`Narrative Contract`：开局契约、四种控制力量、结构组合、事件职责、阶段/秘密、偏离、失败、不可逆、结局和继续游玩策略。

## 轻量路径与升级

- 短篇：开局 + 核心矛盾 + 3–5 个事件责任 + 失败/结局。
- 分支、长期生成、跨系统结算、伏笔和读档重投时升级完整事件/阶段契约。

## 交接与验证

- 交给 Prompt Policy、Turn/State、玩法联动、Save 和行为规格。
- 验证拒绝、偏离、失败、重复触发、读档和结局后继续游玩都符合契约。

## 不负责

不实现事务、数据库或事件总线，不替角色档案定义人格，不承担文风细节。
