# 世界观与知识边界

## 作用

建立作品中“什么是真的、谁知道什么、哪些会变化”的世界契约，为角色、剧情、世界书、玩法和 Memory 提供唯一事实边界。

## 读取条件

创建、迁移、扩展或审查世界设定时读取。局部任务已有明确 World Contract 时只读受影响部分。

## 前置输入

- `Discovery Draft Package` 或来源作品资料。
- 同人/原创边界、玩家体验和内容模式。
- 已知角色、开局与系统想法。

## 方法

### 1. 确认来源与改编边界

- 同人：采用哪个版本、时间点、主线状态和改编幅度；区分原作事实、可靠推断、项目私设和待确认。
- 原创：先定义作品能稳定运行的最低公理，不要求一次写完百科全书。
- 混合：明确哪些部分可复用来源，哪些必须重新解释。

### 2. 选择世界尺度

只覆盖实际游玩需要：单一场所、城市、区域、国家、多世界或可生成空间。尺度越大，越需要 MOC、作用域、版本和按需检索；不要把“大世界”当作必须写满所有地点。

### 3. 定义世界如何运转

至少检查：

- 物理/超自然规则、资源与代价。
- 社会、法律、经济、技术、文化和日常生活。
- 历史与当前局势，哪些只是背景，哪些会直接进入剧情。
- 组织、地点、物品和机制之间的因果关系。

### 4. 分离四类事实

| 类型 | 含义 | 典型消费者 |
|---|---|---|
| 稳定设定 | 不随普通游玩改变的世界公理与来源事实 | 角色、世界书、Prompt |
| 当前状态 | 会被正式 Command/事件改变的局势 | Kernel、UI、Save |
| 公共知识 | 世界内普通角色可合理知道 | 角色认知、Lore |
| 秘密/受限知识 | 仅特定角色、地点、阶段或调查后可知 | Lore 作用域、Memory、测试 |

模型生成的合理句子不是自动事实。新地点、NPC、组织或规则是否可生成，要明确“允许生成的槽位、不可触碰的核心和生成后怎样提交”。

### 5. 建立认知矩阵

按主体记录：事实来源、谁知道、谁误解、何时可揭示、泄露后如何检测。不要把作者知道、玩家知道、角色知道和模型上下文里存在混为一谈。

### 6. 做遗漏提醒

世界可以保持留白，但在总结时提醒作者检查：日常生活是否可想象、角色行动是否有现实约束、剧情机制是否有代价、秘密是否存在合理发现路径。提醒不等于强制补全。

## 唯一产物

`World Contract`：来源等级、世界公理、尺度、日常运转、稳定/动态事实、公共/秘密知识、认知矩阵、生成边界和待确认项。

## 轻量路径与升级

- 小型作品：一页世界卡 + 公共/秘密边界 + 当前局势。
- 多阵营、时间层、动态世界、同人来源冲突或大规模生成时升级完整目录和版本控制。

## 交接与验证

- 交给角色、剧情、世界书、玩法、Memory 和 Prompt Policy。
- 验证同一事实不会在多个系统拥有相互冲突的真值；秘密不会因 Prompt/Lore/Memory 注入而提前泄露。

## 不负责

不定义世界书字段、检索算法、Prompt 插入位置、数据库 Schema 或状态提交。
