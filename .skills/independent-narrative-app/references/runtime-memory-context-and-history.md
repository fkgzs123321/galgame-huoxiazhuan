# Memory、上下文与历史

## 作用

管理消息历史、事件记忆、摘要、检索、遗忘和角色知识作用域，并保证它们只消费已提交事实，不成为第二状态源。

## 读取条件

需要多回合连续性、长期记忆、摘要、检索、历史操作或认知隔离时读取。

## 前置输入

- `CommittedTurn/CommittedFacts` 和 revision。
- `World Contract`/`Character Portfolio` 的认知边界。
- 上下文预算、会话长度、Save 和隐私要求。

## 方法

### 1. 分离四类信息

- **消息历史**：已提交的玩家输入与正式正文。
- **事件记忆**：发生过且后续有检索价值的事实和因果。
- **当前状态**：由 Kernel/State owner 维护，Memory 只引用，不复制真值。
- **派生摘要/索引**：可丢弃并按 revision 重建。

### 2. 建立作用域

每条记忆记录来源 revision、主体、可见角色、世界/场景/会话范围、置信/事实类型和生命周期。作者/玩家/角色/模型可见性分别处理。

### 3. 摘要策略

- 摘要事实而非重写世界规则。
- 保留决定、关系变化、未解决目标、承诺、物品/任务变化和重要信息来源。
- 不把模型草稿、被拒候选和调试信息写入叙事摘要。
- 摘要合并保留来源 revision；无法追溯时标记不确定，不伪装精确。

### 4. 检索与预算

先按作用域和权限过滤，再按时间、相关性、事件链或向量检索。返回结果携带来源、排序理由和预算；Prompt Assembly 再决定裁剪，Memory 不直接发送模型请求。

### 5. 遗忘和更正

区分自然淡化、索引过期、角色遗忘、事实更正和数据删除。正式事实更正通过新 Command/commit；Memory 只更新派生视图。隐私删除需要同步清理摘要、索引、缓存和备份策略。

### 6. 失败与重建

Memory 生成/索引失败不回滚已提交回合。记录消费到的 revision 水位，重试必须幂等；发现缺口时从已提交事件重建。

## 唯一产物

`Memory-History Contract`：历史模型、事件记忆、摘要、检索、作用域、遗忘、更正、消费水位和重建策略。

## 轻量路径与升级

- 短会话：最近消息窗口 + 显式阶段摘要。
- 长期群像、多作用域、RAG、跨存档人物记忆或隐私删除时升级完整索引和重建。

## 交接与验证

- 交给 Prompt Assembly、Lore、UI、Save 和 Behavior Spec。
- 验证认知泄露、摘要事实漂移、候选污染、重复消费、删除和重建。

## 不负责

不创造世界事实，不提交状态，不编写世界书正文，不决定物理数据库格式。
