# 最小宿主与内容包

## 作用

定义独立 RP 应用必须自行承担的宿主能力、内容身份和最小闭环。复用 ST 契约不等于依赖 ST 页面或插件运行时。

## 读取条件

从零应用、完整改造或 Card-to-App 进入结构阶段时读取。局部内容任务不自动加载。

## 前置输入

- `Design Gate Package`、所选 RP 契约和桥梁证据。
- 目标平台、运行方式、模型来源和分发边界。

## 方法

### 1. 覆盖十三类职责

职责必须覆盖，实现强度可轻量：

1. 内容版本与作品身份。
2. 角色、Persona、场景、世界书、预设和资源归属。
3. 玩家输入、UI Command 与只读 Projection。
4. 消息、会话和回合生命周期。
5. 正式状态、规则、revision 和事务。
6. 模型接入、流式、取消和错误。
7. Prompt/Preset、消息链和预算。
8. Lore/World Info 选择与注入。
9. History、Memory、摘要和认知隔离。
10. Output Contract、候选变化和解码。
11. 保存、读取、迁移和恢复。
12. 平台、文件、资源、安全与隐私。
13. 行为测试、Trace、诊断和发布证据。

不要把这十三项都实现在一个 Host 类中；它们是能力地图，具体 owner 在对应 runtime reference。

### 2. 定义内容包

内容包至少记录：

- `packageId`、版本、作品 ID、作者/来源和许可边界。
- 角色、玩家 Persona、场景、世界书、Prompt Profile、资源和迁移脚本的稳定 ID。
- 依赖、能力需求、可选模块和兼容范围。
- Schema/内容版本、升级路径和加载失败语义。

原始 ST 字段或未知扩展保存在 sidecar/来源区，目标语义使用独立契约；不要为“整洁”静默删除。

### 3. 建立最小可运行闭环

基础闭环至少能够：选择/加载内容包 → 建立会话 → 接收玩家 Command → 装配 Prompt → 调用模型 → 形成候选 → Kernel/Save 提交 → Projection 展示 → 保存重开 → Trace 定位。

### 4. 选择强度

- 纯文字短篇可以使用内存状态、单存档和短历史，但仍需区分草稿/候选/提交。
- 长期游玩、群像、正式玩法状态、RAG、多模态、多模型、跨设备、Mod/更新和旧卡迁移触发更完整实现。

## 唯一产物

`Host Foundation Contract`：能力地图、内容包契约、稳定 ID/版本、依赖组合、最小闭环、缺失能力和条件升级表。

使用 `../assets/templates/host-capability-map.md`。

## 轻量路径与升级

- 单内容包、单角色、单模型、单存档先跑闭环。
- 多包组合、更新/Mod、跨平台或外部生态兼容时增加版本解析、权限和迁移。

## 交接与验证

- 交给所有 Runtime、Platform、Security 和 Stage Control。
- 验证 ID/归属稳定、缺少能力时显式失败、保存重开后内容版本和正式状态一致。

## 不负责

不选择具体框架，不实现其他分册内部逻辑，不把十三项职责集中成巨型模块。
