# RP 独立应用设计示范

> 本文只展示 Skill 怎样路由、交接和收敛，不定义新规则。题材、人物、系统、字段和技术选择都可替换，不是必选模板，也不应原样复制成用户作品。

## 作用

用一个中性小型项目展示“想法 → 草案 → 契约 → 最小运行时 → 行为证据 → 阶段交付”的完整路径，帮助初次创作者理解各分册为什么分开。

## 读取条件

用户需要完整教程示范、看不懂产物之间的关系，或维护者需要前向检查 Skill 路由时读取。局部明确任务不必读取。

## 前置输入

- 已选用的权威契约或需要验证的路由。
- 本文提供的中性样例；不得把样例内容写回用户项目，除非用户主动选择相同设定。

## 示例起点

用户说：

> 我想做一个独立 RP 应用。玩家在一座常年起雾的海边小镇经营失物招领处，通过归还物品认识居民；希望可以长期玩，但先做一个能保存重开的基础版本。

这是原始想法，不是完整需求。总控先建立 Task Envelope，再读入口发现分册。

## 1. Discovery Draft Package

- **来源**：原创；没有需要继承的现有角色卡。
- **作品轮廓**：小镇群像、日常悬疑、长期生成式委托；首版不做战斗和开放地图。
- **玩家体验**：通过物品线索、对话和选择逐步建立关系，并发现小镇过去。
- **初步系统草稿**：对话、委托簿、人物关系、世界书、保存读取。
- **暂定项**：是否允许无限生成新居民；首版先使用 3 名固定居民。

这里允许“不完整”。草案只负责找到要设计的对象，不替世界/角色/运行时契约写答案。

## 2. 内容契约

### World Contract

- 小镇地理和公共历史稳定；每件失物有可追踪来源。
- 角色只知道自己经历、公开消息和被告知的内容。
- “旧灯塔事故真相”是分层秘密，不因关键词命中就对所有角色公开。

### Agency Contract

- 玩家扮演自定义的招领处经营者。
- AI 可描写玩家可见环境和 NPC，不代写玩家台词、内心或重大决定。
- 玩家明确授权“帮我概括操作”时，AI 可转述低风险日常动作。

### Character Portfolio

首版为每名 NPC 建立主要/次要级别、目标、矛盾、外貌识别点、语料样本、知情边界和关系状态。示例不在这里展开完整人设，避免把人物内容误当方法规范。

### Content Mode Contract

首版选择单一 SFW 模式，并明确不做露骨内容。若未来增加其他模式，需要重新设计 Prompt/Lore/资源/模型/存档隔离，而不是只加开关。

### Narrative 与 Expression

- 开局：雨天，一只没有姓名牌的旧行李箱被送到招领处；场景给出可行动信息，不强迫玩家接受唯一线索。
- 长期循环：接收物品 → 调查/交流 → 归还或保留 → 关系与世界状态留下已提交影响 → 新委托。
- 默认第三人称环境叙述、NPC 直接对话；这是方向，不替代后续 Prompt 组装。

## 3. 世界书与 Prompt

`Lore Authoring Package` 将小镇规则、地点、公开历史、角色秘密和委托机制拆成常驻/关键词/条件条目，并标注消费者和认知作用域。

`Prompt Policy Package` 定义 AI 为叙事执行者：扮演 NPC、描写环境、按正式状态推进委托、提出候选变化；不得代演玩家、泄漏秘密或直接写存档。基础核心单独可运行，高级文风模块暂不启用。

## 4. Gameplay-Narrative Contract

“委托簿”不是独立摆设：

- 剧情中 NPC 交付物品后，Kernel 才能提交新委托。
- 玩家在委托簿标记线索会成为正式状态，后续 Prompt 可读取。
- 归还结果改变关系/世界事件，并反馈到正文和新委托条件。
- 只在 UI 中显示、但正文不知道的委托状态视为联动失败。

系统卡还记录 Command、状态、Memory、失败、保存和跨系统接口。若删除委托簿，基础对话回合仍应可运行。

## 5. 最小运行时契约

- Host：单内容包、本地 in-process、一个远程模型、单存档。
- Turn-State：`AdvanceTurn` 携带 commandId/expectedRevision；候选仅包含正文和受约束的委托/关系变化。
- Assembly：固定基础模块、当前场景、最近历史、命中 Lore、当前用户输入和文本+结构化候选契约。
- Gateway：流式正文只做 overlay；完整响应才能 Decode。
- Save：CommitRecord 原子写入；durable ACK 后发布 next revision；重开后恢复正文、委托和关系。
- UI：主对话、委托投影、保存/读取；UI 不直接改数据库。

## 6. Behavior Evidence Package

首批案例包括：

1. 玩家拒绝检查行李箱，AI 不替玩家打开，委托状态不推进。
2. 玩家向不知道灯塔秘密的 NPC 询问，NPC 不泄漏真相。
3. 正确归还物品后，正文、委托簿、关系和重开存档一致。
4. 模型返回非法关系值时，解析/规则拒绝，revision 不变。
5. 保存 ACK 丢失时按 commandId 对账，不重调模型或重复奖励。

人物自然度使用人工量表；revision、秘密词、状态和重复提交使用硬断言。

## 7. 垂直阶段路线图

- **阶段 1**：基础文本回合 + 一项委托状态 + 保存重开 + 正常/失败 Trace。
- **阶段 2**：三名 NPC、关系与认知边界。
- **阶段 3**：世界书关键词/秘密作用域和 Lore Trace。
- **阶段 4**：长期委托生成与多系统联动。
- **条件阶段**：跨平台、离线、多内容模式；只有证据出现时开启。

每阶段完成后独立验收。后续阶段未详细设计成文件级计划，直到前一阶段产生真实证据。

## Walkthrough Trace

| 步骤 | 权威 owner | 输入 | 产物/状态 |
|---|---|---|---|
| 想法整理 | Entry Workflow | 原始表达 | `Discovery Draft Package` |
| 世界/玩家/角色 | RP owners | Draft + 来源 | 三个内容契约 |
| 叙事/模式/表达 | RP owners | 上游契约 | Narrative/Mode/Expression |
| 世界书/Prompt/玩法 | RP owners | 内容契约 | Lore/Prompt/Gameplay Packages |
| 可行性 | Feasibility Workflow | 所有权威产物 + 环境证据 | `Design Gate Package` |
| 最小回合 | Runtime owners | 已确认设计 | Host/Turn/Assembly/Profile/Gateway/UI/Save Contracts |
| 证明 | Quality owners | 验证意图 + 实现 | Behavior/Integration Evidence |
| 阶段推进 | SKILL + Stage Workflow | evidence | Gate State + `Stage Control Record` |

## 唯一产物

`Walkthrough Trace`（非规范）：记录示范每一步读取的 owner、输入和产物，仅用于教学与路由前向检查。

## 不负责

本示范不提供可直接发布的完整 Prompt、人设、数据库 Schema 或代码；出现冲突时以对应权威分册为准，不以示例措辞覆盖规则。
