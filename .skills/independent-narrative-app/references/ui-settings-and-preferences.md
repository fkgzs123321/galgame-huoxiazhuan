## 作用

这本分册帮助作者和实现者把“可调整的东西”整理成明确的设置契约。它回答：有哪些设置、谁能修改、作用于哪个范围、保存在哪里、什么时候生效、怎样迁移和怎样在冲突时给出反馈。

设置不是把所有开关堆在一个页面里。一个选项只有在 owner、默认值、作用域、生效方式和失败语义都清楚时，才是可维护的设置。

## 读取条件

- 规划基础设置或高级设置界面。
- 需要决定 API/模型、Prompt/预设、世界书、内容模式、外观、存档、调试和隐私选项的归属。
- 用户要求导入、导出、重置、迁移或跨设备同步设置。
- 排查“设置改了但没有生效”“重开后丢失”“作品 A 的设置影响作品 B”等问题。
- 需要区分玩家设置、作者设置、作品默认值和运行时临时值。

不需要新增或修改设置时，不自动读取本册。

## 前置输入

- `Project Profile`、`Host Foundation Contract` 和目标平台能力。
- `Content Mode Contract`、`Executable Profile Contract`、`Save-Migration Contract`。
- 需要被设置影响的 owner：模型、Prompt、Lore、UI、存档、隐私或诊断。
- 作者对哪些选项开放给玩家、哪些只开放给创作者的决定。

## 底层设置不得省略

独立 RP 前端从无到有搭建时，以下设置域属于底层能力。界面可以精简、合并或分阶段开放，但设计方案中不能完全缺席；暂不实现的项目要记录原因、风险和后续入口。

| 设置域 | 最低应覆盖的内容 |
|---|---|
| 总设置 | 应用语言、主题/显示模式、内容包或作品版本、默认启动行为、恢复默认值、设置导入导出 |
| 模型/API 接口 | 供应商或本地模型、端点、模型 ID、凭证引用、连接测试、流式、超时、重试、代理/自定义 Header、能力检查与错误反馈 |
| 提示词与预设 | 基础提示词组、高级提示词组、启用 Profile、模块开关、组装顺序、导入导出、重置、版本和 Prompt Trace 入口 |
| 世界书与知识注入 | 启用的 Lore/World Info、兼容档位、预算、触发/命中诊断、模式与认知隔离、来源版本 |
| 存档与读取 | 新建、手动保存、自动保存、存档槽、读取、覆盖确认、备份、导入导出、删除、旧档迁移、损坏与崩溃恢复入口 |
| 正文与界面 | 字体/字号、阅读宽度、自动滚动、流式显示、动效、声音、消息显示、辅助功能和设备偏好 |
| 内容与隐私 | SFW/NSFW 或其他模式、内容隔离、密钥和日志脱敏、远程资源、数据清除、遥测与网络权限 |
| 诊断与维护 | 当前版本、模型/Profile、Token/缓存摘要、Prompt/Lore/State Trace、错误报告、缓存清理和安全重置 |

“拥有设置域”不等于首版必须提供复杂页面。例如单模型作品仍需有明确的接口配置来源、连接失败反馈和替换入口；单存档作品仍需有保存、读取、备份和损坏恢复的设计结论。

除这些底层域外，战斗、地图、手机、经营、关系、相册、任务或其他玩法设置由作品内容决定。Skill 应先读取玩法系统设计，再建议是否新增设置，不能把示例系统当作所有项目的默认配置。

## 方法

### 1. 按“底层设置 + 作品设置”建立目录

先完整覆盖底层设置域，再根据作品的玩法和内容增加扩展设置。按用途而不是按实现文件分类：

- 底层设置决定应用是否能够配置、生成、保存、读取、诊断和恢复。
- 作品设置决定具体玩法允许玩家或作者调整什么。
- 创作者设置负责编辑、预览、调试、内容版本和发布；不应混进普通玩家的基础设置。
- 一次会话或一次请求的临时选项单独标记，不伪装成长期设置。

目录的作用是防止底层遗漏，并让作品扩展设置有明确 owner。不能因为首版界面还没画完，就省略保存、读取、接口或 Prompt 配置的契约。

### 2. 为每项设置写完整字段

至少记录：

- 稳定 `settingId` 和人类可读名称。
- 所属 owner 与数据类型。
- 默认值、允许范围、枚举和无效值处理。
- 可见对象：玩家、作者、调试者或仅内部。
- 作用域：全局、作品、内容包、存档、会话、设备或一次请求。
- 继承来源、覆盖优先级和清除覆盖的方法。
- 保存位置、敏感等级和版本。
- 生效时机：立即、下一回合、重建会话、重启或迁移后。
- 影响的 runtime contract、缓存键和验证案例。

没有这些信息的“开关”只能算草案，不应直接接入运行时。

### 3. 分清默认值、继承和覆盖

建议把来源写成一条可解释链：

```text
平台默认 → 应用默认 → 作品默认 → 存档覆盖 → 会话临时覆盖 → 当前命令覆盖
```

实际层级可以不同，但必须明确谁覆盖谁、删除覆盖后回到哪一层、导入旧设置如何映射。不要让 UI 组件各自使用一套优先级。

### 4. 选择正确的作用域

- 全局：适合语言、主题、设备偏好和密钥引用；不应混入单个作品状态。
- 作品/内容包：适合默认 Prompt、Lore、角色和内容模式；更换作品不应污染其他作品。
- 存档：适合与故事进度绑定的选项；删除存档时说明是否一起删除。
- 会话：适合临时模式、调试、一次性 Profile 或本回合选项；关闭会话后可丢弃。
- 请求：适合一次模型任务的超时、候选模式或重试参数；不自动写回长期设置。

作用域错误通常比缺少一个设置更危险，因为它会造成跨作品串扰或无法复现。

### 5. 设计基础层与高级层

基础层放影响基本运行、且小白需要理解的选项，例如接口连接、语言、内容模式、提示词/预设选择、保存读取、自动保存和文字大小。高级层放 Profile 细节、宏兼容、Token/缓存、Trace、迁移、实验功能和恢复策略。

分层不是隐藏风险。高级设置仍要说明影响、默认值、适用范围和恢复方法；对玩家主权、安全、内容隔离和正式状态的约束不能通过高级开关绕过。

### 6. 定义保存与生效行为

每个设置都要有保存状态：未修改、草稿、已保存、保存失败、迁移中或来源冲突。修改后立即生效的设置需要说明正在生成的回合是否受影响；下一回合生效的设置要显示何时生效；需要重启的设置不能假装即时生效。

保存失败时保留用户能理解的失败信息和回滚动作。内存中的 UI 值不是正式设置，除非保存确认成功并写入对应 store。

存档操作本身也要形成可用入口：新建、保存、读取、另存、覆盖、删除、备份、导出和恢复分别说明确认条件与失败结果。设置书负责确保这些入口和偏好存在；实际 CAS、迁移和崩溃恢复继续由 `runtime-save-migrations-and-recovery.md` 定义。

### 7. 处理导入、导出和迁移

导出应带设置版本、来源、作用域和敏感字段处理说明。密钥默认不随普通设置导出，或明确要求用户重新绑定。

迁移按字段处理：保留、重命名、转换、废弃、需要确认或无法迁移。未知字段不能静默吞掉，应保留 sidecar 或迁移报告。导入前预览冲突，导入后报告改变了什么以及怎样撤销。

### 8. 处理能力冲突

设置可能要求目标运行时不支持的能力，例如结构化输出、供应商缓存、离线模型或某种宏。能力检查应发生在生效前，给出三种明确结果：可直接启用、降级到兼容方案、拒绝并说明缺口。

不能因为 UI 显示了一个开关就假设功能存在，也不能静默把用户选项改回默认值。

### 9. 保护密钥和隐私

把“凭证值”“凭证引用”“是否启用供应商”分开。日志、导出、Trace、错误报告和屏幕共享默认不暴露密钥或完整敏感 Prompt。不同内容模式的设置、缓存和存档必须有真实隔离。

### 10. 面向小白的提问顺序

先向用户说明底层设置会由 Skill 自动补齐，不要求小白逐项发明。作者只需确认模型/API 的使用方式、Prompt/预设是否允许调整、存档策略、内容模式和作品特有玩法；其余由 Skill 形成建议草案，再逐项确认 owner、作用域和生效时机。

## 唯一产物

`Settings Contract`：底层设置覆盖表、作品扩展设置目录、字段 Schema、默认值、作用域/继承、可见对象、保存位置、敏感等级、生效时机、存档/读取入口、迁移表、能力冲突和错误反馈。

## 轻量路径与升级

- 小型项目：可以合并页面和减少选项，但仍需对总设置、接口、提示词/预设、世界书、保存/读取、正文显示、隐私和诊断给出最低实现或明确延期结论。
- 多作品或长期存档：增加作用域继承、导入导出、迁移和冲突预览。
- 多模型、创作者工具、跨设备或高隐私风险：增加能力矩阵、密钥引用、审计 Trace、备份与恢复演练。

## 交接与验证

- 设置值交给对应的 Model/Profile、Prompt、Lore、UI、Save 或 Security owner。
- 外观相关的视觉表现参考 `ui-visual-style-and-color-guidance.md`；本册只负责配置的存在、归属、保存和运行时影响。
- 验证底层设置域没有缺项，并覆盖默认值、接口连接、Prompt/预设切换、世界书启用、保存/读取、覆盖顺序、生效时机、重开、导入导出、迁移、冲突、无效值、权限和敏感数据隔离。

## 不负责

不决定页面导航或视觉品牌，不创作 Prompt/世界书正文，不替 Kernel 提交正式状态，不实现数据库、模型 API、缓存或具体 UI 组件。
