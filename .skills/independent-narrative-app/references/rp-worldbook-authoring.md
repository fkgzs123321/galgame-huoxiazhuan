# 世界书内容编写

## 作用

把世界、角色、地点、事件、机制和演绎知识拆成可由独立 Lore Runtime 消费的条目。采用 ST World Info 的成熟核心语义有利于导入复用，但内容设计不依赖 ST 运行。

## 读取条件

创建、迁移、清理或审查 World Info/Lore 内容时读取。

## 前置输入

- `World Contract`、`Character Portfolio`、`Narrative Contract`。
- `Gameplay-Narrative Contract`（存在玩法系统时）。
- 外部世界书、来源文本和目标兼容档位。

## 方法

### 1. 先分内容职责

常见条目包括：世界公理、当前背景、角色补充、关系/认知、地点、组织、物品、事件、机制、演绎规则、内容模式和可选扩展。分类用于找 owner，不要求每个项目都有全部类别。

### 2. 一条只解决一个检索问题

正文应能回答“模型为什么现在需要看它”。控制长度，写清消费者、作用域和与其他条目的关系。不要把整个设定集常驻，也不要把运行时代码、完整 Prompt 和无关 Markdown 装饰塞进条目。

### 3. 选择触发意图

| 意图 | 用途 |
|---|---|
| 常驻（社区常称蓝灯） | 每轮都不可缺少的短规则、当前核心局势 |
| 关键词（社区常称绿灯） | 角色、地点、组织、物品、事件等被提及时加载 |
| 条件触发 | 状态、阶段、模式或其他明确条件成立时加载 |
| 默认关闭 | DLC、作者工具、互斥内容或未选择路线 |

“灯色”只是 UI 俗称；实际导入/导出要保存稳定字段和行为语义。

### 4. 设计关键词

- 使用玩家和模型真实可能出现的称呼、别名、简称和必要变体。
- 避免过短、过泛、到处出现的词。
- 区分主关键词与辅助条件；为否定、同名和歧义提供边界。
- 无关键词的常驻条目明确空数组，不用虚假 key 占位。

### 5. 设计条目关系

记录是否允许递归、可触发谁、被谁触发、互斥/分组、概率、冷却、优先级和模式。创作层只声明意图；扫描轮次、预算和算法由 Runtime 定义。

### 6. 认知和模式隔离

秘密条目标明谁可消费、何时揭示和从哪个证据进入上下文。多内容模式的条目必须有实际过滤条件，不能只靠 UI 开关。

### 7. 清理外部内容

保留原始数据与来源，分类为直接兼容、转换、重写、隔离、降级、放弃或待作者裁定。未知字段、宏和脚本不静默删除；不可执行内容默认惰性。

## 唯一产物

`Lore Authoring Package`：内容目录、条目草案、触发意图、关键词、作用域、条目关系、认知/模式边界、来源和兼容需求。

## 轻量路径与升级

- 小型项目：少量常驻 + 关键词条目 + 确定顺序。
- 条件/递归、秘密、多书合并、大语料、向量检索或 ST 导入时升级完整规范。

## 交接与验证

- 交给 `runtime-worldbook-selection-and-injection.md` 和 Prompt Assembly。
- 验证应触发、不应触发、同名歧义、秘密泄露、递归、去重、预算和导入回放。

## 不负责

不实现扫描、递归求值、Token 预算、注入顺序、宏解释器或数据库。
