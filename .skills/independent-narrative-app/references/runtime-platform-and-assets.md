# 平台与资源 Port

## 作用

把应用所需的文件、网络、模型、窗口、通知和媒体能力抽象为可验证 Port，并管理图片、音频、视频等资源的导入、缓存、打包、离线和降级。产品是独立应用，不等于必须抛弃 Web 技术实现。

## 读取条件

选择 in-process、Web Worker、Tauri、原生移动端、Cloud，或使用外部媒体资源、离线模式和跨平台发行时读取。

## 前置输入

- `Host Foundation Contract`、目标设备/系统和发布方式。
- 资源清单、性能/离线/容量要求和当前环境证据。
- Gateway、Save、UI 与 Security 对平台能力的需求。

## 方法

### 1. 先列能力，不先选 Host

使用 `host-capability-map.md` 列出：存储、原子写入、文件选择、密钥保存、网络、模型运行、流式、后台任务、多窗口、通知、剪贴板、媒体解码、更新和诊断。每项标记必需/可选、当前支持、降级和证据。

### 2. 选择最小 Host

- **in-process**：依赖最少，适合验证契约和单体本地应用。
- **Worker/独立进程**：需要隔离长任务、避免 UI 阻塞或故障域分离时采用。
- **Tauri/桌面壳**：需要本地文件、系统密钥、安装包或桌面集成时采用。
- **Cloud**：需要跨设备、远程协作或服务端密钥时采用，并接受网络、隐私和运维成本。
- **移动端**：需重新验证文件、后台、内存、模型和媒体限制。

没有真实需求时保持 in-process 是有效选择。Host 可使用 Web UI 技术，但核心契约不能依赖 ST 页面、浏览器插件或只在某个网页存在的全局对象。

### 3. 定义 Platform Port

为文件/存储、密钥、网络、时钟、随机数、后台任务、通知和系统信息定义最小异步接口、错误语义和能力探测。业务层消费 Port，不直接散落平台 API。

### 4. 管理资源生命周期

资源使用稳定 ID、来源、许可/归属、内容哈希、MIME、尺寸/时长、版本和引用关系。流程覆盖导入验证 → 转码/缩略图 → 存储 → 缓存 → 引用 → 导出 → 清理。

禁止把临时 object URL、绝对本机路径或 UI 缓存键当成永久资源 ID。内容包资源与存档生成资源分开归属。

### 5. 离线与降级

明确哪些能力必须联网，断网后能否读档、继续本地剧情、查看资源或仅进入只读模式。资源缺失时提供占位、重试、重新定位或禁用相关功能；不能让单张图片阻断存档加载。

### 6. 性能与打包

大资源使用按需加载、尺寸预算、缓存淘汰和解码限制。发布包检查路径大小写、非 ASCII 文件名、许可、校验、重复资源和目标平台架构。开发路径不可泄漏进成品。

## 唯一产物

`Platform-Asset Port Contract`：Host 选择证据、能力表、Platform/Asset Port、资源身份与生命周期、缓存/离线/降级和打包要求。

## 轻量路径与升级

- 单平台纯文本：当前 Host + 本地存储/网络 Port + 静态资源清单，不预建第二平台抽象。
- 第二平台、多模态、离线模型、大资源、自动更新或 Cloud 时按真实缺口增加 Port。

## 交接与验证

- 能力表交给 UI、Gateway、Save 和 Security；发布结果交给 Release。
- 在目标平台测试缺文件、断网、缓存清理、路径迁移、打包安装、低内存和资源导出；区分模拟与真机证据。

## 不负责

不提前强制物理分离，不决定 RP 内容，不定义模型政策，也不把“使用 React/WebView”误判为产品必须依赖 Web 服务。
