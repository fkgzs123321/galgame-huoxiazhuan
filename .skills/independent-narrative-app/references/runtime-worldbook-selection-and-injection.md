# 世界书选择与注入运行时

## 作用

把 Lore Authoring 的触发意图实现为可预测、可预算、可追踪的 World Info 选择和注入。优先兼容 ST 核心语义，同时由独立运行时执行。

## 读取条件

应用使用 World Info/Lore、导入 ST 世界书或需要排查“世界书没生效/乱触发”时读取。

## 前置输入

- `Lore Authoring Package`、`Host Foundation Contract`。
- 当前 base revision 的消息/状态/Memory、Prompt 预算和兼容档位。

## 方法

### 1. 明确选择管线

```text
收集可用条目
→ 模式/权限/认知过滤
→ 常驻候选
→ 关键词/条件扫描
→ 分组/互斥/概率/冷却
→ 有界递归
→ 去重、排序、预算裁剪
→ 生成注入块与 Lore Trace
```

每次选择钉住 base revision 和输入消息范围，避免流式过程中重新命中导致不稳定。

### 2. 触发语义

- 常驻条目仍受模式、作用域和预算约束。
- 关键词支持主/辅助 key、大小写/语言正规化、扫描深度和歧义条件。
- 条件触发只读取允许的已提交状态，不执行不可信任意代码。
- 分组/互斥明确优先级、排序和未命中行为。
- 概率与冷却必须可复现或记录随机种子/决策证据。

### 3. 有界递归

定义最大轮数、可触发/被触发标志、已访问集合和新增内容扫描范围。循环、重复内容和指数膨胀必须停止并进入 Trace。

### 4. 去重与预算

按稳定条目 ID 和内容指纹去重。排序至少考虑安全/模式、强制规则、作用域、优先级、相关性和成本。裁剪应尽量保留完整条目，并记录丢弃原因；不得静默截断关键禁止规则。

### 5. 注入

Lore Runtime 产生带来源、位置意图、顺序和 token 估算的选择计划；Prompt Assembly 决定最终 role/Marker/位置。宏在专用兼容层求值，未知宏保留并报告。

### 6. Trace

记录每条候选：为什么可用、命中了什么、在哪轮递归、被哪个规则排除、预算前后顺序、最终是否注入。

## 唯一产物

`Lore Runtime Contract`：选择管线、扫描/条件、递归、分组、概率、冷却、去重、预算、注入计划和 Lore Trace Schema。

## 轻量路径与升级

- 小型项目：常驻 + 关键词 + 确定顺序 + 简单 Trace。
- 条件/递归、多书、向量、概率、冷却和预算压力时升级完整管线。

## 交接与验证

- 选择计划交给 Prompt Assembly，Trace 交给 Integration Diagnostics。
- 覆盖正/反命中、同名、秘密、递归循环、去重、互斥、预算和 ST fixture 回放。

## 不负责

不创作条目正文，不定义宏语法，不直接组装完整 Prompt，不修改正式状态。
