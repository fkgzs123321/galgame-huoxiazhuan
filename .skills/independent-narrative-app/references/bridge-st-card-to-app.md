# ST 角色卡迁移为独立应用

## 作用

把普通角色卡或 SillyTavern 资产的内容与行为语义迁移到独立应用，同时保留原始数据、来源和不支持项。迁移目标是复现作者确认的体验，不是让独立应用继续依赖 ST 页面或插件运行。

## 读取条件

用户希望把已有普通角色卡、ST 角色卡、世界书、预设或配套扩展升级为独立前端应用时读取。

## 前置输入

- Task Envelope、原始文件及来源版本；尽量收集可运行的 ST 环境截图/导出/行为证据。
- 作者希望保留、改造和明确放弃的体验。
- 目标平台、内容模式、兼容档位和禁止执行边界。

## 方法

### 1. 建立只读来源快照

复制原始资产到隔离证据区，记录文件名、格式/版本、哈希、来源和相互引用。不得覆盖源文件。JSON/PNG 等使用结构化解析器读取，未知字段原样保留。

### 2. 盘点完整资产与依赖

至少检查：

- 角色核心字段、Persona/玩家假设、开场白、示例对话和备选开局。
- World Info/世界书、条目位置、触发、递归、概率、分组与禁用状态。
- Prompt/Preset 模块、启用状态、`prompt_order`、模型参数、停止词和 Prefill。
- 宏、变量、MVU、EJS、正则、前端脚本、扩展字段、第二 API 和外部资源。
- 仅靠 ST 宿主提供的历史、消息角色、存档、UI、命令和注入行为。

不能只看卡面字段。插件或预设承担的关键规则若漏盘点，独立应用会出现“内容在，但行为消失”。

### 3. 建立行为基线

在不修改来源的前提下记录代表性场景：初次开局、玩家拒绝/意外行动、多回合连续性、世界书正反命中、变量变化、保存重开、模式切换和已知异常。无法运行原环境时明确标记为来源推断，不能声称等价复现。

### 4. 提取目标语义

把来源映射到独立应用权威产物：

| 来源 | 主要目标 owner |
|---|---|
| 世界设定/秘密 | `World Contract`、`Lore Authoring Package` |
| 玩家身份/代演规则 | `Agency Contract` |
| 角色字段/示例语料 | `Character Portfolio` |
| 开场与剧情规则 | `Narrative Contract` |
| 预设模块 | `Prompt Policy Package`、`Executable Profile Contract` |
| 变量/脚本规则 | `Gameplay-Narrative Contract`、`Turn-State Transaction Contract` |
| ST 宿主行为 | Host、Assembly、Lore、Save、UI 等运行时契约 |

先迁移语义，再决定目标代码结构；不要把 ST 字段名直接当内部领域模型。

### 5. 给每项依赖分类

- **直接兼容**：目标运行时已有同义行为，且 fixture 通过。
- **转换**：能确定性映射为目标 Schema。
- **重写**：保留体验但改用原生 Kernel/Port 实现。
- **隔离**：保留资产但默认不执行，例如不可信脚本。
- **降级**：提供明确的较弱体验和提示。
- **放弃**：作者确认不进入目标，记录影响。
- **待作者裁定**：语义或授权不清，暂不实施。

未知项不得被默认为无用。

### 6. 决定兼容边界

分别选择 World Info 字段、Prompt/Preset、宏和资源格式的兼容范围。宏按完整/核心/不启用三档；MVU/EJS/正则/脚本不是自动继承的运行时，需提取状态规则或保持惰性。

### 7. 按垂直切片迁移

先完成最小开局 → 一次模型回合 → 一次候选变化 → 耐久保存 → 重开回放，再逐步加入 Worldbook、宏/预设、高级变量和 UI。每个切片与原行为基线和目标契约同时比较。

### 8. 输出兼容报告

使用 `../assets/templates/compatibility-report.md`，逐项记录原始位置、目标位置、分类、实现状态、证据、差异、风险和作者决定。保留原始附件或其哈希引用。

## 唯一产物

`ST Migration Dossier`：来源资产清单、行为基线、语义映射、兼容分类/报告、目标契约缺口、迁移阶段、风险和回归夹具。

## 轻量路径与升级

- 普通纯文字卡：静态字段盘点、世界/玩家/角色/开局映射、最小基线和目标内容包。
- 含 Worldbook、Preset、Macro、MVU、EJS、正则、脚本或第二 API 时升级完整依赖扫描与隔离迁移。

## 交接与验证

- 内容语义交给对应 RP owner；宿主缺口交给 Runtime；每项迁移分类交给 Stage 和 Quality。
- 验证原始数据未丢、未知能力保持可追溯、不可信代码未自动执行、目标应用脱离 ST 后仍能完成核心闭环。

## 不负责

不因为“能解析文件”就宣称玩法兼容，不自动执行插件代码，不原封不动复制外部方法正文，也不强制目标应用复刻 ST 全部 UI。
