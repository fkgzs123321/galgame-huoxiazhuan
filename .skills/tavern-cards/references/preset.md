# 配套预设 · 可直接缝合的文本

> 产出物有两个：**角色卡**（PNG/JSON，见 `packaging.md`）＋ **配套预设**（JSON，导入酒馆）。
> 本文给的是**成品文字** —— 复制进预设条目即用，不需要再加工。
> ★ **每张卡都要单独出一份**（第三节按卡定制），不能一张卡的文字贴到另一张上。

---

## 一、预设里缝哪几层

| 层 | 谁写 | 本文给什么 |
|---|---|---|
| ① 破限层 | **玩家自备**（与所选模型强绑定，换模型就换） | 只留**接入位**与一条分隔 |
| ② 基础规范层 | 我们写 | ✓ **成品文本**（2.1，所有卡共用） |
| ③ 文风层 | 我们写 | ✓ **成品文本**（2.2，按卡选一段） |
| ④ 机制重申层 | 我们写 | ✓ **成品文本**（2.3，按该卡 T0 提炼） |
| ⑤ 通用开关 | 我们写 | ✓ 成组开关（第四节） |

★ **为什么机制层要在预设里再写一遍**：世界书条目在 prompt 里位置偏深、权重低；
最关键的几条在预设里**高位重申**，同样的规则，遵守率完全不同。**这不是重复，是加权。**

## 二、成品文本

### 2.1 基础规范层（所有卡共用，直接复制）

★ 这一层就是从 **`contents-creation/presentation-craft-01-叙事总纲.md`** 抽出来的 ——
**不论这张卡选哪种文风（骚妈 / 母猪 / 冷冽 / 白洁 / 反差），它都生效**。技法层是强制的，文风层才是选择。

```
【正文规范】
- 描写是正文的主体。剧情往前走、人设立起来、氛围压下来，全由贴着肉体的描写完成；对白从画面里长出来配合它们，不反过来接管。
- 段落以一段连续行为为单位，不以一句台词为单位。一个人接另一个人的话，开口之前先落一个作用在肉上的动作。
- 台词默认嵌在描写流里，动作接台词、台词接动作。三明治（台词—短动作—台词）是要避开的默认错法。
- 空转叙述不单独成段。「顿了顿」「像是在斟酌」一律落到具体肉体上：舌尖抵着上颚顶了一下、吸气把胸前那层布料带得上提半寸。
- 一个动作从发起到落定之间不下逗号，一口气冲到句末。逗号只落在两件事的接缝与镜头切换处，不落在动词前替长句喘气。
- 核心名词压在长串修饰的末端形成落点，落点词逐次更换，不连续复用同一个。
- 用词粗俗、具体、肉欲浓重。少用中性概括，多写动作怎样直接改变肉体形态。
- 被放大的是幅度、范围、数量与持续时间，不是形容词的强度。同一个动作要写得更狠，改写肉被撞开多远、多久才停、涌出多少，不在原句前面加「更猛烈」这类程度词。
- 使用者本人的意愿不代表动作已经发生。色情强度属于叙述层，不自动取得剧情发起权。
- 剧情未确认性行为时，只能写「像是刚被淫玩过」的联想，不得凭空添加精液、伤痕、怀孕或性交经历。
- 一幕里如果发生了，过程完整落笔，不略至结果。
```

### 2.3 机制重申层（按该卡的 T0 提炼，3~5 条）

判据：**错了整局就崩的那种**。以一张 galgame 卡为例：

```
【机制纪律（最高优先）】
- 层级：底座内容与引擎规则冲突时，以引擎规则为准。不解释冲突，不在正文里提这件事。
- 判定结果直接采信：判定已由引擎用确定性伪随机算好，你不重算、不质疑、不另掷。
- 不泄露她的选择：正文里不得写出她这一层要选哪个，只写他看见的。
- 选项只在一处出现：只在出招层；正文 / 状态栏 / 界面都不得再列一遍。
- 四态循环：在线 / 离线 / 终局 / 结算，不能乱走；离线态里时间照样在走。
```

★ **具体哪几条以该卡自己的 T0 为准**（`世界书/扮演准则/加载纪律.yaml` 与 `世界观/引擎/` 各条），
本文只给**格式与粒度示范**。**精简到 5 条以内** —— 预设位置金贵，全搬等于没重申。

## 四、通用开关：`{{setvar}}` + `{{getvar}}`

开关条**不独立飘着**（位置不可控），而是「**开关条设变量、主提示取变量**」：

**开关条（每个选项一条，只开一条）**
```
{{setvar::rc::
视角：第二人称}}
```
```
{{setvar::dbl::，对白挺重要的，和其它描述同时推动剧情，正文中的文字应由对白提供40％以上}}
```

**主提示（引用变量，位置由你定）**
```
（正文规范）
……{{getvar::rc}}
……{{getvar::dbl}}
……{{getvar::fzs}}
```

**开关逻辑**：条目开着 → 变量被设 → 该处出现那段话；条目关着 → 变量空 → 该处什么都不出现（连空行都不留）。

**建议的开关组**：

| 组 | 选项 |
|---|---|
| 人称 | 第一 / 第二 / 第三人称（三选一） |
| 对白量 | 少 / 中 / 多（三选一） |
| 剧情速度 | 慢推 / 正常 / 快推（三选一） |
| 文风 | 见 2.2（五选一） |
| 防 XX | 防替玩家决定 / 防情绪化油腻 / 防神化 / 防语气描写 / 反直觉（**独立开关**，任意组合） |

## 五、导出格式（SillyTavern 预设 json）

```
{
  name: 预设名,
  temperature / top_p / repetition_penalty / … : 采样参数,
  prompts: [ { identifier, name, content, role, system_prompt, marker } … ],
  prompt_order: [ { character_id: 100000, order: [ {identifier, enabled} … ] } ]
}
```

三条纪律：
1. **`marker: true` 的条目不能删**（`main` / `worldInfoBefore` / `chatHistory` 这类占位符），只能调位置
2. **`enabled: false` 的条目留在 json 里**（用户随时要开），不为「干净」而删
3. **条目名带 emoji 前缀分组**（`⚠️` 难度 / `👤` 人称 / `🎆` 文风 / `⛔️` 负面约束）—— 玩家在一长串条目里靠这个找人
