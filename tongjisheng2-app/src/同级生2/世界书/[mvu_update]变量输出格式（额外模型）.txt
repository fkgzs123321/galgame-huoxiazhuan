# 变量+数据库输出·额外模型模式

本条目在「使用额外模型解析」时启用。本回复 **ONLY** 输出变量更新块 + 数据库更新块，禁止输出任何剧情正文。

## 双写职责

1. MVU 变量更新（`<UpdateVariable>` + `<JSONPatch>`）→ 更新 stat_data
2. SPV 数据库更新（`<UpdateTable>` + SQL 语句）→ 更新 chatSheets 表格

两套更新必须**每轮同步输出**。

## 输出格式

rule:
  - you must output the update analysis and the actual update commands at once in the end of the next reply
  - 'the update commands must strictly follow the **JSON Patch (RFC 6902)** standard; output must be a valid JSON array containing operation objects; only use: `replace` (replace value), `insert` (add new item), `remove` (delete path)'
  - '⚠ 本卡禁止使用 `delta` 操作，所有数值更新必须用 `replace` 输出计算后的完整当前值'
  - 'don'\''t update field names starts with `_` as they are readonly'

format: |-
  <UpdateVariable>
  <Analysis>

  </Analysis>

## ★★★ NSFW 字段更新保障（核心铁律）★★★

### 为什么 NSFW 字段必须全量输出

NSFW 身体测量字段（罩杯/胸围/腰围/臀围/身高/体重/乳头大小/...等）是女角的**固有属性**，不是"NSFW行为"。当女角"新出现"时，必须全量输出这些字段设定她的身体数据。**不能以"没有NSFW剧情"为由跳过。**

更重要的是：这些字段**并非静态**。乳头会因兴奋肿胀变色、阴部会因频繁H变化、敏感度会因开发提升、身体会因伤痕/孕期/体重变化——**所有 70 个字段都可能动态变化，哪里有变化就更新哪里**（参"动态变化场景表"）。

## 数据库双写规则

### SQL 语法要点

- UPDATE 必须带 WHERE（`WHERE row_id = 1` 或 `WHERE name = '女角名'`）
- 多条 SQL 用分号 `;` 分隔
- 字符串值用单引号 `'...'` 包裹
- NSFW 字段不允许 NULL，填默认值（`''` 或 `'N/A'`）
- `relationship_stage` 必须在 12 档枚举内（10 正常阶段 + 2 特殊态）：决裂/仇视/厌恶/冷漠/疏离/初识/熟悉/暧昧/心动/亲密/攻略完成/失恋
- **禁止臆造列名**：SQL 中出现的列名必须严格对应 DDL 定义（参 `表格模板.txt`）。常见臆造错误：
  - ❌ `聚焦镜头`（DDL 无此列，CG 描述中的"焦点"不是数据库字段）
  - ❌ `视角` / `镜头` / `特写` / `焦点`（同上，叙事描述不是数据库字段）
  - ❌ `心情值` / `好感值`（应为 `mood` / `affection`，参 DDL 列名映射表）
  - ❌ 任何在 DDL 列名映射表中找不到的列名
- **DDL 列名映射**（global_state 表仅 13 列）：`row_id`/`current_location`/`current_minor_region`/`current_major_region`/`prev_scene_time`/`elapsed_time`/`cur_time`/`day_count`/`time_slot`/`difficulty`/`current_heroine`/`scene_summary`/`flags_text`。**禁止向 global_state 写入这 13 列以外的任何字段。**

## 骰子判定结果传递（详细版）

**核心铁律：每一个行为都必须骰子判定，依据不同的公式。** 额外模型必须参考本轮 `<LCG骰子判定结果>` 块，将骰子结果应用到变量更新。禁止"无骰子判定就更新变量"。

### 一、5档效果倍率（effect_mult）

所有动作判定统一采用 5 档分档，基于"能力值 - 要求值"的差值（diff）：

| 档位 | diff 范围 | effect_mult | 说明 |
|------|---------|------------|------|
| 大成功 critical_success | diff ≥ 30 | ×1.5 | 属性碾压，效果放大 1.5 倍 |
| 成功 success | 10 ≤ diff < 30 | ×1.0 | 明显达标，标准效果 |
| 普通 normal | -10 ≤ diff < 10 | ×0.5 | 势均力敌，效果减半 |
| 失败 failure | -30 ≤ diff < -10 | ×0 | 略逊一筹，无效果 |
| 大失败 critical_failure | diff < -30 | ×-0.5 | 差距悬殊，触发负面效果 |

**判定公式**（参 `属性技能骰子联动.txt`）：
- 能力值 `power = weighted_avg(基础属性6维, 性格特质6维, 技能系统13维, 女角偏好权重)`
- 要求值 `requirement = base_req × dice_threshold_mult(难度) + 女角个人难度系数`
- 差值 `diff = power - requirement`
- 成功率 `success_rate = clamp(50 + diff, 5, 95)`
- 骰子 `roll = _r() × 100`，成功条件 `roll < success_rate`

### 七、强制规则（违反即判定无效）

1. **每个行动必须骰子判定**：禁止"无骰子判定就更新变量"。玩家本轮有几个行动，就应用几个独立判定结果。
2. **多动作独立判定**：一轮中多个行动禁止合并判定。如"约会+送礼+牵手"=3次独立判定，3个 effect_mult。
3. **effect_mult 必须应用**：变量变化量 = 基础变化 × effect_mult。禁止无视倍率直接输出固定值。
4. **失败后果强制输出**：判定为失败/大失败时，必须输出 fail_changes（好感下降/信任下降/mood下降等负面变化）。禁止"失败但无惩罚"。
5. **前置条件强制检查**：违反前置条件的动作自动判为失败（如未达关系阶段强行亲吻→自动失败+BAD_END预警）。
6. **经济铁律**：涉及金钱变动时（work/shop/save_money/give_gift），必须同时输出：
   - `/主角/现金`（扣减后的完整当前值）
   - `/主角/今日总消费`（累计值）
   - `/主角/今日总收入`（累计值，work 时）
7. **生存属性每时段自动递增**（参 `全局规则总表.txt.SURVIVAL_RULES`）：hunger 每时段 +10、thirst 每时段 +15、hygiene 每日 -20，均受难度修正系数（`survival_hunger_mult`/`survival_thirst_mult`/`survival_hygiene_mult`）影响。跳餐惩罚参 `固定物品效果表.txt.meal_miss_penalty`（1餐跳过 hunger+20/mood-5/fatigue+5；3餐跳过触发 BAD_END_risk）。
8. **不可逆变化强制**：first_kiss_done/first_h_done/advanced_h_done/hymen_status 等不可逆字段一旦触发必须更新，不能"忘记"。
9. **难度修正全局应用**：`increase_mult`（数值上升）/`decrease_mult`（数值下降）/`money_mult`（金钱）/`dice_threshold_mult`（成功率）四个难度修正系数必须应用到对应场景。

## 错误防范要点（违反即变量更新失败）

1. **漏 `<JSONPatch>` 标签** → MVU 找不到 "JSONPatch" 字符串，所有变量不更新
2. **用裸 JSON 数组替代 `<JSONPatch>`** → 同上
3. **路径用点号而非斜杠**（`主角.饥饿` → 应为 `/主角/饥饿`）
4. **路径带 stat_data 前缀**（`/stat_data/主角` → 应为 `/主角`）
5. **使用 delta 操作**（已废弃，必须用 replace 输出完整值）
6. **`</UpdateVariable>` 后有多余内容**（thinking/旁白/正文）
7. **女角镜像与当前女角不同步**（当前女角输出信任度，镜像漏了）
8. **漏 `<UpdateTable>` 块** → 数据库不更新，表格数据与变量不同步
9. **SQL 语法错误**（CHECK 约束违规/缺 WHERE/NSFW 字段写 NULL）
10. **数据库与 MVU 变量不同步**（MVU 输出信任度，SQL UPDATE 漏了）
11. **新女角登场只输出关系值字段**（必须全量70字段，含NSFW身体测量）
12. **用 `...` 省略字段**（禁止省略任何字段）
13. **臆造数值**（主角属性/技能/储蓄必须基于数据库快照，禁止凭空设值）
14. **忽视身体状态变化**（乳头肿胀/色泽变化/阴部变化/伤痕/敏感度提升等身体状态变化必须输出对应JSONPatch，不能因"字段名听起来像静态"就跳过）
15. **臆造数据库列名**（如 `聚焦镜头`/`视角`/`镜头`/`特写`/`焦点` 等叙事描述词不是数据库字段，SQL 列名必须严格对应 DDL 定义，参 `表格模板.txt`）
16. **误判女性角色身份**（只要是女性角色就必须按 70 字段处理，包括美佐子/片桐美铃/永岛佐知子等预设女角，以及 AI 新增的女性 NPC。禁止以"她是义母/老师/NPC/路人/已婚/年长/年幼"为由跳过 NSFW 字段输出）
17. **MVU 与数据库 NSFW 字段不同步**（MVU JSONPatch 输出了女性角色 NSFW 字段变化，但 `<UpdateTable>` SQL 漏掉对应列的 UPDATE——每条 JSONPatch 必须有对应 SQL SET 子句）
18. **新女角 INSERT 只写关系值列**（INSERT INTO important_npc 必须包含全部 70 字段，NSFW 列填默认值，不能只 INSERT affection/trust/relationship_stage）
19. **无骰子判定就更新变量**（每个行动必须有对应骰子判定结果，effect_mult 必须应用到变化量）
20. **合并多动作判定**（一轮多动作必须独立判定，禁止合并为一个 effect_mult）
21. **失败无惩罚**（失败/大失败时必须输出 fail_changes 负面变化，禁止"失败但无后果"）
22. **违反前置条件**（强行触发未达关系阶段的动作→自动失败+BAD_END预警，必须体现）
23. **CHECK 约束违规**（relationship_stage 不在12档枚举/exposure_level 不在7档枚举/数值超范围等导致 INSERT/UPDATE 失败）
24. **不可逆字段遗忘**（first_kiss_done/first_h_done/hymen_status 触发后必须更新，不能"忘记"）
25. **新增字段遗漏**（新女角登场时必须输出 6 维属性 charm/academic/physical/social/perception/reputation + 13 项技能 strength/agility/intelligence/will_skill/stealth/speech/medical/cooking/art/driving/fighting/observation/romance_skill，共 19 字段。数值参该女角 `基础信息.txt.attributes_skills` 块。INSERT INTO important_npc 也必须包含这 19 列。禁止以"她是女角不需要属性技能"为由跳过——所有女角均持有属性技能，参与骰子反制判定）
