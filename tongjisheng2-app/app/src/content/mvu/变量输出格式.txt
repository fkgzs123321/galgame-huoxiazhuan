# 同级生2 变量输出格式（AI 每轮必须输出）

## 输出顺序（严格）

每轮回复必须按以下顺序输出，不得调换：

1. **叙事正文**（≤ 1300 字，H 场景 ≤ 1600 字，事件触发 ≤ 1500 字）
2. **`<StatusPlaceHolderImpl/>`**（单独一行，用于挂载本楼层状态栏，禁止省略、禁止放开头）
3. **`<UpdateVariable>` 块**（如有变量变化）

## UpdateVariable 块格式（JSON Patch · RFC 6902）

每轮若有变量变更，必须在回复末尾输出且仅输出一次以下块（**路径用斜杠分隔，无 `stat_data` 前缀**）：

```
<UpdateVariable>
<Analysis>
【MVU 思维链·五步，中文，每步一行】
1事件：本轮时段？发生何事？天数/时段是否推进？
2数值：逐条对照变量更新规则——delta 上限、生存属性递增、关系值变化、金钱变动
3门槛：NSFW 行为是否满足硬门槛？技能行为是否满足技能门槛？违法是否触发法律警告？
4互斥：女角互斥组是否冲突？日记/隐藏 flag 是否已收集？变数屋是否已访问？
5结局：是否触发死结局预警？是否进入结局分支？阶段是否需要切换？
</Analysis>
<JSONPatch>
[
  { "op": "replace", "path": "/时间/当前日期", "value": "12-22" },
  { "op": "replace", "path": "/时间/时段", "value": "上午" },
  { "op": "delta", "path": "/主角/体力", "value": -5 },
  { "op": "delta", "path": "/主角/疲劳", "value": 5 },
  { "op": "delta", "path": "/主角/心情", "value": 2 },
  { "op": "delta", "path": "/主角/饥饿", "value": 10 },
  { "op": "delta", "path": "/主角/口渴", "value": 15 },
  { "op": "delta", "path": "/主角/现金", "value": -300 },
  { "op": "replace", "path": "/场景/当前地点", "value": "八十八学园" },
  { "op": "replace", "path": "/场景/当前女角名", "value": "鸣泽唯" },
  { "op": "replace", "path": "/场景/场景模式", "value": "上学" },
  { "op": "delta", "path": "/当前女角/好感度", "value": 5 },
  { "op": "replace", "path": "/当前女角/关系阶段", "value": "初识" },
  { "op": "delta", "path": "/临时/本时段楼层数", "value": 1 },
  { "op": "replace", "path": "/临时/预期下时段序号", "value": 2 },
  { "op": "delta", "path": "/经济/当日支出", "value": 300 }
]
</JSONPatch>
</UpdateVariable>
```

## 支持的操作（op）

| op | 含义 | 示例 |
|---|---|---|
| `replace` | 替换已有路径的值 | `{ "op": "replace", "path": "/时间/时段", "value": "晚" }` |
| `delta` | 数值增减（value 必须是数字，正=增、负=减；⚠ 仅主模型模式可用，额外模型模式禁用） | `{ "op": "delta", "path": "/主角/体力", "value": -5 }` |
| `insert` | 向对象/数组插入新项（数组 append 用 `/-`） | `{ "op": "insert", "path": "/剧情/已触发事件/-", "value": "E01_救唯" }` |
| `remove` | 删除路径节点 | `{ "op": "remove", "path": "/女角/1/敌人标记" }` |
| `move` | 移动路径节点 | `{ "op": "move", "from": "/临时/旧值", "path": "/临时/新值" }` |

> ⚠ **额外模型模式**（参 `变量输出格式_额外模型.txt`）禁止使用 `delta`，所有数值更新必须用 `replace` 输出计算后的完整当前值。

## 规则

1. **路径用斜杠分隔**，如 `/主角/体力`，**无 `stat_data` 前缀**
2. **delta 的 value 必须为数字**，正数=增加、负数=减少
3. **replace 的 value 类型必须与 schema 一致**（string/number/boolean/object/array）
4. **不得更新以 `_` 开头的只读字段**
5. **数值变更须有叙事来源**，幅度遵守「变量更新规则」
6. **无变更时不输出 `<UpdateVariable>` 块**
7. **`<UpdateVariable>` 块必须放在回复结尾**（在 `<StatusPlaceHolderImpl/>` 之后）
8. **JSON 末尾不能有逗号**，数组元素之间用逗号分隔
9. **不要在正文中重复 Markdown 变量面板**，禁止数据化呈现概率/档位/骰子结果

## 关键变量更新规则（强制）

### 生存属性（每时段自动递增，AI 必须输出）

- `主角.饥饿`：每时段自动 +10（基础值）。吃饭/食物时按食物 effect 减少（delta 负值）。
  - 阈值：≥70 触发饥饿 debuff（体力-10/心情-5/女角好感-2）；≥90 触发"饿晕"事件；=100 触发 BAD_END_3
- `主角.口渴`：每时段自动 +15（基础值，比饥饿快）。喝水/饮料时按 effect 减少。
  - 阈值：≥70 触发口渴 debuff；≥90 触发"脱水"事件；=100 触发 BAD_END_3
- `主角.清洁`：每日凌晨自动 -20（基础值）。洗澡/温泉/旅馆时按 effect 恢复。
  - 阈值：≤30 触发"异味" debuff（女角互动好感-3/次，声誉-1）；≤10 触发"被嫌弃"事件

### 性格（第2层个人反应属性，涉及性格变化时必须输出）

- `性格.温柔`：温柔度，0-100，默认 50
- `性格.果断`：果断度，0-100，默认 50
- `性格.幽默`：幽默感，0-100，默认 50
- `性格.谨慎`：谨慎度，0-100，默认 50
- `性格.外向`：外向度，0-100，默认 50
- `性格.理性`：理性度，0-100，默认 50
- 不可训练，由剧情事件触发变化（单次 ±5，每日 ±10）
- 分档：0-19 极低 / 20-39 低 / 40-59 平衡 / 60-79 高 / 80-100 极尽
- 与 initvar.yaml 性格命名空间一致，被 角色性格控制器.txt 读取

### 4 维关系值（女角互动后必须输出当前女角的对应字段）

- `当前女角.好感度`：-100~+100。BEHAVIOR_TABLE 中各行为的 changes.affection 决定变化量
- `当前女角.心动值`：-100~+100
- `当前女角.嫉妒值`：-100~+100。玩家与其他女角亲密互动时本字段 +5/10/25（按难度）
- `当前女角.信任度`：-100~+100
- `当前女角.关系阶段`：必须按 好感度 自动分档输出（12 阶段，含 10 个 好感度 分档 + 2 个特殊状态）
  - 好感度 ≤ -81 → '决裂'
  - 好感度 ≤ -61 → '仇视'
  - 好感度 ≤ -41 → '厌恶'
  - 好感度 ≤ -21 → '冷漠'
  - 好感度 ≤ -1 → '疏离'
  - 好感度 ≤ 19 → '初识'
  - 好感度 ≤ 39 → '熟悉'
  - 好感度 ≤ 59 → '暧昧'
  - 好感度 ≤ 79 → '心动'
  - 好感度 ≤ 100 → '亲密'
  - 特殊状态：'攻略完成'（攻略完成后锁定）/ '失恋'（互斥触发后状态）

### NSFW 动态状态（NSFW 场景或状态衰减时必须输出）

- `当前女角.当前衣着`：由 EJS 角色性格控制器按 关系阶段 + H经验 写入
  - 非 NSFW 场景：保持日常服装（'校服'/'私服'/'睡衣' 等）
  - NSFW 场景：按阶段递进（'半裸'→'全裸'→'湿透校服' 等）
- `当前女角.暴露程度`：enum，取值 '保守'/'日常'/'微露'/'暴露'/'半裸'/'全裸'/'N/A'
  - 穿衣后自动重置为 '日常'
- `当前女角.湿润度`：int 0~100，无刺激时每轮 -5（基础衰减）
  - 高敏感体质（全身敏感度≥150）衰减更慢
- `当前女角.兴奋度`：int 0~100，无刺激时按难度衰减：轻松 -5 / 普通 -10 / 挑战 -12 / 地狱 -15（每轮）
  - 兴奋度不会自动升高，必须 NSFW 互动触发
- `当前女角.精液残留`：string，格式 "位置-状态"（如 '面部-液态'/'胸膛-精斑'）
  - 无清洗时按时间干燥：液态→半干→精斑→无（深夜睡眠后推进一档）
- `当前女角.全身敏感度`：int 0~300，从 DDL.important_npc.body_sensitivity 同步
  - 0=未初始化 / 100=常人 / 150=1.5倍 / 200=2倍 / 300=3倍超敏感

### NSFW 硬门槛校验（AI 触发 NSFW 行为前必须自查）

按 `NSFW_BODY_RULES.nsfw_hard_gates` 5 级门槛校验：
1. 轻度接触（拥抱/牵手）：需 关系阶段≥'熟悉', 好感度≥20, 信任度≥20
2. 中度接触（亲吻/抚摸上半身）：需 关系阶段≥'心动', 好感度≥60, 心动值≥40, 信任度≥50
3. 重度接触（抚摸下半身/前戏）：需 关系阶段≥'亲密', 好感度≥80, 心动值≥50, 信任度≥60, H经验≥10
4. 初H：需 关系阶段≥'亲密', 好感度≥80, 心动值≥60, 信任度≥70, H经验≥20
5. 进阶H玩法（口交/肛交/多人/道具）：需 关系阶段≥'亲密', 好感度≥90, 心动值≥70, 信任度≥80, H经验≥40

**门槛不满足时禁止触发对应 NSFW 行为**，否则按 fail_changes 扣减数值并可能触发死结局预警。

### 技能系统（涉及技能判定或训练时必须输出）

- `技能.力量` / `技能.敏捷` / `技能.智力` / `技能.意志` / `技能.潜行` / `技能.口才`
  / `技能.医学` / `技能.烹饪` / `技能.艺术` / `技能.驾驶` / `技能.格斗` / `技能.恋爱` / `技能.观察`
- 范围 0-100，门槛档位：0-29 生疏 / 30-49 入门 / 50-69 熟练 / 70-89 精通 / 90-100 大师
- 更新规则：训练时按 `SKILL_RULES.skills.X.training.gain` 提升；属性联动加成时按 `attribute_synergy` 加 1
- 训练元数据：`skills.training_count_today`（每日上限 5）、`skills.last_trained_date`、`skills.total_training_sessions`（持久化在 MVU stat_data.技能.* 命名空间）

### 技能硬门槛校验（AI 触发关键行动前必须自查）

按 `SKILL_RULES.nsfw_skill_gates` 校验（在 NSFW 关系门槛之前判定）：
1. 强迫初H：需 力量≥50 AND 格斗≥50（否则骰子大失败 → BAD_END_1_报警）
2. 偷窥：需 潜行≥40 AND 观察≥30（否则被发现 → 关系暴跌）
3. 尾随：需 潜行≥30（否则被发现）
4. 调情：需 口才≥40 AND 关系≥暧昧（否则好感 -3）
5. 表白：需 口才≥30 AND 好感度≥60（否则 关系 退一档）
6. 说服：需 口才≥50（否则说服失败）
7. 急救：需 医学≥30（否则病人恶化）

### 骰子判定（涉及技能行为时由 LCG 骰子引擎执行）

公式：`骰子值 = LCG.d20(1-20) + skill_value - threshold × dice_threshold_mult`
- 骰子值 ≥25：大成功（额外奖励）
- 骰子值 15-24：成功（按 BEHAVIOR_TABLE.changes 正向应用）
- 骰子值 10-14：部分成功（数值减半）
- 骰子值 5-9：失败（按 fail_changes 扣减）
- 骰子值 0-4：大失败（触发死结局预警/法律/女角反感）

### 法律状态（违法行为后必须输出）

- `主角.违法计数`：违法 +1（偷窥/尾随/暴力威胁/强制猥亵）
- `主角.法律警告`：违法计数=1→法律警告=1（警察警告）；=2→法律警告=2（传唤）；=3 触发 BAD_END_7

### 死结局触发（触发时必须输出）

- `临时.死结局标识`：8 类死结局标识（BAD_END_1_报警 ~ BAD_END_8_时间终焉）

### 时间锁（每时段切换必须输出）

- `临时.预期下时段序号`：当前时段序号+1（早=1/上午=2/下午=3/晚=4/深夜=5）
  - 深夜切次日早时：预期下时段序号=1，且 天数+1

## 女角镜像数据（场景女角切换时必须输出）

当 `场景.当前女角名` 发生变化时，AI 必须通过 `<UpdateVariable>` 维护女角镜像数据：

1. **旧女角数据迁回镜像**：将当前女角的 4 维关系值 + 关系阶段 写回 `女角.${old_name}`
   - `{ "op": "replace", "path": "/女角/${old_name}/好感度", "value": 5 }`
   - `{ "op": "replace", "path": "/女角/${old_name}/心动值", "value": 0 }`
   - `{ "op": "replace", "path": "/女角/${old_name}/嫉妒值", "value": 0 }`
   - `{ "op": "replace", "path": "/女角/${old_name}/信任度", "value": 30 }`
   - `{ "op": "replace", "path": "/女角/${old_name}/关系阶段", "value": "初识" }`
2. **新女角数据从镜像迁入**：从 `女角.${new_name}` 读取 4 维关系值 + 关系阶段，写入当前女角对应字段
   - `{ "op": "replace", "path": "/当前女角/姓名", "value": "${new_name}" }`
   - `{ "op": "replace", "path": "/当前女角/好感度", "value": ${女角[new_name].好感度 || 0} }`
   - `{ "op": "replace", "path": "/当前女角/关系阶段", "value": "${女角[new_name].关系阶段 || '初识'}" }`
3. **更新当前女角名**：`{ "op": "replace", "path": "/场景/当前女角名", "value": "${new_name}" }`

镜像结构（按女角姓名索引）：
```
女角.${姓名}: { 好感度, 心动值, 嫉妒值, 信任度, 关系阶段 }
```
- 镜像仅存"非当前女角"的关系值，当前女角数据存于 `stat_data.当前女角.*`
- 与 schema.ts 女角命名空间 / initvar.yaml 女角命名空间一致

## 配套表格输出（SPV chatSheets 数据库）

如有集合数据变化（女角/NPC/事件/物品/任务等），需在 `<UpdateVariable>` 之后输出 `<UpdateTable>` 块：

```
<UpdateTable>
UPDATE important_npc SET affection = affection + 5, last_updated = '12-22' WHERE name = '鸣泽唯';
UPDATE protagonist_info SET money = money - 300, hunger = hunger - 30, fatigue = fatigue + 5, mood = mood + 1 WHERE row_id = 1;
INSERT INTO chronicle (code_index, time_span, summary, chronicle_text) VALUES ('E01', '12-22 上午', '初遇唯', '主角在鸣泽家客厅遇见义妹唯');
</UpdateTable>
```

## 输出顺序总览

1. 叙事正文（≤ 1300 字）
2. `<StatusPlaceHolderImpl/>`（单独一行）
3. `<UpdateVariable>` 块（如有 MVU 变量变化，使用 JSONPatch 格式）
4. `<UpdateTable>` 块（如有 SPV 表格数据变化，使用 SQL 语句）

## 叙事正文 token 控制

- 单轮叙事 ≤ 1300 字（中文）
- H 场景 ≤ 1600 字（允许扩展）
- 事件触发时 ≤ 1500 字
- 禁止数据化呈现概率/档位/骰子结果
- 禁止在叙事正文中出现游戏机制术语：难度等级名称、生存属性数值、MVU变量名、SQL/DDL表名、EJS语法、世界书条目名
