## 四、引擎 + 底座架构

- **分界判据：是否随「换游戏」而变。** 屏幕外的她 → 不变 → 引擎；女角/世界观 → 变 → 底座。换底座 ＝ 改 `世界.底座` ＋ 放底座条目 → EJS 路由。
- **order 分区**（**物理上不许交错**）：`1-19` T0 宪法层｜`20-49` T1 状态层｜`50-99` T2 契约层（只声明接口）｜`200-399` T3 底座（必门控，大条目走 EJS 裁剪）｜`400+` T4 按需层（selective，绝不 constant）
- **三条门控铁律**：① 底座条目必含 `世界.底座` 判定 ② 大条目必走 EJS 裁剪 ③ **单条常驻「渲染后」≤ 5,000 字符**
- **加载纪律**：`扮演准则/加载纪律.yaml`，**order = 1**；**底座与引擎冲突以引擎为准**（不解释、不写进正文）
- **引擎 8 处底座耦合点**（换底座必改）：`schema.ts` ① `世界.底座` enum ② `当前关卡` 默认 ③ `场景` 默认 ④ `当前线` enum ⑤ `篇章` enum ⑥ `事件/终局.yaml` ⑦ `关卡序列.yaml` ⑧ `创作规划.yaml` 的 `ejs.entries` 显隐条件
- **零耦合可原样搬（25 条）**：`世界观/引擎/`＋`扮演准则/`＋`阶段指导/`＋`角色/屏幕外的她/`＋`机制/判定引擎.txt`
- **角色结构（四方）**：`现实世界的我` 只作用于 `<user>` **内层**，**影响不了屏幕外的她**；她唯一通道＝「`<user>` 的异常 → 被她当成游戏故障」。
  ★ **通用规律：某类输入没有归属 = 设计缺口的高频形态**（表现为「角色被玩家带跑」）
- **换任何底座都要另建一份「零耦合清单」核对**：引擎 8 耦合点逐条落到新底座的文件上。
- ⚠️ **不在底座体系里的独立卡（如 系统哥的末日）天然过不了 verify-prompt-budget 的第 1/2 条**（order 分区、`世界.底座` 判定）→ 那两条是底座专属，**只看单条上限 / 分层预算 / 常驻总量 / 按需层误常驻**四条。

## 五、机制层判据 + 判定引擎 + 她的手段

- **三判据**：① 换底座还成立吗 ② **含不含「具体内容」**（含 → 要素）③ 是否为别的功能提供能力。
  ⚠️ 判据 2 最易错：**怀孕系统不是机制**——机制层只提供「带周期的可累加状态」。
- **机制层 = 引擎能力 + 契约声明（表）**；底座 = 填表 + 提供内容。**skills 本身就是这个分层的实例**（引擎 = `scripts/*.mjs`；契约 = `references/requirements/` + `type/state.ts`；要素 = `contents-creation/*.md`）。→ **原卡病根：绕过推导（手工填 index.yaml）＋ 没有校验。**
- **判定引擎 E3**：`D = P - R + E` → `S = clamp(50+D,5,95)` → `V = LCG(seed)×100`，`V < S` 成功；**档位由 D 与成败联合决定**（大成功×1.5／成功×1.0／勉强×0.6／大失败×2.0）。
  原实现两 bug：① 分档与成败不同源 ② 关系阶段修正恒为 0。要保留：**LCG（禁 `Math.random`）／权重归一化／难度用乘法**。已落地 `机制/判定引擎.txt`（`judge()`），`scripts/test-judge.mjs` 30/30。
  ★ **判定放玩家按拒绝按钮那一刻**（AI 不能执行 JS；状态栏是前端能读写变量），条目只负责把结果交给 AI。
- **E6 · 她的手段**（属引擎层，不随底座换）：手段本身即性格。两维度＝遇障碍／遇无聊。
  温砚 反复试·也认真看·不开挂｜丰娆 换线·**快进**·偶尔开挂｜舒晏 **故意更难**·**反复看同一段**｜唐响 撞上去·乱点｜沈眠 **阻止救援**·静静看｜莫漾 **外挂跳过**·**挂机**·最懒｜纪清 算漏洞·为补漏开挂｜郁灼 只挑最刺激的。
  **后果全落在 `<user>`**；**开挂是最重手段**（改好感/时间/关系阶段/flag）。
  ⚠️ 底座相关的「手段表现」写进底座（同级生2＝`底座_nanpa2/人设补丁.yaml`），不进引擎层。

## 六、★★ 屏幕外的她 · 结构定稿

- **8 套 × 2 条 = 16 条**，全在 T1（`她_XX_主体` order 29-36 ／ `她_XX_阶段` 37-44）；`@@if` 门控（底座 + `她.人设`）。
- **主体**：基本信息/外貌特征/背景设定/性格调色盘/游玩风格（含 **★ 她怎么发骚**）/关系设定/诉求/她要拿到什么/**她离目标还有多远**/现实干扰/退场。
- **阶段**：**熟练度 5 档 · 只此一个变量**，条目内 EJS 精准裁剪，只渲染当前一档。
- ★ **只有熟练度是「阶段」**；**目的进度不是阶段，是一个数**。⚠️ 用户当场纠过「**熟练度才是唯一变量吧**」——把目的进度也做 3 档＝过度设计。
- **`她.熟练度`（0~100）**＝运用「手段」的老练度。引擎四处读它：误点概率／**反抗成功率惩罚**（新手 0 → 上手 .1 → 沉浸 .2 → 狂热 .3 → 收官 .4）／离线痕迹扫描强度／她上线多久。分档 **新手 1~20｜上手 21~40｜沉浸 41~60｜狂热 61~80｜收官 81~100**；与 `目的进度` 任意错位。
- **每档都要有**：`她的手段（★…）`／`她的边界`／做得到／做不到／**她的样子**／她怎么玩／她说的话／她不会做什么／她怎么到自己那一下／完事之后
- **写法**：`@@if`（在 `contents`）＋ 文件内块作用域 `<% { %>` ＋ `<%_ const 熟 = getvar(...) _%>` ＋ if/else。**一个条目只有一个装饰器**。
  ★★ **`<%_ ... _%>` 只吃空格与制表符，不吃换行**（真 ejs 实测）。**别信自己写的迷你渲染器。**
- **配套脚本**：`scripts/验证_阶段裁剪.cjs`（8×5 通过）／`scripts/校验_屏幕外的她.cjs`（0 问题）／`scripts/render-entry.cjs`（**真 ejs 渲染单条目**）
- **8 套极端玩法（壳各不相同）**：温砚（壳厚→薄）／丰娆（无壳）／舒晏（壳＝温柔）／唐响（「我就试试」）／沈眠（「随便点点」）／莫漾（「反正闲着」）／纪清（「我在算效率」）／郁灼（无壳）。
- **⚠️ 未决（规划里是空的，不许自创）**：① `过程.世界的裂缝.意义` / `过程.她用过的手段.意义` 只有 `|` 没内容 ② `变量更新规则.yaml` 引用「开挂（**L3 手段**）+1」但 **L1/L2/L3 从未定义** ③ `底座_nanpa2/人设补丁.yaml` 只有 7 套，**缺郁灼**
