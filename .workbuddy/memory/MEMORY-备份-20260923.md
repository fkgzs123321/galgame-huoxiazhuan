## 二、⚠️ 协作铁律（违一条就返工）

1. **不自己裁决** —— 冲突或规划没写：先查规划（design-spec／创作规划.yaml／机制层规范）；仍没有 → **列给用户决定 + 每案影响**（改哪些文件、破坏哪些已有内容）。
2. **判「原作没有」前必须搜全** —— 中文百科＋英文维基＋日文攻略＋论坛帖，**每个来源翻完分页**。**原卡被判错先假设自己搜漏**。
3. **删掉自创设定后不许顺手编新的顶上**（还是自创）。
4. ★★ **「怎么写」不用我写，只做结构** —— 用户给整包资料时里面已规范好写法；我只理解结构（分层/挂载/索引/接口/取用规矩/边界）。✗ 重写手法段 ✗ 自写样本 → ✓ **照搬，一字不改**。
5. ★★ **模板必须自包含** —— ✗「同上」✗ 别处才有的名字 ✗ 纯占位符 → ✓ `槽位｜这格填什么｜照着这个写（原句）`＋填好范例。
6. ★★★ **强制要求必须写进「执行流程」** —— 只挂 `references/` 清单＝写卡时不打开。✓ 创作循环加步骤＋SKILL.md 同步＋`rules-check.md` 加**可数**判据。自检：**这段对应素材索引表哪一节？说不出＝凭印象写。**

## 三、⚠️ 审计铁律（变量侧 4 次／条目侧 3 次／校验器 3 次都栽在这）

**脚本只能「列线索」，判定必须人工；脚本的判定性指标一律不可信。**
- 「20 次公式参与」＝ 1 个真读点 + 19 份手工复制的同一段逻辑
- 审计器用 `enabled` 判常驻/按需，但 ST 投放看 `strategy` → 全盘误报
- **词表不全＝守卫是假的**（6/23 → 补词后 13/23，还漏「西御寺」）
- **量错方向比不量更危险**：拿「文件字符数」判「渲染后 ≤5000」→ 会让人删本就进不了 prompt 的字。**判据写「渲染后」就必须真渲染再量。**
- 自动审计把 `元数据.小时`／`玩家.警觉度`／`玩家.D20历史` 判成「没人读」——因 D0 用局部名 `_meta.小时`。**脚本产出的「死变量/未引用」清单必须逐条人工看用法。**
- ⚠️ **手动查，不要脚本查**（用户明确要求）：要**用眼读出来**，脚本只按词表捞关键词。

**过审判据**：每个数值问三句 —— ① 玩家看得见吗 ② 能拿它做决策吗 ③ 会改变叙事走向吗；三否 → 删。再反问 **这数值是帮玩家玩，还是替 AI 记账？**

## 五、机制层判据 + 判定引擎 + 她的手段

- **三判据**：① 换底座还成立吗 ② **含不含「具体内容」**（含 → 要素）③ 是否为别的功能提供能力。
  ⚠️ 判据 2 最易错：**怀孕系统不是机制**——机制层只提供「带周期的可累加状态」。
- **机制层 = 引擎能力 + 契约声明（表）**；底座 = 填表 + 提供内容。**skills 本身就是这个分层的实例**（引擎 = `scripts/*.mjs`；契约 = `references/requirements/` + `type/state.ts`；要素 = `contents-creation/*.md`）。→ **原卡病根：绕过推导（手工填 index.yaml）＋ 没有校验。**
- **判定引擎 E3**：`D = P - R + E` → `S = clamp(50+D,5,95)` → `V = LCG(seed)×100`，`V < S` 成功；**档位由 D 与成败联合决定**（大成功×1.5／成功×1.0／勉强×0.6／大失败×2.0）。
  原实现两 bug：① 分档与成败不同源 ② 关系阶段修正恒为 0。要保留：**LCG（禁 `Math.random`）／权重归一化／难度用乘法**。已落地 `机制/判定引擎.txt`（`judge()`），`scripts/test-judge.mjs` 30/30。
  ★ **判定放玩家按拒绝按钮那一刻**（AI 不能执行 JS；状态栏是前端能读写变量），条目只负责把结果交给 AI。
- **E6 · 她的手段**（属引擎层，不随底座换）：手段本身即性格。两维度＝遇障碍／遇无聊。
  温砚 反复试·也认真看·不开挂｜丰娆 换线·**快进**·偶尔开挂｜舒晏 **故意更难**·**反复看同一段**｜唐响 撞上去·乱点｜沈眠 **阻止救援**·静静看｜莫漾 **外挂跳过**·**挂机**·最懒｜纪清 算漏洞·为补漏开挂｜郁灼 只挑最刺激的。
  **后果全落在 `<user>`**；**开挂是最重手段**（改好感/时间/关系阶段/flag）。
  ⚠️ 底座相关的「手段表现」写进底座（同级生2＝`底座_nanpa2/人设补丁.yaml`），不进引擎层。

## 八、文风库（`contents-creation/`）

- `craft-01~06 技法层`（总是）／`common-01 用词层`／`common-02 素材层`／`style-01~06 文风层`。`character/by-style/` 六套×三份（基础信息/调色盘/多阶段）。**`presentation-styles.md` 是总索引。**

- ★ 规范条文用**说明文体**；只有实样按文风本身写。★ **表现尺度**放大的是**幅度/范围/数量/持续时间**，不是形容词强度。
- ★ **三层落笔法**：形态 + 受力质地 + 第三层（被挤到哪/温度气味/透出多少/攥紧挤出多少/牵动哪处），**缺层不成立**。

- ★ **乳/屄/臀不配雅词**；雅词每段至多一处且必须与秽词同框。★ **禁则要能被机器执行，有禁就有替**。

## 九、MVU + EJS 铁律

- ★★★ **Zod 卡里数组/对象「加新项」走不通（2026-09-22 源码坐实）**：
  MVU 核心把命令**同时**发给 zod 处理器与自己的执行器；**zod 语法里 `add` ＝ 数字加减**，**追加数组要用 `insert`** → 标准 JSON Patch 的 `{"op":"add"}` 打到数组上会被 zod 判「不是数字」而**不消费** → 落到核心 → 核心判 `'array'===type && (!1===extensible || undefined===extensible)` → 必抛 `assignNonExtensibleArray`。
  而 **zod 卡拿不到 extensible**（`mvu_zod.js` 与 `registerVariableSchema` 里 `extensible` 各 **0 次**）。→ **`/-` 只管「插到末尾」，不管「允不允许插」**。
  ★ **判据速记：报错前缀是 `[MVU]` 而非 `[MVU zod]` ⇒ 命令没被 zod 层消费，落到了带校验的核心。**
  **Zod 卡三种正确做法**：① 列表类变量**别用数组，用字符串**（`、`／`；` 分隔）整串 `replace`；② 系统记账类**交给卡内脚本写**（前端 `Mvu.replaceMvuData` / `updateVariablesWith` **不经过命令校验**）；③ 真要数组只能整组 `replace`（走 `set` 分支无校验），但注意核心对「恰好 2 元素且第 2 个是字符串」的 VHD 误判。
  ⚠️ **对象加新键同样中招** → 需要新增的键**预置在 initvar**，规则写成「只 replace 值，永不新增键」。
- **门控兜底（三通道 + 一兜底）**：前端/表单写 `stat_data.X` 后世界书 `@@if getvar(...)` 可能读不到 → 永远走 defaults：
  ① chat 级 `updateVariablesWith(fn,{type:'chat'})` ② floor 级 `{type:'message',message_id}` ③ slash 兜底 `triggerSlash('/setvar ...')`
  ④ EJS 条件写 `matchChatMessages(['TAG:值'],{start:0}) || (!matchChatMessages(['TAG:'],{start:0}) && getvar(...)==='值')` —— **右项必须带 `!matchChatMessages(['TAG:'])`**；`start` 默认 **-2**，扫全历史必须显式 `{start:0}`。
- **initvar_override**：`开场白/N.txt` ↔ `开场白/initvar/N.yaml` **必须同号**；key 是 `first_messages` 原始值，JSON Pointer 里 `/`→`~1`；父字段不存在先 `{"op":"add","path":"/initvar_overrides","value":{}}`；patch 的 `replace` 打在「值是文件路径」的字段会被当**文件重命名** → 用 `remove`+`add`。
  **ST 端映射**：`first_messages[0]`→`first_mes`，`first_messages[1..]`→`alternate_greetings[0..]`。
- **卡面校验**：PNG 的 `chara` chunk 是 **base64 编码 JSON**（`tEXt`，data = `chara\0<base64>`）；`character_book` 在 `card.data.character_book`；`data.extensions.regex_scripts` 是**数组**。★ **打包后要真解 PNG 复核，不能只看源文件。**
