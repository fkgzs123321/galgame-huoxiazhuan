## ★★★ 状态栏卡在「正在载入」的真因：围栏重复（packer 会自己加）

### 截图给出的两个线索
1. 面板上下各露出一行 `…`（= 一个**空代码块**）
2. 中间 `<body>…正在载入状态栏…` 被当**裸文本**渲染

### 真因：`pack_yumq.mjs:628` —— packer 读 `replace_file` 时会自己套围栏
```js```
obj.replaceString = '```html\n' + htmlContent + '\n```\n';
``````
而我的源文件 `正则/状态栏界面.html` **自己也带了围栏** → **双重包裹**：
``````
```html      ← 空代码块开始
```          ← 空代码块立刻结束
<body>…      ← 变成裸文本（HTML 规范不允许 body 嵌在消息流里）
</body>
```
```          ← 又一个空代码块
``````
⇒ 所以状态栏**根本没被渲染成独立界面**，只剩一个转圈的占位。

### 修法
**源文件不带围栏**（只写 `<body>…</body>`），让 packer 套那对围栏。
修后卡里：````html` + `<body>…</body>` + ````` → 围栏 **2 行** ✅

### ★ 和 skills 的关系（容易看错的一处）
`ui/text.md` 说「含 `<body>` 的界面，文件首尾要用 3 个反引号包裹」——
那是给**直接用 ST 原生 `replace_file`** 的卡说的。
**我们这条管线里 packer 已经代劳了**，所以源文件不该再带。
判据：**看 packer 有没有加**，不要只看 skills 的原文。

## ★★★ 「点一个选项就消失一个」—— skills 直接否掉了我之前的做法

### skills 里三条相关规范

**① `sillytavern-embedded-ui` · Keep state ownership explicit**
状态分四类：
``````
data state      持久化的游戏/配置数据
draft state     可撤销、未确认的用户输入
UI state        tab、展开、焦点、滚动、临时错误
derived view    格式化值、计数、进度、摘要
``````
> **不要把 tab、折叠、滚动位置持久化进世界书或 MVU，除非它们本来就是玩法的一部分。**
> **尽量在数据刷新后保留用户控制的视图状态。**

   我原来在 `做选项()` 里把 `局面.当前选项[k]` **清空** —— 那是 **UI 越权改 data**。

**② 同 skill · Render defensive data**
> **Show malformed or unsupported data as a diagnostic state rather than silently hiding it.**
⇒ 「变空就 `hidden`」正是规范禁止的 **silently hiding**。

**③ `ui/text.md` · 限制与边界**（更根本）
> 纯文本版基于字符串替换，**无法执行 JavaScript 逻辑**。以下场景应改用**前端版**：
> 条件显示 / 数值映射 / **进度条、动画、交互按钮** / 跨多消息的状态记忆

## ★★★★ 点选项后卡死 —— 两个源：整块重建 DOM + 每次都 fetch

### 症状
点选项 → 判定正常跑完、结果也推进了输入框 ✓ → **然后界面卡死**。

### 卡死源（`refresh()` 里两行）
`js`
async function refresh(showBusy){
  ...
  loadTheme(); 拉原文(); 补模板(); 同步();     // ← 这两个
}
```
1. **`拉原文()`** 是网络 `fetch` —— **每次判定后都发一次**
2. **`补模板()` 里的 `root.innerHTML=S.模板`** —— 每次重绘把 **115KB 的面板整块重建**（重排 + 样式重算）
两者叠一起，点一下就卡。

### 改成（照 旮旯给木-同级生2 的精神：**不重建 DOM，只改文本**）
| 函数 | 改法 |
|---|---|
| `补宏()` | **首次**遍历 DOM，把**每个含宏的节点 + 它的原文**记进 `宏节点[]`；之后**只把值写回那几个节点**（`nodeValue` / `setAttribute`），**DOM 结构一个都不动** |
| `补模板()` | **删掉** `root.innerHTML=S.模板`；只保证输入框里的字还在 |
| `refresh()` | `拉原文()` 改成 **只在首次**（`if(!S.模板就绪)`）|
| `渲染选项()` | 只重建**选项区**那一小块（本来就是我上一步加的）|
| 拉原文成功后 | `宏节点=null` → 下次 `补宏` 重新收集（因为 ST 可能又替我们替换过一轮）|

### 验收
不再有 `root.innerHTML=S.模板`（仅注释提及）✅｜refresh 不再每次 fetch ✅｜有 `收集宏节点()` ✅｜JS 通过 ✅
CDN `c0edcd1` ✅｜loader 已更新 ✅｜打包 121 条 ✅｜需重导卡

### ★ 教训
**"每次重绘都重建整块 DOM"是性能自杀** —— 面板越大越致命（这张 115KB）。
同级生2 全程只 `txt()/bar()/num()/chips()` 改单个元素，从不重建。**这是它流畅的根本原因。**
