## 关键经验
- **字节 vs 字符陷阱**：ls 显示 UTF-8 字节（中文3字节/字），JS .length 是 UTF-16 码元（中文1码元）——对比文件大小要用同口径
- **EJS 渲染验证**：条目含 await getwi 必须 `ejs.render(..., {async:true})`；`@@if/@@private` 是 tavern-cards 层语法，渲染前须剥离

## 第二轮：用户实测首页第一句话仍 8万+ token（16:48）

### 根因（比第一轮更深一层）
- **initvar.yaml 初始 12 成员中 8 个 `本轮活跃: true`** → 首页时角色档案 @@if（本轮活跃===true）命中 8 份 + [总控]NSFW 按活跃拉 8 份 NSW ≈ 全量注入

- 用户关键洞察："所有人的 nsfw 是不是有唯一的变量值能够 ejs 控制"——**答案：是**（每个 NSW 档案有 uid/phase/isProfiled 变量 + 内容级阶段门控）

### 修复（第二轮）
1. **initvar.yaml**：初始活跃 8 → 3（su_mei/su_qing/lin_wanqing），其余 false
2. **initvar.yaml**：`群.今日主题` 空 → 初始化为具体主题（"不吵醒儿子的情况下让他射精"）→ 避免欲妈群规则 66 主题库注入（省~3k）
3. **[总控]NSFW getwi 三重条件**：时段匹配 && `_active(uid)` && `matchChatMessages([成员名,儿子名,群昵称]) && matchChatMessages(NSFW词, {start:-3})`——成员名与 NSFW 词必须同现，日常打卡/闲聊不拉 NSW
4. **D0 头部 30 行设计注释精简为 4 行**（省~1.2k）
5. **群主_基础信息去重**（7286→~5300）：二外貌/三身体压缩为摘要+指向调色盘，五地域删与三四重复项

### 结果
- EJS 模拟验证：[总控]NSFW 首页不拉任何 NSW 档案（2737 字符，原拉 8 份≈4万字符）
- 首页 token：8.2万+ → **~4.96万**（降 40%）：系统核心 2.1万 + 角色档案(郝佳期+3核心) 1.9万 + getwi 0.6万 + MVU 0.23万 + 玩家 0.07万
- 剩余硬底：44 条蓝灯常驻结构本身；想再降需砍常驻条目数（结构改造）

### 教训
- 群聊卡"开局即满员"是 token 爆炸暗雷：initvar 初始状态直接决定首页注入量
- 判断"活跃"要用变量标记（本轮活跃）而非关键词扫描——群聊卡关键词必然命中
- 用户实测反馈比静态分析重要：上轮优化对"运行中"有效但首页无效，因为首页走 initvar 初始值
