- **PowerShell 执行策略为 Restricted**：必须先 `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force`
  再 `& script.ps1`（同一条命令内，因为工具每次是独立进程）；从 Bash 调 powershell 会被安全策略拒绝
- **本环境 PowerShell 工具不捕获 stdout**：所有输出必须 `*> 日志文件` 再用 Read 读回

## Bash 环境故障诊断与修复（coreutils 全缺）

### 症状
- Bash 里 `ls` / `head` / `find` / `grep` / `cat` / `dirname` 全部 command not found
- 每条 bash 命令都附带两行 stderr：
  `shell-runtime-bash-env.sh: line 3: dirname: command not found` + `cd: null directory`
- `npm` 报 `/usr/bin/env: 'bash': No such file or directory`
- `cat >> file` 会**静默失败**（不追加任何内容，却返回 exit 0）——差点漏记一条记忆

### 根因（已确证）
- **不是 coreutils 真缺**：`<PortableGit>/versions/1.2.0/usr/bin` 里 358 个文件齐全（ls/cat/head/dirname/grep/find/bash 都在）
- **是 WorkBuddy 注入 bash 的 PATH 缺了 MSYS 的 `/usr/bin`**：
  bash 是 WorkBuddy 管理的 PortableGit（`~/.workbuddy/binaries/PortableGit/versions/1.2.0/bin/bash.exe`），
  而注入的 PATH = 用户 PATH + 系统 PATH + WorkBuddy 自己两项，**唯独没有 PortableGit 自己的 usr/bin**
- 连锁反应：`BASH_ENV` 指向的 `shell-runtime-bash-env.sh` 第 3 行就要用 `dirname` → 每次都报错（纯噪音，非致命）

### 时间线（判断是不是"更新导致的"）
- `PortableGit/versions/1.2.0` + `.extracted` mtime = **2026-08-31 03:25**（重新解压过）
- PortableGit 根目录 mtime = 2026-08-13；`usr/bin` mtime = 2026-08-05
- WorkBuddy safe-bin shim mtime = 2026-09-11
- 最后一次「bash 正常工作」的记录是 2026-08-07~08-12 的记忆日志
- **结论：是 WorkBuddy 侧更新（重新解压 PortableGit / 调整 PATH 注入）导致的回归，不是本机任何仓库更新造成的**；
  本次会话第一条命令就已经是坏的（先于我今天所有改动）

### 修复（用户选定：junction + 追加用户 PATH）
1. 建稳定目录 junction：`C:\Users\64806\.workbuddy\binaries\PortableGit\usr-bin` → `versions\1.2.0\usr\bin`
   （用 PowerShell `New-Item -ItemType Junction`，PS 5.1 原生支持，不用 cmd/mklink）
2. 把 junction 路径**追加**到**用户级 PATH**（`[Environment]::SetEnvironmentVariable('Path',...,'User')`）
   - 原值已备份：`_env_userpath_backup_20260914154717.txt`
   - 追加后用户 PATH 条目：pnpm/bin、WindowsApps、Roaming/npm、.lmstudio/bin、%USERPROFILE%/WindowsApps、**PortableGit/usr-bin**
3. 验证：junction 下 `ls`/`dirname`/`cat`/`find` 全部可用；`command -v dirname` 正确解析
4. **需重启 WorkBuddy 生效**（当前进程的环境快照不会更新）
5. 将来 PortableGit 升级只需重指 junction，PATH 不用动

### 副作用与备注
- Git 版 `find` / `sort` 等会优先于 Windows 同名命令（影响极小，可逆）
- WorkBuddy 注入路径的方式已确认会继承用户 PATH（注入的 PATH 里同时含用户级 pnpm/bin、.lmstudio/bin 与系统级 system32、Git/cmd）
- 这是 **WorkBuddy 的 bug**（bundled bash 没把自己的 usr/bin 放进 PATH），值得反馈官方

## 新卡立项：旮旯给木（src/旮旯给木）—— galgame 男主被屏幕外女玩家操控

### 用户已拍板的核心设计
1. **游戏底座 = Euphoria**（CLOCKUP）。理由：①密室+被迫游戏 = 「不能读档只能继续玩」的天然理由；②原设定就是男主被合欢看穿并要挟操控 = 被支配母题原生；③True End 自带元叙事反转

3. **三态循环**：在线态（言行锁死，唯一能动的是消耗反抗值拒绝选项）→ 离线态（她下线，自主但烧体力）→ 冻结态（体力归零，时间停滞等她上线）
4. **反抗值双源**：离线自主行动缓慢累积 + 在线被逼屈辱剧烈累积。耗尽 → 深度顺从（可恢复）
5. **上线完全不可预测**；**不可读档**（反抗后果永久留存，她只能继续玩）
6. **认知错位**：游戏内所有人认为是男主的个人行为；屏幕外的她认为「系统 BUG 了」
7. **感知规则（硬约束）**：男主能听到她的吐槽、能通过电脑摄像头看到她，但**不能互动**（她不知道他看得见）。严禁男主表达「这是游戏世界」「我们被操控」「和屏幕外的人对话/施加影响」；即使表现异常，外界她也忽略
8. **11 套支配者人设**（目的/三围/性癖/游玩喜好，开局启动其一，决定她点什么选项）：温柔 / 贪心 / 笑着 / 试胆 / 安静 / 无所谓 / 清账 / 拆散(NTR) / 心动(女性向) / 乱点(素人) / 走遍(完美主义)

### 终局设计（用户拍板）
- **触发**：她的目的达成 → 她关掉游戏 → 男主获得最后一次自由（体力回满，此时反抗值已无用，因为没有需要反抗的对象了）
- **结束**：体力归零 = 真正结束
- **能做的事 5 选 1**：去见一个人【最后一个人】/ 留下记录【写给不会读的人】/ 毁掉一切【砸不掉的东西】/ 什么也不做【凝视】/ 越界一次【BUG 不可能是爱】
- 设计内核：三个出口全焊死（不能说 / 不能影响她 / 世界要结束），剩下唯一的自由是「姿态」
- 隐藏机制：她关掉游戏后是否会再打开（再打开则从冻结苏醒，但"最后满槽"已用尽）

### 第二轮迭代（机制补全 + 变量审计）
- **四态**（不是三态）：新增**暂停态**——她按暂停键，世界静止、不耗体力，但你也出不来（最恐怖场景：她按了暂停然后忘了，你在一帧画面里待一整夜）
- **新增机制**：违和感轴（不解锁力量，只解锁信息层级）/ 离线痕迹 + 她的扫描判定 / 她在学习你（已知软肋清单，越反抗越难反抗）/ 关键节点不可反抗（剧情锁）/ 误点的残忍
- **她的愉悦线（第三层剥削）**：她玩游戏有三层目的 ①通关 ②满足人设目的 ③愉悦自己。兴奋度 0-100 且**界面上没有任何提示**（唯一来源是玩家自己盯）。硬作用：兴奋度高 → 选项激进 + **反抗成功率大幅提升（战术窗口，她爽的时候注意不到 BUG）**；高潮后有贤者时间（选项变温和但痕迹扫描加强）。11 人设各有一套自慰形式

### 第六轮：楼层交互循环 + 推演链（用户要求「好好思考」楼层截断）
- **核心问题**：SillyTavern 一层只能「AI 说完 → 用户输入一次」，但玩家需要在她点选项**之前**有介入机会
- **解法：一次「她的选择」拆成两个楼层**
  - **楼层 N（她出招）**：叙事 → 选项浮现（3-4 个，标注反抗等级与消耗）→ **她的倾向暗示**（光标停在哪，是线索不是答案）→ 你的处境（反抗值/体力/违和感）→ 停在「她正在选择…」

- **战术核心**：选项有 3-4 个但她只会选一个 → 玩家必须**预判她会选哪个**（依据是对她性癖/兴奋点的观察）→ **拒绝错了就白烧反抗值**。这是「观察她」与「反抗」的连接点

### 第二十三轮：修复「冻结」误显示的 CSS bug
- **用户反馈**：预览里一直显示「冻结」覆盖层
