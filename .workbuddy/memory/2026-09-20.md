### 七、条目层 ↔ 正文层的接口（用户提出）

### 一、EJS 报错的真凶：不是 9-20 改的，是 9-18 生成器漏了一个括号
- 现象：用户报「现在 ejs 报错」。全库扫 EJS 标签配对只揪出 `时间线/人物出现索引.yaml`（开 0 / 闭 1），但那不是报错源。
- 真凶：`scripts/verify-ejs2.cjs` 报 **13 个文件 `Unexpected token 'else'`** ——
  `角色/底座_nanpa2/<名>/剧情线.yaml` 的分支链写成了 `<%_ else if (...) { _%>`（**少了闭合上一段 `if (...) {` 的 `}`**）。
  真 EJS 会把所有代码块**拼成一个函数体**，`if (x) {` 后面直接跟 `else if` = 非法 JS → **模板编译期就炸**。
- 范围：15 份剧情线里 13 份中招（只有 17:03 的鸣泽唯、17:12 的加藤美纪是对的），时间戳 9-18 17:18~17:22 ——
  **是当时那个生成脚本的 bug，不是内容写错**。共 26 处。
- 修：`scripts/fix-ejs-else-brace.cjs`（只匹配块首裸 else，不误伤已有的 `} else if`）。修完 verify-ejs2 **192 个代码块全通过**。
- ★ **教训**：verify-ejs2 早就能抓到这个错，但当时没跑。**生成器批量产出的 EJS，产出后必须立刻过一遍语法器。**

### 三、★★ 预算器（verify-prompt-budget.mjs）估算 bug —— 第三类「量错方向」
- 旧逻辑 `est = stateGated ? chars : chars/branches`：**门控里一旦有 `@@if`，条目内 EJS 就完全不折算**。
  而 `她_XX_阶段` 是 **@@if 门控 + 文件内 5 档 if 链双重裁剪** → 整份源码被计入。
  报「违规 7 项」：`她_温砚_阶段 7934`（**实际渲染 1657**）等 6 条 + `T1 状态层 18590 > 15500`。
- 第二处：**单条上限判的是 `chars`（文件全量）**，而规则原文写的是「**渲染后** ≤ 5,000」。
- 修：**用真 ejs 真渲染一遍再量**（`getvar` 一律返回自己的 `defaults` = 「按初值渲染一次」，可复现；渲染不了才退回旧公式）；单条上限改用 `est` 判。

- ★ **观念**：**量错方向比不量更危险** —— 它会让人去删本来就不会进 prompt 的字。判据写「渲染后」就必须真渲染。（已进 MEMORY §三）
