## ★★★ 坐实：Zod 卡里「数组追加」根本走不通 → 四个数组整体重构为字符串

用户报错（第二次，**带上 `/-` 照样报**）：

```
{"op":"add","path":"/群/周竞赛历史/-","value":{…}}
→ SCHEMA违规:无法向路径“["群"]["周竞赛历史"]”处不可扩展的数组写入元素
```

### 三层根因（源码坐实，不是猜）

1. **MVU 核心把命令同时发给 zod 处理器，又自己照旧执行**：
   `await eventEmit(COMMAND_PARSED + '_for_zod', …)` 之后核心仍 `for` 循环执行；
   zod 处理器（`mvu_zod.js`）把**成功处理**的命令用 `_.pullAt` 从数组里摘走 —— 摘掉的核心才不会再碰。
2. ★ **zod 命令语法里 `add` ＝ 数字加减**（`case'add': if('number'!==typeof 旧值) return null`），
   **追加数组要用 `insert`**（等价 `_.assign`）。所以标准 JSON Patch 的 `{"op":"add"}` 打到数组 →
   zod 判「目标不是数字」→ **`return null` 不消费** → 命令落到核心。
3. 核心判据 `'array'===type && (!1===extensible || undefined===extensible)` → 必抛。
   而 **Zod 卡拿不到 extensible**：`mvu_zod.js` 里 `extensible` **0 次**、
   JS-Slash-Runner 的 `registerVariableSchema` 也 **0 次**；
   `$__META_EXTENSIBLE__$` 标记只对**非 zod 的 JSON 结构卡**有效（生产 zod 卡明确不用 `$meta`）。

**⇒ `/-` 只管「插到末尾」，不管「这个数组允不允许插」。我上一轮只教 `/-`，判断错了。**

★ **判据速记**：报错前缀是 `[MVU]` 而不是 `[MVU zod]` ⇒ 命令没被 zod 层消费，落到了带校验的核心。

### 踩到的技术坑（CRLF 今天第 4 次咬人）

- 多行替换在 **CRLF** 文件上静默失配 → 一律 `a.split('\n').join(eol)` 归一化，或按行号 `splice`
- **bash 里给 `node -e` 传含引号／反引号的中文串会被吃掉**（今天第 3 次因此返工）→ 改写成 `.mjs` 脚本文件
- 锚点替换时把上一函数的收尾 `}` 一起替换掉 → 多出一个 `}`；
  **教训：多行锚点替换后必须 `node --check` 抽出的 script**
- 自己拼 HTML 字符串时 `"…+x+'…'` 引号配错 → 同样靠 `node --check` 抓出来（第 200 行）

## 条目前缀审计（用户：「所有的 mvu 世界书条目前缀也都正确了吧」）

**规范出处**：`.skills/tavern-cards/references/conventions.md`「条目名称前缀 / 双 AI 发送路由」

| 前缀 | 发送目标 |
|---|---|
| `[mvu_plot]` | **只**发给剧情 AI |
| `[mvu_update]` | **只**发给变量更新 AI |
| 无前缀 | **发给两个 AI** |
| `[InitVar]` / `[initvar]` | MVU 按 `comment.toLowerCase().includes('[initvar]')` 检索 → **大小写不敏感** ✓ |

**MVU 的过滤实现（bundle 原文）**，额外模型模式下：
```js
_.remove(t, e => { const t=ut.test(e.comment), n=pt.test(e.comment);
  return (t||n) && r.add(e.world), o.is_extra_analysis ? (n && !t) : (!n && t) })
```
→ **`[mvu_plot]` 条目会被从变量模型的上下文里删掉**；无前缀条目**保留**。

### 审计结论

| 项 | 判定 |
|---|---|
| `[mvu_plot]` ×19 | ✅ 正确 |
| `[mvu_update]` ×2（变量更新规则／变量输出格式） | ✅ 正确 |
| `[initvar]初始(别开)(勿动)` | ✅ 正确（MVU 大小写不敏感） |
| `[文风]` ×6（关灯，不计） | ✅ 无关紧要 |

### 建议改法（改 packer，**不动条目键名**）

在 `pack_yumq.mjs` 的 `buildEntries()` 里给 `comment` 加前缀，**state／manifest／文件名全部不改**，

- 角色档案（84）＋ `玩家档案` → `comment = '[mvu_plot]' + name`
- 5 个自造前缀条目 → `'[mvu_plot]' + name`（如 `[mvu_plot][总控]剧情与事件`）
- `MVU变量列表` → `'[mvu_update]' + name`
- 已带规范前缀的 19＋2＋1 条 → 原样

## 格斗设计（对照 skills 后定稿）—— 「三幕式格斗单元」

用户要求「还有格斗，是怎么个战斗方式，好好对照skills来看」→ 先读了三份规范再设计：

### 从规范里拿到的硬约束

- **E3 判定链**：`D = P − R + E` → `S = clamp(50+D, 5, 95)` → `V = LCG(seed)×100` → `V < S` 成功。
  档位**必须由 D 与成败联合决定**（禁止先按差值定档再按骰子定成败）。难度用**乘法**不用加法。
- **E1 时间推进器**：要有「单位上限」防拖沓 → 借来当**幕上限**
- **标定必须解方程不能盲搜**：先算 P 在三个时点的真实值 → 目标成功率 → `R = P − D` → 联立反解。
  ★ 对手强度与关系修正**必须按难度各自缩放**，不能对三档一视同仁
- **判定通道**：引擎算、**AI 只读不重算**。主通道 `createChatMessages([{role:'user',message:摘要}])`
  （字段是 `message` 不是 `content`，**绝不 await** —— await 是转圈卡死的真凶）；
  副通道 `@@generate_before` ＋ EJS 读 `局面.判定结果`
- ★★ **EJS 沙箱里只能用 `var`** —— `const`/`let` 报 `Unexpected token`，**整个条目渲染失败**

### 定稿设计

**不做回合制 RPG，做原作式「格斗单元」** —— 原作的战斗从来不是血条对拼，是有规则的比赛。

| 幕 | 内容 | 判定 |
|---|---|---|
| 起手 | 挑战状／被迫应战／摆架势 | 无 |
| 交锋 | 互有攻守，中途必出一次意外 | 判定一（谁占上风） |
| 决胜 | 必杀技对轰 | 判定二（谁赢） |

**幕上限 3，超过强制出结果。**

`P_你` = 流派等级 ＋ 形态修正 ＋ 湿度惩罚 ＋ 气势｜`R_对面` = 对手基准 × 难度乘数 ＋ 个体修正｜
`E_环境` = 天气 ＋ 在场人数 ＋ 地形

★ **15 种竞技项目改的是 `R` 的算法** —— 这才是「规则对你不利」的落地（不是换个名字重打一遍）：

## ★★★ EJS 报错真因：`<%-` 不能包语句（不是 const/var 的问题）

用户报错：`Unexpected token 'var' in worldinfo/欲妈群/8-[mvu_plot]D20对抗判定系统`

### 我上一轮修错方向了
看到 `const` 报错就把全库 `const`→`var` —— **问题不在关键字**（同级生2 也用 `var`）。
真正的错是**标签用错**：我用 `<%-` 包了**语句**（var 声明）。

### ST 的 EJS 三种标签（本次实测确认）
| 标签 | 用途 | 例 |
|---|---|---|
| `<%` … `%>` | **语句**（可含 var） | `<% var _x = getvar('…'); %>` |
| `<%-` … `%>` | **输出表达式**（不转义） | `<%- await getwi('[总控]人物') %>` |
| `<%=` … `%>` | **输出表达式**（转义） | `<%= _出 %>` |

⇒ **没有 `-%>`**（我和 D0、同级生2 都不用）。D20 原来是 `<%-` 包语句 → 非法 ✓

### 而且我把 D0 改坏了（比原错误更严重）
我用**全局替换**把全库 `<%-` → `<%` →
**D0 系统控制器的 40 处 `<%-` 全是表达式**（`<%- _newDay %>`、`<%- _pSanity %>`…）
→ 改成 `<%` 后**这些内容不再输出** ⚠️
→ **已从 `_backup_欲妈群_20260921/世界书/` 整体还原 D0** ✓
→ 复查：所有含 EJS 的文件与备份一致 ✓

### D20 现在的正确写法（照 旮旯给木-同级生2 的 判定引擎.yaml）
`@@generate_before` ＋ `<%` 语句块 ＋ `<%= _出 %>`
→ 编译 + 渲染实测通过 ✓

### 顺带修：「点交给她判没反应」
根因是 **EJS 报错让整条消息（含面板）的渲染中断** ✓ 修好 EJS 后应恢复。
另外把 `S.结果` 从**选项区的 if 分支**里移到**无条件显示**（原来她还没摆选项时，操作结果不显示）✓

### 验收
D20 EJS 编译+渲染 ✓｜D0 已还原（`<%-` 40 处回来）✓｜全库与备份一致 ✓
面板 JS 通过｜打包 121 条｜push **873687d**

### ★ 教训（三条）
1. **改 EJS 标签前先看同级生2 的写法** —— 我用 `<%-` 包语句就是没照抄；
