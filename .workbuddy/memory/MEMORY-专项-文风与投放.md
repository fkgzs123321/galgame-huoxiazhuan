## 八、文风库（`contents-creation/`）

- `craft-01~06 技法层`（总是）／`common-01 用词层`／`common-02 素材层`／`style-01~06 文风层`。`character/by-style/` 六套×三份（基础信息/调色盘/多阶段）。**`presentation-styles.md` 是总索引。**
- ★★ **技法层每一套文风都必须使用**（表述用**强制**）。★ **style 只决定「什么味道」，craft 决定「合不合格」**。
- ★ 规范条文用**说明文体**；只有实样按文风本身写。★ **表现尺度**放大的是**幅度/范围/数量/持续时间**，不是形容词强度。
- ★ **三层落笔法**：形态 + 受力质地 + 第三层（被挤到哪/温度气味/透出多少/攥紧挤出多少/牵动哪处），**缺层不成立**。
- ★ **温湿词不许互换**：捂（遮盖）/焖（封闭积热）/沤（长期浸泡变质）/闷（热气困住）/焐（外热源）/腻（黏滑）。
- ★ **乳/屄/臀不配雅词**；雅词每段至多一处且必须与秽词同框。★ **禁则要能被机器执行，有禁就有替**。
- ★ **`淫视` = 「眼睛」**：主语必须是器官/部位不是「她」；其余五套是「味道」。★ **素材索引三层**：通用技法（强制）/通用设定（强制）/题材特化（按需）。
- ⚠️ **改卡 = 重写不是润色**：抽事实 → 丢原文 → 从零按新文风写。⚠️ **「只写衣物和身形轮廓就收尾」= 白描**，头号禁忌。
- ★ **配套预设**：要「能缝合进预设的**纯文字**」（基础规范层／文风层五选一／机制重申层按该卡 T0 提炼 3~5 条），**每卡单独一份**；成组开关 ＝ `{{setvar::key::内容}}`＋`{{getvar::key}}`。破限**不搬别人的文本**。
- ★★ **文风转写不许丢特色 / 不许串味** —— 转写前先抄该角色的特色锚点（职业·癖好·口头禅·群昵称·后门·**专属变量**），转写后逐条对照复查；判据：**遮住名字能不能认出是哪一位**。
- ★★ **角色条目不用数据库格式** —— 结构照 `character/basic-info.md`，**写法必须同时打开 `by-style/<套>/基础信息.md`**；只读前者＝写出来必是白描。外貌：只写偏离默认的特征＋必写**体型落点**，**禁**万能美人词、禁每个五官写一遍。★★ **四禁句式**：她觉得／她不知道／她经常／她喜欢。
- ★★ **条目层 ↔ 正文层**：条目层 ＝静态资料「她是谁」，给**锚点与边界**；正文层 ＝动态规范「怎么写」，硬约束**合不合格**。
  ★ **体型落点 ≠ 识别特征**。★ 三面性**语料**（5~10 句纯对话，**不写 ~❤**）↔ `craft-04`；调色盘**衍生** ↔ `craft-03`。
  ⚠️⚠️ **规范明写「衍生由用户自己写，AI 引导用户创作」—— AI 不该代写衍生，只给草案。**
- ⚠️ **同步纪律**：`.skills/tavern-cards` ↔ `_tc_repo/tavern-cards` **是同一份**，改一边必须同步（md5 可验）。例外：`references/ejs/guide.md` 两边不同但**不是我改的**，**待确认哪边新**。
- ★★ **开场白五条硬判据**（`contents-creation/first-message.md` ＋ `SKILL.md` 第 8 步）：
  ① **视点**＝玩家角色，只写他听得见／闻得见／看得见／身体感觉得到的；
  ② **首轮不发说明书**；③ 第一段交代处境；④ ★ **结尾必须有开场点**；⑤ N 个开场白走 N 条不同感知通道＋重样检测。
  ⚠️ 多备选开场白若**只差时间**，那是「同一段剧情的 N 个时刻」不是 N 个开局。

## 十、tavern-cards 投放 + token 规范

- **`SKILL.md` 第 12-17 行是总纲** —— 三条策略（**不是「把内容写短」**）：**结构化表达 ＋ MVU 变量 ＋ 关键词匹配/EJS**。
- ⚠️ **order 手工排**（引擎 1-99／底座 200+；T0 1-19／T1 20-49／T2 50-99），**不要交给 `configure`**（按 tens-group 重排 310 处）。**手填 strategy/position 已齐时直接 `pack` 就能成功。**
  ★ **但全新项目 `configure` 是必要的**，且它有三个必踩的坑：
  ① 角色类型 `basic`/`personality` 的 `required:true` 要求**两者条目数一致** → 玩家档案那类「只补了 basic 没补 personality」会直接报错。
  ② 派生成 conditional 的条目**必须显式给 `scope`**（`specific`/`catalog`），否则报 `has conditional threshold (N) but no scope set`。
  ③ 派生为 selective 的条目**必须给非空 `keywords`**，否则报 `Selective entry has no keywords`。
- ⚠️ **D1+ 深度绝对禁止**（只能 depth 0）
- `strategy` 由 `strategyThresholds` 推导：`Infinity`=常驻／`0`=关键词／`null`=禁用／`>0`=按同 part 计数
- `scope: catalog` → 始终 constant 且不参与计数；**EJS 条目在同 part 最多计为 1**
- **角色条目只有 4 个 part**：`basic`/`personality`/`tri_faceted`/`other`（阈值 5/2/2/2）
- **一个条目只能有一个装饰器**（有 `@@private` 要加 `@@if` → 换手写块作用域）
- ⚠️ **`getwi` 读世界书条文不受 `enabled` 影响** → 「条目关闭 + 被 getwi 引用」= **正确的按需加载**
- **`rules-check.md` 三条硬约束**：① ★ **破折号（——）全文一律违规**（**含台词里表示拉长音的那种**；craft-04 允许「破折号或半截词」→ 用半截词）② ★ **跨条目引用「详见 X」违规，每条独立可读** ③ ★ **元叙事一律删**。⚠️ **YAML 注释也会进 prompt** —— `#` 说明头一律删。
  ★ **反引号（Markdown 行内代码）虽然不在禁则里，但审查时会被当 Markdown → 条目内容里一律写 `<user>` 不要包反引号。**
- **显示层美化全在「正则 + 界面」**（判据：正则只做显示层、只定位、不解析数据）。`regex_scripts` 是**顶层 record**（key=脚本名）；`replaceString` 与 `replace_file` **互斥**。
- **engine 两个坑**：① `state.ts` 的 `group.use_scoring` 写完 null 后 **schema 读不回来** → 带 `group` 的条目永久失败 → **不用 `group`**，互斥改由 EJS `@@if` 保证 ② `extensions.tavern_helper.scripts.*.id` 是 **required string**，`delete` 报错 → 跨卡复制脚本**保留原 id**。
