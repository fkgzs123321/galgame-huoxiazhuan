## 二、⚠️ 最高优先：协作六条（违一条就返工）

1. **不自己裁决** —— 遇设定冲突或规划没写：先查规划（design-spec / 创作规划.yaml / 机制层规范）。
   规划也没有 → **列出来让用户决定，并给出每个方案的具体影响**（改哪些文件、破坏哪些已有内容）。
2. **判「原作没有」之前必须搜全** —— 中文百科 + 英文维基 + 日文攻略 + 论坛帖都要过；**一个来源要翻它的分页**（`_2`~`_N`）。
   → **原卡被判错时先假设是自己搜漏了**。（反例三次：88 海岸 / 美里周三休假 / 杉本樱子「只有一句话」）
3. **删掉一个自创设定后，不要顺手编一个新的顶上**（那还是自创）。
4. ★★ **「怎么写」不用我写，我只做结构** —— 用户给整包参考资料时（如 `2026.08.12`），里面**已经规范好了怎么写**。
   我的任务是**理解结构**（分层 / 挂载 / 索引 / 接口 / 取用规矩 / 范围边界），**不是按自己理解再写一遍**。
   ✗ 把「资料库怎么写」写成一节规范 ✗ 把原文手法段按自己理解重写 ✗ 自己写样本演示「该怎么写」→ ✓ **照搬，一个字不改**。
5. ★★ **模板必须自包含 · 不许偷懒** —— `by-style/` 的人物模板是**以后写卡的参照物**，拿着那一张表就能填。
   ✗「同上」 ✗「〔某某模板〕」这种别处才有的名字 ✗ 只给占位符 → ✓ 表单式 `槽位 ｜ 这格填什么 ｜ 照着这个写（原句）` ＋ 填好的范例。
6. ★★★ **强制性要求必须写进「执行流程」，不能只写进「资料清单」** —— 素材索引只挂在 `references/` 清单里时，写卡根本不打开它。

## 三、⚠️ 审计铁律（变量侧 4 次 / 条目侧 3 次 / 校验器 3 次都栽在这）

**脚本只能「列线索」，判定必须人工；脚本的判定性指标一律不可信。**
- 反例：「20 次公式参与」看着健康，实际 = 1 个真读点 + 19 份手工复制的同一段逻辑。
- 反例：审计器用 `enabled` 判常驻/按需，但 ST 投放看 `strategy` → 全盘误报。
- 反例：**词表不全 = 守卫是假的** —— 先报 6/23，补齐词后真相 13/23；后又漏「西御寺」。
- 反例：**量错方向比不量更危险** —— 预算器拿「文件字符数」判「单条渲染后 ≤5000」，把温砚阶段报成 7934（实际渲染 1657），
  它会让人去删本来就不会进 prompt 的字。**判据写「渲染后」，就必须真渲染一遍再量。**

**人工过审判据**：每个数值问三句 —— ① 玩家能看见吗 ② 玩家能用它做决策吗 ③ 会改变叙事走向吗；三个都否 → 删。
外加反问：**这数值是在帮玩家玩，还是在替 AI 记账？**

## 五、机制层判据 + 判定引擎 + 她的手段

**三判据（逐级收紧）**：① 换底座还成立吗 ② **含不含「具体内容」**（含 → 要素）③ 是否为别的功能提供能力。
⚠️ 判据 2 最易错：**怀孕系统不是机制** —— 机制层只提供「带周期的可累加状态」，机制层里不该出现「怀孕」二字。

**机制层 = 引擎能力 + 契约声明（表）**：引擎能力（EJS 函数，不含内容）／契约（强制底座填四张表：时间怎么切・追踪哪些状态・有哪些判定动作・NSFW 阶段表）／**底座 = 填表 + 提供内容**。
**skills 本身就是这个分层的实例**：引擎 = `scripts/*.mjs`；契约 = `references/requirements/` + `type/state.ts`；要素填法 = `contents-creation/*.md`；表 = `创作规划.yaml`。
→ **原卡病根：绕过推导（手工填 index.yaml）+ 没有校验**。

**判定引擎（E3 · 机制层唯一允许有数字的地方）**：`D = P - R + E`（`P` = Σ(状态值×权重)/Σ权重，权重归一化；`R` = 基准 × 场景难度乘数 + 目标个体修正）
→ `S = clamp(50 + D, 5, 95)` → `V = LCG(seed) × 100`，`V < S` 成功；**档位由 D 与成败【联合】决定**（大成功×1.5 / 成功×1.0 / 勉强×0.6 / 大失败×2.0）。
**原实现两个 bug**：① 分档与成败不同源 → 会同时产出「大成功」与「失败」② 关系阶段修正恒为 0。
**要保留**：LCG（禁 `Math.random`）／权重归一化／难度用**乘法**。**已落地** `机制/判定引擎.txt`（`judge()`，不含世界观/角色/地点名），`scripts/test-judge.mjs` **30/30**。
★ **判定放在玩家按拒绝按钮的那一刻**（AI 不能执行 JS；状态栏是前端，能读写变量），条目只负责把结果交给 AI。

### E6 · 她的手段（每套人设都不一样 · 属引擎层，不随底座换）
**手段本身就是她们性格的一部分**。两维度决定：① 遇到障碍怎么办 ② 遇到无聊怎么办。

| 人设 | 障碍 | 无聊 | 开挂 |
|---|---|---|---|
| 温砚 gentle | 反复试、查攻略、每步都算 | **也认真看** | 不会 |
| 丰娆 greedy | 换一条线 | **快进** | 偶尔 |
| 舒晏 smirking | **故意让它更难** | **反复看同一段** | 不会 |
| 唐响 daredevil | 撞上去 | 乱点跳过 | 会 |
| 沈眠 quiet | **阻止救援** | 静静看 | 不会 |
| 莫漾 indifferent | **外挂跳过** | **挂机** | 会，最懒的 |
| 纪清 completionist | 算、找漏洞、改 | 也看 | 会，为了补漏 |
| 郁灼 | 只挑最刺激的 | 跳过不能快进的 | — |

**后果全部落在 `<user>` 身上**；**开挂是最重的那一种手段**（改好感/时间/关系阶段/flag）。
> **她做的每件事都不需要理由 —— 她只是在玩。而每一件都变成他的一天。**
⚠️ 底座相关的「手段表现」不进引擎层 —— 同级生2 的做法是底座写 `底座_nanpa2/人设补丁.yaml`。

## 七、三个底座（只记「非显然」的部分）

**★ 拒绝机制（引擎级、全底座共用）**：**选项不是给玩家选的** —— 选项池是她摆出来的本关完成方式，**她**从中挑一个；
玩家只有两个动作：**眼睁睁看着**／**拒绝某个选项**（拦住她正要点的那个）。
三段不确定（缺一即崩）：① 按对地方 ② **过骰**（微 90／中 60／强 30／极 10 × 兴奋度 × 熟练度，失败照扣）③ 代价确定、结果不确定。
代价表 微 3~5／中 10~15／强 25~35／极 50+／锁 无。隐性成本：每次反抗被她察觉为故障 → 进 `已知软肋` → 清单越长她越绕开。
**三条硬规则**：① 层1 的规则只约束 `<user>`，绝不约束她 ② 层1 只推 `世界.关卡进度`，绝不碰 `她.目的进度` ③ 她的难度必须来自时间，不能来自数值。

## 九、MVU + EJS 铁律

**变量作用域与门控兜底（三通道 + 一条兜底）** —— 表单/前端写 `stat_data.X` 后，世界书 `@@if getvar(...)` 可能读不到 → 永远走 defaults：
① chat 级 `updateVariablesWith(fn, { type: 'chat' })` ② floor 级 `{ type: 'message', message_id }` ③ slash 兜底 `triggerSlash('/setvar ...')`
④ EJS 条件写成 `matchChatMessages(['TAG:值'], { start: 0 }) || (!matchChatMessages(['TAG:'], { start: 0 }) && getvar(...) === '值')`
   —— **右项必须带 `!matchChatMessages(['TAG:'])`**，否则变量通道失效时同时命中两条；`start` 默认 **-2**（只扫最后两楼），扫全历史必须显式 `{ start: 0 }`。

**initvar_override**：`开场白/N.txt` ↔ `开场白/initvar/N.yaml` 必须**同号**；key 是 `first_messages` 原始值，JSON Pointer 里 `/` → `~1`；
父字段不存在要先 `{"op":"add","path":"/initvar_overrides","value":{}}`；patch 的 `replace` 打在「值是文件路径」的字段会被当成**文件重命名** → 用 `remove` + `add`。
**ST 端映射**：`first_messages[0]` → `first_mes`，`first_messages[1..]` → `alternate_greetings[0..]`。

**卡面校验**：PNG 的 `chara` chunk 是 **base64 编码的 JSON**（`tEXt`，data = `chara\0<base64>`）；`character_book` 在 `card.data.character_book`；
`data.extensions.regex_scripts` 是**数组**（按 `scriptName` 找）。★ **打包后要真解 PNG 复核条目，不能只看源文件。**
