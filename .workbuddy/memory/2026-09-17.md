### ★ 判据修正：分界线在**「谁的动作」**，不在「面板」
我上一轮把结论写成「面板是监控屏、只有三按钮」—— **那是走极端了**。

| 谁的一侧 | 面板能否操作 | 例 |
|---|---|---|
| **操作类**（他在动 / 她在操作） | ✅ **给按钮** | 装备 / 使用 / 强化 / 加点 / 接任务 / 打人 |
| **状态类**（她的状态是**结果**不是操作） | ❌ **只显示** | 兴奋度 / 周期 / 倾向 / 目的进度 |
| **玩家自己的动作** | ✅ 出招层三个 | 看着 / 拒绝 / 自定义 |

★ **一句更简的判据**：问「**这一下是他在动，还是她在变？**」
★ **语义**：玩家在面板上的操作，**等同于「她在操作」** —— 他是在替她按键。

### ★★ 加了「面板配置」契约 —— 通用面板的**开关层**
用户说「**这个是通用面板，也要考虑其他游戏**」，所以要有一层**声明**：
```yaml
面板配置:
  开放:
    物品: [装备, 使用, 丢弃, 强化]
    技能: [请教, 强化, 突破]
    任务: [接取, 推进, 放弃]
    穿着: [换上, 脱下]
    战斗: [挑对手, 看上一场]
    交易: [买入, 卖出]
  暂不开放:
    兴奋度: '设定原文：界面上没有任何提示'
    周期: '周期是剧情结果'
```
★ **换游戏时面板代码一字不改，只改这一节。**
这是「通用面板」的正确形态：**面板给能力，契约给开关。**

### 强化为什么是**同一个形状**
装备强化与技能强化都是「**拿材料叠层 + 层数封顶 + 每层递增**」，
只是作用对象不同（一个加装备加成，一个加判定强度）。
→ 所以它该在**引擎层**（E8 已有 `强化()`），契约只填参数。
**这是「一个能力两处用」的例子** —— 也回答了之前那个问题「为什么通用层不该写具体内容」。

## 追加（同日 08:54-09:30 后）· 技能树修复（打结 / 重叠 / 点了没反应）

**用户**：「你这技能树都打结了，重叠在一起，也太丑了，而且点了里面的技能也没有任何反应」

### 三个都是真 bug
| 症状 | 根因 |
|---|---|
| **打结** | 绝招**挂了多个父**（`依赖.forEach` 里对每个依赖都 `push`）→ **布局只放一次、连线却画多次**，线全缠在一起 |
| **重叠** | 布局算法用「取子树中间行」的递归，多父 + 顺序不定 → 同一列内撞位 |
| **点了没反应** | `.yx-tn` 的点击绑定被后来几轮补丁**覆盖掉了** |

### 修法
1. **★ 树不是图**：绝招**只挂一个父**（选依赖里名字最长的那个 —— 最长 = 最具体）
   > 一句话：**挂多父就会「布局一次、连线多次」**，必然打结。
2. **布局改成「按深度分列 + 列内纵向排」**：
   - 递归算每个节点的深度 → 按深度归列 → **列内按「父在上一列的位置」再按名字排序**
   - ★ 这样**同一列内不会撞**（每行一个），且连线交叉最少
3. **连线改用贝塞尔曲线**（`C mx y1, mx y2`）+ **用节点自己的品级色**、宽度 1.3、透明度 .45
4. **补回点击绑定**（并 `stopPropagation`，免得连带触发展开）

### ★ 还顺手修了两个「太满」的问题
- **门派名重复**：「八卦门」+「派」=「八卦门派」→ 门派表里的名字**已经带门/教/派**，不再拼字
- **只画当前门派那一支**：原来所有门派的武功都画 → 一屏全是节点。
  改成只画**当前门派 + 它的绝招**（逍遥派只在无门派时画）

#### ★★★ 判定系统：三条必须吸收
**① 修正相对化**（解决"开放数值"）
```
属性修正 = clamp( round( (相关属性 − 自身均值) / 自身均值 × 30 ), −15, +20 )
```

→ **我们的判定引擎仍是绝对量纲**（`Σ(状态×权重)/Σ权重`）→ **能力值涨高就失真**。

**② ★★★ 对战必须加「绝对强度差」**（最关键的一条）
> 「纯相对修正在『人 vs 任务』成立，但『人 vs 人』会**丢掉绝对强弱** ——
>  **全 2 的杂鱼和全 500 的神，属性修正都 ≈ 0**」
```
对战 = 绝对强度差 + 相对修正差
强度档：T0 杂鱼 0 → T9 源初 90，每档 ±6（百分骰）/ ±1（d20），封顶 ±40 / ±6
```
→ **我们的判定是纯相对的 → 人 vs 人 会失真。必须补。**

**③ 自然 20 / 自然 1 + 优势劣势**
- 自然 20 = 大成功（**无视 DC** + 后果翻倍）；自然 1 = 大失败（**无视 MOD** + 反噬）

**④ 求爱好感门槛**（我们的核心场景）

## 追加（同日 13:52-20:20 后）· ★★★★★ 真机跑出来的第一个 bug（Zod 容错）+ 第九道关

```
（开局 1 到 10 全一样）
```

### ★ 根因：**`prefault` 不挡类型错误，全块被丢**
`gen-schema.cjs` 里字符串字段的生成逻辑：
```js
if (typeof 值 === 'string') return `${键}: z.string().prefault('${值}')`
```
- **`prefault(x)` 只处理 `undefined`**，输入类型不对时**校验直接失败**
- 失败的不是「一个字段」——**是整个变量更新块被丢弃**（MVU 的行为）
- 所以 AI 某层把 `熟练度` 写成 `3`，那一层的**全部变量更新都没了**

**★ 而脚本自己的注释写着**：
> 数值一律 `z.coerce.number()` + `_.clamp`：**越界夹紧，而不是整块更新被丢弃**

→ **数值有容错，字符串没有。这是设计一致性的缺口。**

### 修法：字符串一律 `z.string().catch(默认)`
```
世界.底座   catch('yingxiong')      她.熟练度   catch('新手')
世界.阶段   catch('初入江湖')        主角.状态   catch('在线')
她.人设     catch('')               关系阶段   catch('陌生')
她.情绪     catch('好奇')
```
**`catch` 连类型错误一起兜住** → AI 写坏 `熟练度` 时**只这一个字段落回「新手」，其余字段照常保存**。

```
「把这一路压成…」  ❌ 价值低 —— 只是把已发生的事摘要一遍，正文里本来就写了；
                     而且它**不进变量**，读完就散在楼层里，下次还得再花一次生成
```
★ 通病两条：**① 文案是谜语**（"压成他记得的事"猜不出是干嘛的）
              **② 两个都不改变任何状态**（纯"看一段文字"）

### 改法
```

② 「把这一路压成他记得的事」 → **换成「你背着我做过什么」**（data-ai="漏看"）

     她开挂改过的数值或关系 / 趁画面切走时替你点的 / 把某条路悄悄绕开的 / 把某件事从记忆里抹掉的
   每条一行、≤八条、只写真发生过的（从 她.已用手段、世界的裂缝、前面楼层判断），一条都没有就写「暂时没有」
   ★ 为什么这个值：**它既影响决策、又能查账，而且只有这个通道能拿到**
③ 卡片标题改成「问她（各花一次生成，不动剧情）」，下面补一行说明每个按钮答什么
④ 委托里加 data-ai="漏看" 分支（求回顾 保留着，不删，以防别处引用）
```
