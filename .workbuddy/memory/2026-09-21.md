## D0 的 EJS 报错真因查清（2026-09-21 第十九轮）★★ 方法沉淀

**结论：D0 本身没问题，报错的是我的脚手架。**

**排查过程（三步定因）**：
1. 试验1 非 async 渲染 → ❌ `missing ) after argument list`
2. 试验2 `{async:true}` + **我手写的 `(function(){ })()` 包裹** → ❌ 同样报错（同步 IIFE 里不能出现 await）
3. 试验3 **只把 `<%- await getwi(...) %>` 那两行去掉** → ✅ 立刻通过 → **罪魁就是 await**

**根因**：`guide.md:157` 明令「**`getwi()` 必须加 `await`**」——这是 ST-Prompt-Template 的异步 EJS 语法；而**纯 ejs 的模板函数是同步的**，`await` 放进去必然编译失败（不管加不加 async 选项、只要外层再套一层同步函数就炸）。**项目自带的 `src/旮旯给木-同级生2/scripts/render-entry.cjs` 也不含 getwi**，所以它渲染不了 D0。

**正确脚手架（已验证）**：
```js
let 源 = fs.readFileSync(f,'utf8').split('
').filter(l=>!/^@@/.test(l)).join('
');
const out = await ejs.render(源, { getvar, getwi: async()=>'…' }, { async: true });
```
★ 三点：① **不要自己包 IIFE**（交给 EJS 的 async 包装，自己包会把 output 丢掉或直接编译不过）② 必须 `{async:true}` 且 **await 结果** ③ 先过滤掉 `@@` 装饰器行。
