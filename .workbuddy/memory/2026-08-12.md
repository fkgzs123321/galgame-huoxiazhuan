## 挂载根因终破：srcdoc 转义双重转义 bug（浏览器实测定位，已修复验证）

### 现象
loading 正常显示（"完整应用 943KB"），iframe 注入成功、静态 HTML 渲染（#hgw-app 存在），但应用 JS 完全不执行（App/HGW 命名空间不存在），无任何 console 错误。

### 定位过程（真实浏览器 CDP 实测，非猜测）
1. 用系统 Chrome headless + CDP（Runtime.consoleAPICalled/exceptionThrown/executionContextCreated）连测试页（模拟 ST 主页面 + stub 酒馆 API + 同层前端.js）
2. 证据链：iframe readyState=complete、scripts=1、script 内容完整（807KB）→ 但零执行、零错误
3. 检查 HGW_APP_HTML 运行时值：`</script>` 0 次，`<\/script>`（字面反斜杠）1 次 —— 双重转义确认
4. **根因**：build_shell.py/embed_html.py 先 python 层 `replace('</script>', '<\\/script>')` 再 `json.dumps` → JSON 把反斜杠再转义成 `\\` → JS 字符串值 = `<\/script>`（带字面反斜杠）→ srcdoc 里 `<script>` 永不闭合 → 浏览器忽略整块脚本 → JS 全不执行
5. 修复：在 json.dumps 输出层面替换 `</script>` → `<\/script>`（JSON 的 `\/` 是合法转义，JS 解析后还原为 `</script>`）
6. 修复后浏览器实测：状态栏 "应用已就绪"、bridge=true、viewInner 渲染"聊天"、顶栏"一年级·第一学期 上午" —— 全链路通 ✓

### 踩坑/经验
- **json.dumps 字符串里的转义必须考虑 JSON 层**：python 转义 → json.dumps 会再转义反斜杠，造成双重转义。规则：`json.dumps(html).replace('</script>', '<\\/script>')`（在 JSON 文本层替换，`\/` 合法）
- 诊断 iframe 内应用状态要查 `window.HGW`（window 属性），不要查 `App`（脚本级 const 不挂 window）——一度误判"JS 没执行"
- headless chrome 测试要独立 user-data-dir + 独立调试端口，旧实例占用端口会连到旧页面造成假结果
- 用户提醒：项目自带 `.skills/sillytavern-runtime-debug`（真实运行时复现/证据收集流程，用任意浏览器驱动）——排查酒馆运行时问题应先加载它，不要绕路装新工具
- 最终包：霍格沃茨.json 3.22MB，浏览器实测全链路通过
