## 二、体验目标

1. **起点是喽啰**。不是「隐藏的天才」，是真的资质凡庸、被当下人使唤。变强靠积累，不靠顿悟。
2. **人格决定走向**。原作核心：「人格特质参数随决策变动，从而影响人际关系、剧情走向与决斗策略」。
3. **错过是常态，不是意外**。每个旬能做的事**多于**行动点能做的。
4. **错过可复盘，但不可预知**。事后从别人的反应里体会到，活着的时候不知道自己错过了什么。
5. **师门的重量**。唐门已然式微，玩家的选择在「独善其身」与「献身门派」之间。
6. **失败也是故事**。原作宣传语「好坏都能是一个精彩绝伦的故事」。输了不是 Game Over，是换一条路。

## 三、原作结构

### 3.1 主角

**赵活** —— 唐门外姓弟子。相貌奇丑，出身绵阳，在唐门待了十几年，外姓弟子都走光了只剩他一个，**仍不得入室**。

- 武功：外姓弟子不得修习内门武功，**但不限制拜师他人** —— 这是他的路
- 称号链（`PlayerInfo/Title`）：`唐门杂鱼` → `唐门丑侠` → `下作侠` → `鬼面郎中` → `草食侠` → `阎王使者` …

### 3.2 唐门

|---|---|---|
| `master` | 唐中翎 | 唐门掌门 |
| `brother1` | 唐布衣 | 飞侠（大师兄） |
| `brother2` | 唐铮 | 辣手相公（二师兄，**实为泥教卧底**） |
| `brother3` | 唐升 | 三师兄（**带艺投师，年纪最长**） |

## 四、核心机制 ★★ 数据驱动的条件系统

### 4.1 架构修正

v1 把前置条件当成**代码逻辑**（`if 满足 then 解锁`）。**原作不是。**

逆向结论（DLL 反编译）：

> `checkpointmanager.Condition(key)` **只是一个查表动作**。
> 真正的阈值存在 Unity ScriptableObject 资产里，**脚本里看不到具体数值**。

原作由**三张数据表**驱动：

| 表 | 类 | 规模 | 职责 |
|---|---|---|---|
| **前置表** | `ConditionResultConfig` | 413 key | 条件 → 真/假 |
| **分支表** | `SwitchResultConfig` | 2654 key | 条件 → 分支序号（1-based） |
| **任务表** | `MissionCheckData` | 96 组 / 129 节点 | 含**显式过期字段** |

### 4.2 条件有 17 类（原作官方枚举）

```
Mortal.Core.StatCheckType = {
  常數=0, 角色數值=1, 好感度=2, 旗標=3, 書籍=4, 雜物=5, 貴重品=6,
  隨機值=7, 數值群組=8, 遊戲時間=9, 技能=10, 秘笈等級=11,
  已開發項目=12, 開發項目等級=13, 書籍精通=14, 風雲史=15, 條件設定=16
}
```

| 原作类型 | 本卡对应 |
|---|---|
| 常數 | 字面量；`XXX` 是**恒假哨兵**（54 次用作「永不显示」占位） |
| 角色數值 | `你.*`（53 项） |
| 好感度 | `关系.*.好感`（双向） |
| 旗標 | `任务.事件标记` / `前置.已解锁` |
| 書籍 / 書籍精通 | `秘籍.*.已读` / `秘籍.*.熟练` |
| 雜物 / 貴重品 | `物品.*`（按 `品质` 区分） |
| 隨機值 | 判定引擎 LCG（**确定性，禁 Math.random**） |
| 數值群組 | 派生值（`战斗.*`，引擎算不写回） |
| 遊戲時間 | `世界.年/月/阶段` |
| 技能 | `你.八系.*` / `天赋.*` |
| 秘笈等級 | `秘籍.*.熟练` 达阈值 |
| 已開發項目 / 等級 | `你.锻造` / `你.炼丹` 解锁项 |
| 風雲史 | `任务.已完成` |
| 條件設定 | 前置表自身（元条件：前置可引用前置） |

### 4.3 比较语义写进 key 名（原作做法）

原作 50 个比较 key：

```
S_Beh_GE_60    处世 ≥ 60   （152 次）
S_Kar_LE_40    道德 ≤ 40   （350 次，最高频）
S_Dis_LE_40    性情 ≤ 40
S_Tra_GE_40    修养 ≥ 40
S_Mental_GE_65 心相 ≥ 65
```

枚举：`StatCompareType = {Equal, NotEqual, Less, LessEqual, Greater, GreaterEqual}`

**本卡沿用**：条件写成 `{ 目标: '你.处世', 比较: '>=', 值: 60 }`，
**可读、可 diff、可校验**。

### 4.4 组合器：AND / OR 树

原作 `ConditionResultItem.Check()` = `_items.All(...)` + `LogicOp(..., _logicOp)`。

本卡：`所有: [...]` / `任一: [...]` 嵌套表达，深度不限。

### 4.5 错过：三层，含**显式过期字段**

原作 `Mortal.Core.MissionCheckData` 字段：

```
_active               总开关
_conditions           前置条件组
_dayCheck             是否启用时间窗
_timeCheckType        特定=1 / 區間=2 / 週期=3
_specificTime         特定旬
_minTime / _maxTime   区间窗口
_periodStage          周期
_modifyFlagsWhenTrue  ★ 检查通过时改的 flag
_modifyFlagsWhenFalse ★ 检查失败时改的 flag
```

**关键**：检查时**无论成败都会记账** —— 这是「错过也被记录」的实现，
不是靠单向跳转顺带实现的。

本卡对应：

| 原作 | 本卡 |
|---|---|
| `_active` | 单元 `启用` 字段 |
| `_conditions` | `前置: [...]` |
| `特定` | **只在某一旬出现，过了就没了** |
| `區間` | **区间窗口**，过窗即失效 |
| `_modifyFlagsWhenFalse` | 写 `前置.已错过` ★ |

### 4.6 三个最优雅的设计（照搬）

**① `~x` 隐藏哨兵**
```lua
talk[2] = Any_Food_001 and "default+O_xxx+1+0" or "~x"
```
条件不满足 → 选项**根本不显示**（全文 541 次）。玩家不知道它存在过。

**② Switch 返回首个匹配项的 1-based 序号**
```lua
local r = checkpointmanager.Switch("Battle_Result_001")
if r == 1 then ... end   -- 序号直接和 if 对齐
```

**③ 选项串四段式**
```
"图标+文本key+消耗行动数+消耗贡献"
如 "move+无色广场+1+0" → 移动类、耗 1 行动点、0 贡献
```

## 五、时间与行动点

### 5.1 时间（IL 确证）

```
firstYear=1, firstMonth=4, firstStage=1, roundsPerMonth=3
ConvertToRounds() = (Year-1)*12*3 + (Month-1)*3 + Stage
NextRound():  Stage 1→2→3→(回1, Month+1)；Month==12 → Month=1, Year+1
```

**Stage 就是「旬」**，**起始是第 1 年 4 月**。

### 5.2 行动点（动态）

原作 `GetMaxActionCount()` 按旬分支查不同 stat，再 `+ _defaultActionCount`，
并**减去 `T0002` flag 的 State**：

```
上旬 → stat[26] + 默认
中旬 → stat[39] + 默认
下旬 → stat[40] + 默认
− T0002（惩罚项）
```

行动点用完 → 自动 `NextRound()`。
存档交叉验证：`Year=1, Month=4, Stage=1` + `Stats[action]=2`。

### 5.3 硬约束

> **每个旬的可玩单元数 > 该旬行动点上限。**

强制取舍。这是「错过是常态」的机械保证。

## 七、玩法取舍

**保留**
1. ★ **数据驱动条件系统**（17 类检查 + AND/OR 树 + 过期窗）—— 卡的主体
2. ★ **门派发展六阶段** —— 全卡进度条
3. **行动点经济** —— 每旬有限
4. **三教修养 + 六项性格** —— 有明确数值前置（50 个比较 key）
5. **生活技艺**（锻冶/炼丹/伙房/讲经）—— 每条有产出
6. **关系双向 + 认知边界** —— 谁知道什么是可玩资源
7. **秘籍需师授** —— 逼玩家去交际

**砍掉**
- 战斗实时操作（原作是弹幕+闪避）→ 改引擎逐回合演算 + AI 写过程
- 立绘 CG 作为必须项 → 原作立绘仅作素材参考

## 八、边界（原著向）

**本卡不做露骨性内容。** 依据：

1. **原作是零性描写的武侠养成 RPG**。全剧本（2425 个 TextAsset / 58.9 MB）中，
   「交合」「床笫」「性交」「乳房」「云雨」「春宵」出现 **0 次**。
2. **官方从未公布角色年龄**。开发者明言「詳記於《活俠傳年代記》文件中，現在不可說」。
3. **能确认成年的仅夏侯兰一人**（剧本原话「她都二十六、七歲了」）；
   **唐默铃、叶云裳有原文指向未及笄**（「芳齡及笄」「及笄待嫁」）；
   其余 6 人无可靠依据。

**不接受靠改设定规避。**

恋爱线保留原作尺度：情愫、误会、聚散、师门与私情的冲突。

完整考据：`source/02_角色年龄考据.md`

## 十、重写说明（v1 → v2）

| 项 | v1 | v2 | 为什么改 |
|---|---|---|---|
| **条件机制** | 代码逻辑 `if` | **数据表驱动**（三表 + 17 类检查） | 原作条件是 ScriptableObject 资产，不是代码 |
| **过期机制** | 靠单向跳转「顺带」实现 | **显式过期字段**（特定/区间/周期） | IL 证明有 `_timeCheckType` 等专用字段 |
| **属性名** | 英文键直译（兵器/毒术） | **官方中文名**（锻造/炼丹） | 直译丢系统语义 |
| **进度主轴** | 江湖名声 | **门派六阶段** | `FictionTitle` 才是真正的门派进度 |
| **错过记录** | 没设计 | **`_modifyFlagsWhenFalse` 对应物** | 错过也要记账 |
| **时间起点** | 未指定 | **第 1 年 4 月** | IL 确证 `firstMonth=4` |
| **行动点** | 常数 2 | **按旬动态** | 原作按旬查不同 stat |

v1 产物归档于 `_old_v1/`。
