## 一、条件语法：不是 `if`，是「选项表 + 三元表达式 + 隐藏哨兵」

所有条件是**预计算的选项数组**，不是运行时 if：

```lua
-- resources__ch2_4_3_break_start_01__zh__1.txt L26-34
setmenudialog(menudialogs.Talk)
local talk = {}
local XXX = checkpointmanager.Condition("XXX")          -- "XXX" 是恒假哨兵
talk[1] = XXX and "default+O_2_4_3_Break_01_012+0+0" or "~x"
local Any_Food_001 = checkpointmanager.Condition("Any_Food_001")
talk[2] = Any_Food_001 and "default+O_2_4_3_Break_01_001+1+0" or "~x"
talk[3] = "default+O_2_4_3_Break_01_002+1+0"             -- 无条件项直接写字面量
local choice_talk = choose(talk)
```

- `"~x"` = **隐藏/禁用哨兵**（未满足时选项不显示），全文 **541 次**
- `"a+b+c+d"` 四段式：`图标+文本key+消耗行动数+消耗贡献`
- 另有 `or "~O_xxx"` 形式 → **换文案而非隐藏**

## 二、引擎真身（DLL 反编译所得）

`checkpointmanager` = `Mortal.Story.CheckPointManager`，4 个字段：
`_dice / _switchList / _condition / _position`

| 方法 | 行为 |
|---|---|
| `Condition(key)` | `ConditionResultConfig.GetResult(key)` —— **线性查找同名项，找不到就 `Debug.LogWarning("找不到 Condition 檢查點 "+key)` 并返回 false** |
| `Switch(key)` | `SwitchResultConfig.GetResult(key)` —— **找不到返回 1** |
| `Switch` 有状态 | `SwitchResultData.Execute()` 先 `_count++`，再按 `_items` 顺序返回**第一个满足项的序号（1-based）**；全不满足返回 `Count+1` |

**叶子比较项**（`Mortal.Core.GameStatCheckItem` / `GameFlagCheckItem`）IL：
```
LDF _stat → get_FinalValue / _flag → State
LDF _value; LDF _compare; CALL GameStatUtils::StatCompare
```

**枚举**：
```
StatCompareType = {Equal=0, NotEqual=1, Less=2, LessEqual=3, Greater=4, GreaterEqual=5}

StatCheckType = {常數=0, 角色數值=1, 好感度=2, 旗標=3, 書籍=4, 雜物=5, 貴重品=6,
                 隨機值=7, 數值群組=8, 遊戲時間=9, 技能=10, 秘笈等級=11,
                 已開發項目=12, 開發項目等級=13, 書籍精通=14, 風雲史=15, 條件設定=16}
```
★ **这 17 类就是「前置要求有哪几类」的官方答案。**

**组合器**：`ConditionResultItem.Check()` → `_items.All(...)` + `GameStatUtils.LogicOp(..., _logicOp)`
`LogicOperatorType = {AND, OR}` → 支持 AND/OR 组合树

**比较语义硬编码在 key 名里**（共 50 个比较 key）：

## 三、错过机制：三层，且有**显式过期字段**

`Mortal.Core.MissionCheckData`（ScriptableObject）字段名直接说明：

```
_key / _active / _desc / _position / _conditions / _beforeMainMission
_dayCheck(bool) / _timeCheckType / _specificTime / _minTime / _maxTime / _periodStage
_startScript / _nextStateName / _startDialogs / _alertDialogs
_modifyFlagsWhenTrue / _modifyFlagsWhenFalse
```

```
TimeCheckType  = {特定=1, 區間=2, 週期=3}
MonthStageType = {上旬=0, 中旬=1, 下旬=2}
```

`Check()` 反编译结果：

```
_active == false           → 直接 false
_conditions 全 true        → 继续
_dayCheck && type==1       → GameTime != _specificTime 则 false   （只在某一旬出现，过了就没了）
type==2                    → GameTime < _minTime || > _maxTime 则 false（区间窗口）
type==3（週期）             → 走 _periodStage
```

★ **`_modifyFlagsWhenTrue` / `_modifyFlagsWhenFalse`：检查时无论成功失败都会改 flag**
→ 这就是「错过也被记账」的实现，**不是靠单向跳转顺带实现的**。

脚本侧配套：`luamanager.SetMissionTime("S0200_01", 0, 0, 1)`
存档 `TimeSave` 是这批 GameTimeData 的落地：
```json
{"Name": "S0018_02", "Year": 1, "Month": 4, "Stage": 1}
```

**单向跳转** `luamanager.SetNextScript(name)` + `luamanager.Init()` 共 **2728 处**，
**没有回退入口** → 结构上保证错过不可逆（第二道保险）。

## 四、时间结构（IL 确证 `Mortal.Core.GameTime`）

```
firstYear=1, firstMonth=4, firstStage=1, roundsPerMonth=3
Year/Month/Stage/DayEnvironment

NextRound(): Stage 1→2→3→(回1, Month+1)；Month==12 则 Month=1, Year+1
NextMonth(): Stage=1, Month+1（跨年同理）
ConvertToRounds() = (Year-1)*12*3 + (Month-1)*3 + Stage
```

- **`Stage` 就是「旬」**（`MonthStageType={上旬,中旬,下旬}`）
- 翻译 key：`System/Stage_{n}`、`System/Month_{n}`、`System/GameTimeText=第{0}年{1}{2}`
- `DayEnvironment` = `{白天=0, 晚上=1}`（IL 里默认值写 1）

**行动次数是动态的**：`ResetActionCount()` → `GetMaxActionCount()` 按 Stage 分支：
```
上旬 → 查 stat[26]
中旬 → 查 stat[39]
下旬 → 查 stat[40]
再 + _defaultActionCount
并减去 T0002 flag 的 State
```
行动点用完自动 `NextRound()`。

**存档交叉验证**：`CurrentYear=1, CurrentMonth=4, CurrentStage=1` + `Stats[action]=2`
→ 与「初始 3 点、扣了 1 点」吻合。

> 「段考」在脚本里**未找到**独立触发（仅出现在 `Legend_01` 文本），属推断项。

## 五、互斥 / 分支锁

| 操作 | 实现 |
|---|---|
| 写入 | `statmodifymanager.SetFlag("Talk_Option_01", 1)` → `MissionManagerData.SetFlag` → 找到 `EventFlagSave{Name,State}` 后**赋值** |
| 累加 | `AddFlag(key, n)` → 同一对象 **`State += n`**（可负数，用于计数/倒计时） |
| 读取失败 | 只 `LogWarning("Flag [xxx] 未定義")` 返回 null，**不抛异常** → 错别字会静默变成「永久关闭」 |
| **互斥** | **同一 flag 赋不同值**（`SetFlag("M80050", 1/2/3)` 对应骰子三个结果）配合 `Switch(key)==n` → 后写覆盖前写 = 天然互斥 |
| 批量重置 | `statmodifymanager.ResetTalkFlag()`（78 处）重置 `Talk_*` 系列 → 轮回/新章节时解锁 |

## 八、SubMissions 结构

```json
{"Name": "S0014", "Key": "S0014_01"}
```
`Name`=任务组，`Key`=当前进行到的节点。**129 项里 `Key=="clear"` 表示已完成**。
实测 `S9904 clear`×18、`S2200 clear`×15。任务组共 **96** 个。
配套 `MainMission = {'Name':'main','Key':'M0002'}`。

`SubMissionsData.GetActiveMissions()` IL：
```
遍历 _list → 跳过 CurrentKey=="clear"
          → mission.GetByKey(currentKey) 得 MissionCheckData
          → Check() 通过 → 加入活动表 + ExecuteModifyFlagsWhenTrue()
          → 不通过      → ExecuteModifyFlagsWhenFalse()
```

`MissionManagerData.UpdateCheckMissions()` IL 顺序：
```
UpdateFlagWhenNewRound() → PlayerStat.UpdateGameTime()
→ 重算 ActiveSubMissions → 判定 MainCheckData
→ 若主线可开且 _isTriggerSubMission==false → SetStoryScript(StartScript)
```

脚本侧 `statmodifymanager.Mission("S0018","S0018_02")` / `Mission("S0101","clear")`（415 次）是写入口。
另：`TriggerSubMissionKey` + `IsTriggerSubMission`(bool) + `IsTriggerSubMission("S0020",1)`(24 次)
控制「支线正在进行中，暂不弹新任务」。

## 九、对复刻影响最大的四点

1. **条件不是代码，是数据表。**
   `checkpointmanager.Condition(key)` 只是查表动作，真正的阈值存在 Unity ScriptableObject 资产里，
   **脚本里看不到具体数值**。完整复刻必须重建三张表：
   `ConditionResultConfig` + `SwitchResultConfig` + `MissionCheckData`。

2. **错过有显式过期字段**（`_timeCheckType/_specificTime/_minTime/_maxTime/_periodStage`），
   不是靠 `SetNextScript` 单向性「顺带」实现的。单向跳转只是第二道保险。

3. **两个最优雅的设计**：
   - `~x` 哨兵 + 三元表达式 → 条件不满足则选项隐藏
   - `Switch` 返回首个匹配项的 **1-based 序号** → 直接和 `if choice == n` 对齐
   **EJS 里可以一比一照搬。**

4. **表的实际数值无法从资产读出。**
   该构建剥离了 MonoBehaviour 的 type tree（3671 个里只有 12 个可读），
   且无 .NET SDK 装不了 ilspycmd。
   → **只能靠脚本侧的 `SetFlag` / 比较 key 名反推。**

## 十、给「MVU + EJS + 引擎」复刻的 5 条工程建议

1. **三张表照搬为三份数据文件**，不要写成代码 if：
   `前置表.json`（条件→真假）/ `分支表.json`（条件→序号）/ `任务表.json`（含过期窗）。
   引擎只做查表与求值，**表可 diff、可校验、可热改**。

2. **`~x` 哨兵用「空字符串」代替**：
   EJS 里条件不成立的选项渲染为空，而不是渲染一个灰掉的按钮。
   ★ 保持原作「玩家不知道它存在过」的设计。

3. **过期用三态字段**，别用「已过期」布尔：
   `窗口: { 类型: 特定|区间|周期, 值: ... }`，
   引擎每次结算时求值，**过窗即写 `已错过`**（对应 `_modifyFlagsWhenFalse`）。

4. **`Switch` 的 1-based 序号直接映射到 EJS 的分支**：
   引擎返回 `1..n`，EJS 按序号取对应段落。**不要返回布尔**——
   布尔会丢掉「同一条线按条件走不同岔」的表达力。

5. **计数器（TC 前缀）单独建表**，支持负数累加：
   原作用它做**倒计时与惩罚**（`T0002` 直接减行动点）。这是最容易被忽略的一类状态。
