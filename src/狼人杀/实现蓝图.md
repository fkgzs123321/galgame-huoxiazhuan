## 二、变量层设计（schema.ts 骨架方向）

```
stat_data:
  世界:          # _ 前缀走脚本，无前缀的 AI 可读
    天数(1-7) / 阶段(夜|昼) / 昨夜死讯 / 公开事实(字符串整串) / 存活名单(字符串整串)
  玩家:
    身份(狼|民|铜镜|药囊|银匕|草汁) / 存活 / 血梦 / 同伴(狼) / 今夜行动 / 被种(隐藏$)
  _广播:         # 脚本每晨生成的动态块（12.2③）
    今日指令(11人行为线索·中立措辞) / 今日公开 / 尸体状态
  $庄晚棠 / $白蘅 / $灶婶 / $小满 / $姜芸 / $苏黎 / $陆霜霜 / $闻人夏 / $程郁 / $顾青芜 / $顾青黛:
    每人: { 身份, 持物, 已知, 好感, 怀疑, 被种, 兽化, 存活 }
```

- **不用数组**：名单/事实/指令全是字符串整串 replace（MVU 数组陷阱，MEMORY 铁律）
- 11 人命名空间全预置于 initvar（对象加新键中招 → 「只 replace 值，永不新增键」）
- schema.ts 只写 `export const Schema`，禁 `export type`（pack 校验）
- schema-agent 编写 schema.ts；主代理按序写 initvar.yaml → 变量更新规则.yaml

## 三、脚本清单（AGENTS.md 范围，TavernHelper API）

| 脚本 | 职责 | 关键 API |
|---|---|---|
| 01-指派.js | 先分组后落人；写 `$` 真相＋玩家无前缀身份；生成第一夜血梦文本 | `updateVariablesWith` / `Mvu.replaceMvuData` |
| 02-夜结算.js | 入夜行动收集 → 狼队夜议（玩家狼参与投票）→ 围猎/阻断/银匕/铜镜 → 清零 → 生成 `_广播` | 事件监听（月升/日出）＋变量写 |
| 03-投票处决.js | 好感×怀疑加权 → 玩家 UI 票 → 平票 → 众刑分支（同罪/反扑/以银代众）→ 遗言窗口 | 脚本变量＋UI 事件 |
| 04-胜负.js | 四终局优先级判定 → 结局分支 → 重开重掷 | 结算尾部调用 |
- 门控兜底三通道＋一兜底（defaults 原则，MEMORY 铁律）
- 脚本变量更新一律 `Mvu.replaceMvuData`（不经过命令校验层）
- 机制层自测：Node 模拟对局（指派→七夜→终局路径覆盖），先于条目创作完成
