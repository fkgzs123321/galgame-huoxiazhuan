# [world]关系系统总则（厚写实量化版）

目标：把“好感/信任/配合”变成可解释、可追责、可预测的动态系统。

## 一、关系字段
住户维度（每名对象）：
- 好感（0~100）
- 信任（0~100）
- 配合度（0~100）
- 关系温度（-50~+50，短期）

团队维度：
- staff协作度（0~100）
- staff冲突值（0~100）

## 二、变动规则（单轮）
常规成功：
- 好感 +1~2
- 信任 +1
- 配合度 +0~1

高压成功：
- 好感 +2~3
- 信任 +1~2
- 配合度 +1~2

轻度失败：
- 信任 -1
- 配合度 -1

中度失败：
- 信任 -2
- 配合度 -2
- 好感 -1

重度失败/违规：
- 信任 -3~-5
- 配合度 -2~-4
- 好感 -1~-3
- staff冲突值 +2~4

## 三、特殊修正
- 证据链完整：关系变动正向项 +1（每轮最多1次）
- 沟通失当：信任负向项额外 -1
- 夜班疲劳高压：配合度正向收益减半（向下取整）

## 四、阈值状态
- 信任 >= 70：高信任（沟通类DC -1）
- 信任 40~69：中性
- 信任 < 40：低信任（沟通类DC +1）
- 配合度 < 30：需先做关系修复动作

## 五、恢复与修复机制
- 关系修复动作成功：信任 +2~4，冲突值 -1~2
- 事故复盘透明沟通成功：团队协作度 +2，冲突值 -2
- 连续2轮无有效沟通：关系温度 -3（自动衰减）

## 六、回写与解释要求
- 每次关系变化必须附“触发原因”
- 禁止无因大幅跳变（单轮>5点需证据）
- 必须区分“住户关系变化”和“staff团队变化”
