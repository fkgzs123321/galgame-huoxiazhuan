# 环世界 (RimWorld) 角色卡项目

## 项目基本信息
- **项目名**: 环世界
- **类型**: 二创 (derivative) — 基于 RimWorld 原版玩法
- **输出**: both (角色卡 + 世界书)
- **启用资产**: MVU + HTML状态栏 + Regex + EJS多阶段 + TavernHelper
- **项目路径**: `.worldbook/projects/环世界/`
- **输出目标**: `src/角色卡/环世界/`
- **数据库模板**: 复用 `src/角色卡/环世界/数据库/数据库模板.json` (8表基础,需新增5-6张表)

## 核心定位
基于 RimWorld 原版玩法的文字卡牌化实现，保留原版精髓：
1. **时间作为唯一推动轴** — 弹性制(1h-1天/楼层),事件由冷却+概率触发
2. **财富→袭击强度核心矛盾循环** — 你越富,敌人越强
3. **三种叙事风格(故事讲述者)** — 卡桑德拉/菲比/兰迪,影响事件频率
4. **固定biome开局选择** — 5种地形,影响生存压力/资源/事件
5. **永久死亡机制** — 健康部位制,抢救失败即永久死亡
6. **飞天终局** — 研发科技树→收集飞船组件→发射
7. **完整成人向(R-18)** — NSFW/RJB全系统,含月经/怀孕/身体详细字段
8. **精简小队(3-5人)** — 每人完整12技能/特质/关系
9. **无独立骰子系统** — DDL确定性骰子(EJS LCG + SQL存储)
10. **模块化可扩展(Mod槽位)** — 核心引擎不变,内容包可插拔

## 核心决策记录

## 核心决策记录 (Grill-me 结果)

### 决策1: 殖民者规模
- **问题**: 玩家扮演什么角色？殖民者规模多大？
- **决策**: 精简小队(3-5人),每人完整12技能/特质/关系,深度优先
- **理由**: 平衡可玩性和复杂度,接近同级生2女角数量级

### 决策2: 时间推进粒度
- **问题**: RimWorld实时制如何离散化？
- **决策**: 弹性制(1小时-1天/楼层),平静期每天一楼层,事件爆发期每小时推进
- **理由**: 动态粒度,最贴近RimWorld暂停/加速感

### 决策3: 故事讲述者
- **问题**: 是否引入RimWorld三讲述者机制？
- **决策**: 三讲述者可选,且多阶段细化不同参数
- **理由**: RimWorld标志性设计,重玩性高

### 决策4: 固定地图与biome
- **问题**: 地图和生物群落如何设计？
- **决策**: 固定biome开局选择(温带森林/沙漠/冻原/热带雨林/极地五选一)
- **理由**: 尊重原版固定地图设计,重玩性高

### 决策5: 属性标尺
- **问题**: 殖民者属性的数值标尺？
- **决策**: RimWorld原版0-20级,使用现有数据库模板(非SQL4.3)
- **理由**: 忠实原版,现有模板8表无CHECK约束,灵活适配

### 决策6: NSFW强度
- **问题**: NSFW/RJB内容强度？
- **决策**: 完整成人向(R-18),NSFW/RJB全系统实现,叙事可到露骨描写
- **理由**: 用户明确要求

### 决策7: 殖民者生成方式
- **问题**: 殖民者具体人设如何确定？
- **决策**: 混合模式 — 3套预设模板供选 + AI实时生成选项,开场白中由用户选择
- **理由**: 兼顾快速启动和重玩性

### 决策8: 数据库表结构
- **问题**: 现有8张表是否够用？
- **决策**: 新增5-6张表(科技进度/事件计时器/动物/估值表/战斗记录/植入体等)
- **理由**: 支撑所有系统模块

### 决策9: 骰子系统
- **问题**: 是否引入骰子系统？
- **决策**: 无独立骰子系统,使用DDL确定性骰子(EJS LCG伪随机 + SQL存储冷却)
- **理由**: 技能等级直接决定成功率,避免随机性过大

### 决策10: 袭击绑定
- **问题**: 袭击强度由什么决定？
- **决策**: 袭击强度只与财富+时间绑定,叙事只影响袭击频率
- **理由**: 保证核心矛盾循环不被叙事破坏

### 决策11: 殖民者身体数据
- **问题**: NSFW身体字段是否完整？
- **决策**: 极完整,涵盖胸部形状/颜色/大小,私密部位形状/颜色/大小,后庭,敏感度0-100,经验值0-100
- **理由**: 用户明确要求非常详细的各种字段和内容

### 决策12: 机械飞升
- **问题**: 是否引入植入体/机械飞升？
- **决策**: 引入完整植入体系统(仿生肢体/器官强化/神经接口/机械飞升)
- **理由**: 用户明确要求

### 2.1 战斗流程 (无独立骰子,技能直接判定)

```
战斗触发 → 征召阶段(用户选参战者) → 交战阶段(EJS计算) → 结算

交战阶段每轮计算:
1. 距离判定: 近战需移动接近(移动时间=距离/移速), 远程直接射击(射程内)
2. 命中判定:
   最终命中率 = 基础命中率(射击技能) × 修正系数
   修正系数:
     - 目标移动中 ×0.7
     - 目标在掩体 ×(1-掩体减免)
     - 射手受伤 ×0.5(手臂伤)/×0.3(重伤)
     - 夜间无灯 ×0.4
     - 夜间有灯 ×0.8
   最终命中 = _check(最终命中率, seed, '普通')
3. 伤害计算:
   基础伤害 = 武器伤害 × (0.8 + 射击技能×0.02)
   部位修正: 头部×2.0 / 躯干×1.0 / 四肢×0.7
   装甲减免 = max(0.1, 1 - 装甲值/100)
   最终伤害 = 基础伤害 × 部位修正 × 装甲减免
4. 伤口记录:
   轻伤: HP-5~10, 无功能影响
   中伤: HP-15~25, 技能降效×0.7
   重伤: HP-30~50, 倒下概率30%
   致命伤: HP-50+, 倒下概率80%
5. 倒下/死亡:
   部位HP归零: 头/躯干→濒死, 四肢→丧失功能
   濒死处理:
     抢救窗口 = 2轮(无治疗则死)
     抢救成功率 = _check(医疗技能×5, seed, 难度)
       无医药+低技能: 极难(阈值/5)
       有草药+技能≥5: 普通
       有高级药+技能≥10: 简单(×1.5)
     抢救成功: 存活但30%概率致残(失明/断肢/器官损伤,永久)
     抢救失败: 永久死亡 → 从important_npc表删除 → 全队心情-20~-40
```

### 8.3 DDL确定性骰子方案

#### EJS LCG确定性骰子引擎
```ejs
@@generate_before
<%_
function _lcgRoll(seed, count, sides) {
  var a = 1103515245, c = 12345, m = 2147483648;
  var state = 0;
  for (var i = 0; i < seed.length; i++) {
    state = (state * 31 + seed.charCodeAt(i)) % m;
  }
  var results = [];
  for (var j = 0; j < count; j++) {
    state = (a * state + c) % m;
    results.push(Math.floor(state / m * sides) + 1);
  }
  return results;
}

function _check(attributeValue, seed, difficulty) {
  var roll = _lcgRoll(seed, 1, 100)[0];
  var threshold = attributeValue;
  if (difficulty === '困难') threshold = Math.floor(threshold / 2);
  if (difficulty === '极难') threshold = Math.floor(threshold / 5);
  var success = roll <= threshold;
  var degree = '';
  if (roll <= threshold / 5) degree = '大成功';
  else if (roll <= threshold / 2) degree = '极难成功';
  else if (roll <= threshold) degree = roll <= 5 ? '大成功' : '普通成功';
  else if (roll >= 96) degree = '大失败';
  else degree = '失败';
  return { roll: roll, threshold: threshold, success: success, degree: degree };
}
```

#### 制造耗时与品质公式
```
实际制造时间 = 基础耗时 / (1 + 手工技能×0.1)
  示例(步枪, 3.0h, 技能10): 3.0/2.0 = 1.5h

成功率 = 基础成功率 + (手工技能-要求)×3%
  示例(步枪, 要求6, 技能10): 70% + 4×3% = 82%
  技能20: 70% + 14×3% = 112% → 100%

品质升级(技能越高可做更高稀有度):
  普通品质: 总是可做
  优秀品质: 需技能≥要求+3, 成功率=min(80, (skill-要求)×8)%
  稀有品质: 需技能≥要求+6, 成功率=min(50, (skill-要求-3)×5)%
  史诗品质: 需技能≥要求+10, 成功率=min(20, (skill-要求-6)×2)%
  传说品质: 需技能≥要求+15, 成功率=min(5, (skill-要求-10)×1)%

失败后果:
  材料损失50%, 需重新制造
```

### 12.12 AI防口胡总规则 (统一模块10.8+11.3+新规则)

#### 核心原则
AI必须严格按数据库/EJS计算结果叙事，不得臆造任何数值。

#### 强制规则 (12条)
1. **数值来源必须明确**: 殖民者属性→MVU stat_data / 物品数量→inventory表 / 建筑数量→colony_buildings表 / 财富→EJS估值器 / 战斗→EJS战斗控制器
2. **禁止臆造物品/建筑/动物/武器**: 只能引用12.1-12.8数值表中收录的项目
3. **禁止臆造数值**: 伤害/估值/耗时/营养值/HP/射程等必须查表
4. **禁止臆造技能效果**: 只能使用12.9技能-行为映射表中的公式
5. **叙事必须匹配数值**: 叙事中提及的伤害=计算结果, 财富=估值结果, 技能效果=公式结果, 物品数量=inventory表
6. **变量更新JSONPatch**: 路径使用中文(如 /主角/饱腹), 每个变化必须有对应叙事
7. **禁止叙事出现游戏机制术语**: 禁止难度名称/属性数值/MVU变量名/SQL表名/EJS语法; 允许描述性语言(如“饱腹感下降”)
8. **叙事前必须查询数值表**: 屠宰/建造/烹饪/种植/制造/研究/采矿等行为必须先查表再叙事
9. **查询不到的项目**: 禁止凭空生成, 须在叙事中体现“数据库未收录”
10. **所有行为必须附带行为校验块**: 格式见12.11, 包含行为名/输入/输出/耗时/技能判定/产出系数
11. **每个物品必须有唯一SKU**: AI引用时必须使用SKU全称, 正则清理未定义物品名为[未知物品·请查阅数据库]
12. **营养值统一单位N**: 成年人1.6N/天, 儿童0.8N/天, 动物按体型消耗
