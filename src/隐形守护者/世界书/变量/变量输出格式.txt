# 世界书条目「[mvu_update]变量输出格式」默认 **关闭**（主模型随楼写变量）。
# 请启用「[mvu_update]变量输出格式（额外模型）」+ 酒馆「使用额外模型解析」。
<update_variable_rules>
rule:
  - **每楼只能有一个** `<UpdateVariable>` 块；禁止主模型与额外模型各写一块（否则界面会出现两个「👾变量更新」）
  - **已开「使用额外模型解析」**：主模型 **禁止** 输出 `<UpdateVariable>`；仅额外模型输出一块
  - **未开额外模型**：主模型同楼末尾必须输出 **恰好一个** `<UpdateVariable>`，且 JSONPatch **非空**（纯氛围且无抉择除外）
  - 路径为 JSON Pointer，**不含** `stat_data` 前缀；**禁止** schema 外路径；**禁止** `{"patch":[…]}` 与 `<JSONPatch>` 并存两份
  - **组织信任度** 只能是 `/肖途/组织信任度`
format: |-
  <UpdateVariable>
  <Analysis>
  - 当前节点：序章-?
  - **本楼用户原话关键词** + 选项 ID（**只根据 {{user}} 消息**，禁止根据 AI 正文；见《序章选项识别与一致性铁律》）
  - 是否 BE：是/否
  - 下一节点：通过项写目标；BE 写「无（本线已断）」
  </Analysis>
  <JSONPatch>
  [ 照抄《序章抉择全书-写死表》]
  </JSONPatch>
  </UpdateVariable>
</update_variable_rules>

**序章**（仅 `is_prologue` 时 EJS 注入写死表）：P1-A|P1-B / P2-A|P2-B / P3-A|P3-B|P3-C / P4-A|P4-B / P5 子步+P5-C。

- **P3-B 旅馆**：`已死亡=true`，结局=好梦还乡；**禁止** replace 当前节点→序章-4；**禁止** insert「序章-图书馆接头」
- **P3-C 酒馆**：同上，匹夫之刃；禁止→序章-4
- **P1-B**：用户辩解/另有隐情 → `已死亡=true`、新的征程；**禁止** P1-A 的 →序章-2
- **禁止** JSON 出现写死表没有的字段（如擅自 `/剧情/章节进度` delta）

**第一章**（`is_chapter1` + 序章已完成）：C1-1-A/B … C1-15-A/B/C；照抄《第一章抉择全书-写死表》。

- **禁止** schema 外路径、`/肖途/能力/*`、任意 `$` 字段
- **禁止** 一次 replace 跳多格（如 第一章-2→第一章-10）；仅 C1-15-A 可→第二章-0
- **C1-2-B** 非 BE，仍→第一章-3，仅 delta 阵营信用
- BE 同楼：`已死亡=true`，**禁止** 节点前进；组织信任仅 `/肖途/组织信任度`
