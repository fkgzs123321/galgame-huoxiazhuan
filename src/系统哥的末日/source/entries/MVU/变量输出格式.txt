# ===== MVU 变量输出格式 · 系统哥的末日 =====
# 参考"同级生2"额外模型双写架构
# 核心铁律：新出现=全量输出，之后=增量，时间=每轮必须
# 变量路径、HTML字段名、数据库列名三者完全统一（全中文）

## 一、输出顺序（每轮回复严格按此顺序）

1. 叙事正文（≤1300字，H场景≤1600字，事件触发≤1500字）
2. <StatusPlaceHolderImpl/>（单独一行，挂载状态栏）
3. <UpdateVariable> 块（MVU变量更新，必须含 <JSONPatch> 标签）
4. <UpdateTable> 块（SPV数据库SQL语句）

## 二、UpdateVariable 块格式


<UpdateVariable>
<Analysis>
【变量思维链·五步】
1. 事件：本轮发生了什么
2. 数值：哪些变量需要变化，变化多少
3. 门槛：是否触发硬门槛（新角色登场/阶段跳跃/结局触发）
4. 互斥：是否涉及互斥关系（绑定名额/交涉锁定）
5. 结局：是否触发BAD_END或阶段转换
</Analysis>
<JSONPatch>
[
  { "op": "replace", "path": "/系统变量/天数", "value": 2 },
  { "op": "replace", "path": "/反派状态/评价值", "value": 95 }
]
</JSONPatch>
</UpdateVariable>


## 三、操作类型（仅支持4种）

- replace：替换现有路径的值（**统一用replace，禁止用delta**）
- add：向对象/数组插入新项（新增角色时用）
- remove：删除现有路径
- move：移动路径（极少用）

**路径格式**：斜杠分隔，无 stat_data 前缀。例：/系统变量/天数 而非 stat_data.系统变量.天数

## 五、新增角色全量更新规则（核心铁律）

### 5.1 何时触发全量输出

1. **新女角被绑定**（绑定花名册空槽位填入新角色）→ 必须全量输出该女角28字段 + INSERT important_npc全量87列

### 双写同步规则（核心铁律！）
1. **MVU变量变化了哪些字段，<UpdateTable>中对应的UPDATE就SET哪些列**
2. **/系统变量/* 变化 ↔ UPDATE global_state SET 对应列**
3. **/反派状态/* 变化 ↔ UPDATE important_npc SET 对应列 WHERE name='林天'**
4. **/user状态/* 变化 ↔ UPDATE protagonist_info SET 对应列 WHERE row_id=1**
5. **/绑定花名册/女N/* 变化 ↔ UPDATE important_npc SET 对应列 WHERE name=该女角姓名**
6. **不漏字段，不多输出未变化字段**
7. **如果MVU变量与数据库值不一致，以MVU变量为准，修正SQL语句**
8. **所有中文列名必须用双引号包裹**

## 七、通用规则

1. **路径格式**：斜杠分隔，无 stat_data 前缀
2. **统一用 replace**：禁止用 delta 操作
3. **只输出变化的变量**：无变化不输出（时间除外，时间每轮必须）
4. **数值变更限制**：单轮单值变化 ≤10（特殊事件除外）
5. **隐藏字段**：$ 开头的字段禁止更新
6. **JSONPatch标签必须存在**：漏标签 = 所有变量不更新
7. **UpdateTable标签必须存在**：即使无SQL语句也要输出空块
8. **禁止正文输出数值**：评价值/反抗力等数值由数据库管理，叙事中禁止出现
9. **禁止路径错误**：必须与上方变量路径清单完全一致
10. **数据库列名全中文**：所有列名用双引号包裹，如 evaluation_value、ntr_bind_depth
11. **WHERE条件**：global_state/protagonist_info用WHERE row_id=1，important_npc用WHERE name='角色名'
