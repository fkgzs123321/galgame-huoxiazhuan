## 四、安全与性能（双套件脚本）

### 4.1 安全（`sillytavern-rolecard-security`）

```
high 0 ｜ medium 4 ｜ low 0
```

| 规则 | 数 | 裁定 | 理由 |
|---|---|---|---|
| `TWSEC-DOM-001` | 1 | **mitigated** | 面板用 `innerHTML` 渲染（11 处），但所有插值走 `E()` 转义（转义 `& < > "`），且**实测所有属性一律双引号包裹**，无单引号属性写入点 |
| `TWSEC-REMOTE-001` | 3 | **mitigated** | 唯一远程依赖是本仓库自己的 CDN，**已 pin 到 commit hash `@a67c64e`**（不是分支名），上游改不动这个地址；且只提供静态面板 HTML，不含凭据 |

**未发现**：动态执行（`eval` / `new Function` / `document.write`）**0 处**、
凭据形态字面量 0 处、可执行远程加载器 0 处、通配符 `postMessage` 0 处、iframe 沙箱放松 0 处。

**遗留一条**：`E()` 未转义单引号。当前无影响（没有单引号属性写入点），
**若以后新增属性插值的写法，要同步扩展 `E()`**。

### 4.3 两个脚本**不适用**（说明，不是失败）

| 脚本 | 为什么不适用 |
|---|---|
| `validate-rolecard-schema.mjs` | 它校验的是**数据库型卡**（`modelId` / `tables` / `storage`），本卡不是那种形态 |
| `validate-importable-component.mjs` | 它要 **component kind**（组件包），本卡是角色卡 |
| `validate-tavern-regex.mjs` | 它只认 **V1 格式**，读不到 V2 的 `data.extensions.regex_scripts` → 只数到 1 条 |

★ 第三条是个**真实的格式差异**：酒馆卡有 V1/V2 两种格式，V2 把内容全放 `data` 下。
正则本身的正确性由我们自己的 `check-pages.cjs`（真渲染 12 页）覆盖。
