## 四、原作的「时间—地点—人物」驱动方式

**这是原作最值得偷的结构**：攻略流程表长得像这样：

```
12月22日 AM 11:00  §保育园§        看见天道在偷窥爱美
12月23日 PM 12:00  §保育园§        救起快被货车撞到的园儿-庆子
12月25日 AM 10:00  §网球场§        一起打网球
12月27日 PM  1:00  §ATARU§         爱和梦的旅行
1  月 1 日 PM 12:00 §自宅§          收留久美子
...
```

**三个要素锁死**：`日期 + 时段 + 地点` → 事件。

而且**同一个日期有多个事件点**（AM 8:00 / 9:15 / 9:45 / 10:30 / 11:00 …）——
这说明原作的时间粒度**比原卡的「5 时段/天」细得多**。

### 与旮旯给木「在场名单」机制的对接

原作天然就是这个结构：

```
她决定·今天去哪   →  地点
到达时·是什么时段 →  触发该(日期, 时段, 地点)的事件
那里有谁          →  在场女角名单
```

**这正是旮旯给木里「她替你决定今天去哪」的原作依据** —— 而且原作的事件密度
（一天多个时间点）**比原卡的 5 时段更细**，所以：

> **建议**：底座的 T1 时间表，`单位上限` 要按原作的事件密度来定，
> 而不是照抄原卡的「5 时段」。
> 详见 `状态表.yaml` 的 T1 段（待按此调整）。

## 附：为什么这份清单重要

用户要求「地图系统」。这张卡的地图**不是背景板，是机制**：

| 地图在旮旯给木里承担的功能 | 说明 |
|---|---|
| **她的选项来源** | 「今天去哪」→ 地点决定她能摆出哪些选项 |
| **在场名单的输入** | `(日期, 时段, 地点)` → 谁在这里 → 选项池加载哪些女角 |
| **时间的消耗器** | 原作明写「见一个人要花时间」→ 地点之间的距离 = 时间成本 |
| **线索的埋点** | 各女角家门口（信良/西御寺/芳树宅）是**追人**的地点（梢江线靠这个） |

**没有这张地图，「今天去哪」就只是一个空选择。**
