| 3 | `主角/主角设定` | 「关灯由扩展处理」 | ⚠️ **内容要重写**（见下） |

| 5 | `事件/CG触发条件表` | （无，仅关了） | ❌ **唯一真死** —— 106KB / 88 张 CG，`CG_LIST` 只在自己文件内部自产自销 |
| 6 | `EJS预处理/时间线剧情索引库` | （无，仅关了） | ⬜ **待定**（51KB） |

### 第 3 条为什么是「内容要重写」而不是「打开就好」

它关闭后，文件里定义的 `PROTAGONIST_INFO` / `PROTAGONIST_NPC_INFO` **不会执行**（它们是 `const`，文件内局部变量，不注册全局）。
而全卡有 **5 处**写着「参 `主角设定.txt.PROTAGONIST_NPC_INFO`」：

```
D0系统控制器.txt:132                                    「P2-P6 选择时…参 主角设定.txt.PROTAGONIST_NPC_INFO」
变量/变量输出格式_额外模型.txt:112 / 136 / 161 / 753      「相泽诚 NPC 数据…参 主角设定.txt.PROTAGONIST_NPC_INFO」
```

→ **全卡有 5 条指令指向一个读不到的东西。**

但它不能简单地「打开就好」：那份数据是**「5 位可扮演男性角色 + 相泽诚 NPC」**，
而我们已经决定 **`<user>` 固定为同级生2 男主、砍掉 5 位可扮演角色**。
→ **内容作废，要重写成单一男主的设定，然后开启。**

### 第 4 条：注释与实现不符

注释声称「D0控制器按 `player_identity` 动态加载」，但 `D0系统控制器.txt:707` 只有：

```
player_identity: _playerIdentity      # 输出用，不是加载
```

**没有实际的 `getwi` 调用。** 作者写了意图，没写实现。
且「玩家身份」这个概念本身随 5 身份设计一起废除 → **重写或删**。

### 教训：审计器的「零引用」在「关闭 + 靠框架/约定加载」时会集体误报

| 条目 | 为什么「零引用」是正常的 |
|---|---|
| `[initvar]` | 靠 **MVU 框架的 `[initvar]` 前缀约定**加载，不需要 getwi |
| `[mvu_update]变量输出格式` | 靠**模式选择**（本卡用额外模型，不用主模型）生效，不需要 getwi |

**6 条里只有 1 条是真死（CG 表），审计器连错 5 条。**
这就是为什么判定必须人工 —— 脚本只能列线索。

### 5.4 keywords 规范（`conventions.md:98-106`）

原卡女角条目的 keywords 是 `['鸣泽唯']`（三字全名）—— **符合 skills**：
> **角色名本身不受限**：三字全名是安全的

但有个**风险**：绿灯靠「聊天历史里出现该关键词」触发，而 AI 叙事时可能只写「唯」不写「鸣泽唯」。

```

```
