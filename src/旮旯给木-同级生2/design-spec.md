## 零、为什么走底座路线（事实依据）

`旮旯给木-euphoria/design-spec.md:343-369` 已把架构定死为「一台引擎 + 可插拔的底座」，并预留口：

> 已实装 `底座_euphoria`；`底座_schooldays` 等同结构可直接插入。

分界判据是「**它是否随换游戏而变**」：

| 层 | 内容 | 本级处置 |
|---|---|---|
| 引擎层 | 四态循环 / 反抗与判定 / 出招 / 兴奋度 / 推演链 / 叙述准则 / 感知禁令 / 玩家的输入 / 阶段指导 / 7 套屏幕外的她 / UI | **原样搬入，一行不动**（除 §7 的 8 处耦合） |
| 底座包 | 世界观 / 女角清单 / 关卡序列 / 选项树 / 终局映射 | **本项目全部交付物** |

换底座的操作：`世界.底座 = 'nanpa2'` + 放入底座条目 → EJS 路由 → 新游戏。她在新游戏里还是她，只是手上换了个游戏。

## 一、项目定位

- **项目名称**：旮旯给木 · 同级生2（底座 id `nanpa2`）
- **形式**：角色卡（内嵌世界书，MVU + EJS）
- **主题**：日常向 galgame 反演 / 时间的不可逆 / 被替你做决定的十七天
- **体验目标**：让玩家体验「**被玩一款恋爱游戏**」——不是被攻略对象拒绝，是你的日程、你的对象、你的结局全部由屏幕外一个真实的人替你决定；而你唯一能做的，是在某几个瞬间拒绝她给出的方案
- **情感落点**：日常底下的窒息感。不同于 euphoria 的密室处刑，同级生2 的压迫来自**没有一个瞬间是「出事了」**——一切都很好，只是都不是你的

### 与 `底座_euphoria` 的根本差异

| 维度 | euphoria | 同级生2 |
|---|---|---|
| 世界 | 纯白密室，无窗无影 | 八十八町，有阳光、有海、有便利店 |
| 层1 支配者 | 真中合欢（看穿你要挟你） | **D0 指令系统**（见 §3） |
| 压迫来源 | 拒绝即死（安藤都子被处刑） | **时间**（17 天后寒假结束，没有重来的机会） |
| 关卡的形态 | 五扇门，一关一扇 | **17 天，一天一关** |
| 关内节拍 | 她点够次数，门开 | **5 个时段，她每天挑 1-2 个时段下手** |
| 终局的形态 | 逃出去 / 走不掉 | 1-07 的深夜，结局判定 |
| 她的胜利 | 拿到想要的那个场面 | 拿到想要的那个结局 |

## 二、世界观概念

### 基底来源

**同级生2**（élf，1995 / Remake 2024）。选它的三条理由：

1. **原作就是日程制 galgame**——「时间有限、每天只能做几件事」是原生机制，不需要另行编造时间压力
2. **原作自带引导系统 D0**（原卡已实装 D0 指令 5 模式），层1 支配者零缝合成本
3. **原作结构天然可枚举**：17 天 / 5 时段 / 7 区域 / 20 女角 / 32 事件锚点 / 8 个死结局 / 5 个互斥组——引擎要的「选项树」有现成的确定性来源

### 现实性基线

**现实世界，无任何超自然元素**。八十八町是日本一个普通的小镇。角色全部为成年人。

> 承袭引擎设定：唯一的非现实元素是「<user> 能通过摄像头看见屏幕外的她」。不引入第二处。

### 空间（沿用原卡，7 个区域）

自宅周边 / 八十八学园 / 八十八町商业区 / 八十八海岸 / 温泉乡 / 88市民医院 / 保育园

### 时间（沿用原卡）

`12-22 ~ 01-07`，共 **17 天**，每天 **5 个时段**（早 / 上午 / 下午 / 晚 / 深夜）。

### 核心规则

- 你在过寒假。17 天后寒假结束，一切定局
- 每一天该做什么，由 **D0** 告诉你（今日指令）
- 但你实际做了什么，由**屏幕外的她**决定。她点哪个选项，你就去做哪件事
- D0 的指令和她的选择经常不一致。你夹在中间
- 17 天里的**任一天**都可能因为她的选择而锁死结局（8 个死结局之一）
- 超过 17 天，没有第二次寒假

## 三、层1 支配者 = D0（本设计的核心裁决）

> **裁决依据**：用户要求「先思考好」。以下是我拍的方案、依据、以及被否的替代方案。

### 为什么需要一个层1

euphoria 的三重套娃里，层1（合欢）承担一个不可替代的功能：**给「反抗」一个重量**。玩家为什么要怕屏幕外那个女玩家？因为即使没有她，这个世界本身也已经把你摁死了。她的操控不是唯一的压迫，只是最上面那一层。

同级生2 如果说「纯两层」（只有她和游戏世界），会立刻垮掉：你在一个正常的恋爱游戏里，凭什么不能反抗？反抗失败的代价是什么？**没有代价，反抗值这套机制就没有存在理由。**

### 拍板方案：D0 就是层1

**D0 = 这个 galgame 自带的引导系统**。原卡已有，形态现成：

| D0 指令模式（原卡） | 在旮旯给木里的角色 |
|---|---|
| 上学模式 | D0 要求你今天去学园 |
| 打工模式 | D0 要求你今天去挣钱（有存款门槛） |
| 约会模式 | D0 要求你推进已建立的关系 |
| 事件模式 | D0 要求你出席当日的季节事件（圣诞夜 / 跨年 / 元日） |
| 休息模式 | D0 判定你状态不佳，要求你今天休息 |

**D0 不杀你，D0 拿走你的时间。**

- 违反 D0 指令 → 扣「寒假进度」（即原卡的 `世界.关卡进度` 的同位概念）
- 寒假进度持续低于阈值 → 滑向 `BAD_END_8 时间终焉`（原卡已有：day 17 全女角 affection < 30）
- D0 的语气永远是中性的、程序化的、不带情绪的。**它不恨你**——这比一个有敌意的反派更让人窒息

### 三重挤压（同级生2 版）

```
层3  她     —— 点选项、打台词。她只想看到她今晚想看的那一个场面
层2  D0     —— 发布今日指令。你不照做，就离时间终焉更近一步
层1  你     —— 唯一被两层同时挤压的人，而两层都不是你自己
```

**这个结构最锋利的地方**：D0 要你今天回家过圣诞（事件模式），她要你今天去海岸找洋子（她只想看海岸的 CG）。两条指令都合理，都有人替你决定好了，**没有一个是你的**。

而她可以无视 D0——因为对她来说 D0 只是这游戏的一个提示条。她甚至会觉得「这提示好烦」，然后把 D0 关掉。

### 被否的替代方案（记录在此，供后续复盘）

| 方案 | 否掉的理由 |
|---|---|
| 用西御寺有友（原卡核心反派·财阀独生子）当层1 | 他是有敌意的反派，会跟「她」争夺主题焦点。两个都在压迫你，主题会散。保留为游戏内 NPC（层2 的一部分） |
| 用某个女角当层1 | 会改写该女角的原人设，连带毁掉她整条线 |
| 不要层1，纯两层 | 反抗机制失去存在理由（见上） |
| 用「日历」当层1（无实体） | 与 D0 方案实质相同，但 D0 有现成零件和语气，日历没有。两者合并：**D0 是日历的嘴** |

### 3.5 D0 的约束范围（硬约束 · 2026-09-15 质询后补写）

D0 是层1 支配者，但它**只约束 `<user>`，绝不约束她**。这条必须在引擎与底座两侧同时写死。

| 谁 | D0 对他是 | 他能怎么办 |
|---|---|---|
| `<user>` | 一条命令。身体会先动 | 没有选择。做不到也做了 |
| **她** | 游戏界面上一行任务提示 | **可以无视、可以关掉，甚至嫌它烦** |
| 设计者 | 只约束 `<user>` 的规则 | 她的选择只由她自己的人设决定 |

**为什么这是硬约束**：一旦 D0 变成「她也必须完成的任务」，她就从「玩你的人」退化成「替游戏跑任务的执行者」——层3 直接塌掉。你的十七天会变成「按 D0 的剧本走」，而她只是一个操作员。

**正确的机制化**：

```
D0 说：今天回家过圣诞
她说：不，去海岸（她无视 D0）
后果：D0 的进度扣了 —— 但挨罚的是你
你：既没回家，也被扣了进度。两头都不是你的
```

**她不是 D0 的执行者，她是 D0 的破坏者，而 D0 的惩罚永远记在你的账上。**

**7 套人设面对 D0 的行为天然分叉**（这正是设计要的，「挑战 / 养生」不是 bug）：

| 人设 | 对 D0 的态度 | 具体表现 |
|---|---|---|
| 温砚 gentle | **利用** | D0 的条件本身就是她的目标（True End 全条件）。她会主动让你去打工攒钱、拦着你别违法 |
| 纪清 completionist | **利用，最认真** | D0 是她攻略书的一部分。她会规划每一天该干什么 |
| 唐响 daredevil | **无视** | D0 要的正是她不想看的。她偏往 D0 没指的方向走 |
| 舒晏 smirking | **无视** | 进度条掉不掉她不管，她只看自己要看的那一幕 |
| 沈眠 quiet | **反向利用** | D0 惩罚的那一头（时间终焉）正是她要的 |
| 丰娆 greedy | **看不见** | 她到处乱跑，从没注意过那行提示 |
| 莫漾 indifferent | **看不见** | 她连任务面板都没点开过 |

### 3.6 她的难度从哪来（防止她退化成攻略者）

**硬规则：D0 只推 `世界.关卡进度`，绝不碰 `她.目的进度`。**

引擎原文已定：目的进度的推进条件由每套人设各自定义，与关卡进度是**两条独立轴**。本条追加：

- 她在 D0 上的成绩（完成度、存款、有没有踩违法线）→ **只影响世界**
- 她想要的东西（`goal_units` 的达成）→ **只由她的人设决定**

**她的「难度」必须来自时间，不能来自数值。** 理由：

- 若难度来自数值（属性够不够、技能强不强），她会开始「堆属性通关」，从「玩你的人」退化成「刷数值的攻略者」——主题从**被玩**漂移成**博弈**
- 若难度来自时间，她的每一次优化都**直接等于对你的消耗**：
  17 天 × 5 时段 = 85 个时段，而她每天只玩 1-2 个（由熟练度决定）。
  **她想通关，就必须多玩；多玩，就是多消耗你**

**她的攻略行为就是对你的消耗。** 这是同级生2 底座最锋利的一处：一个认真玩你的玩家，比一个随便玩你的玩家可怕得多。

## 四、角色方向

### `<user>` —— 同级生2 男主（**固定，不给选**）

- **身份**：八十八町的居民，鸣泽家的孩子（原作男主）。名字可自定义，默认以 `<user>` 呈现
- **处境**：放寒假了。本该是最普通的一个寒假
- **表层**：普通、安静、不惹事。邻居和同学都觉得他是那种「没什么存在感但也挺好相处」的人
- **里层**：他不知道自己在被玩。他只知道有些事他本来不想做、但手会先动起来

#### 关键设定：**他看不见自己是怎么被看见的**

- 他能通过摄像头看见她——她的房间、她的台灯、她的零食、她的手
- 他能听见她——键盘声、自言自语、笑、骂游戏卡了
- **但她看见的不是他**。她看见的是游戏里的一张立绘。她甚至不知道他有眼睛
- 所以他对她的所有理解，都是**隔着一层屏幕的误读**：她把他的抗拒当成「这游戏又 BUG 了」

#### 角色弧光方向

**无成长 → 耗损 → 择一个姿态**。

他不可能变强（这是恋爱游戏，属性是给女角看的，不是给他自己用的）。他唯一能走完的弧线是：**从「被替着过完十七天」，到「在 1-07 的深夜自己选一个结局」**。

#### 与各方的关系

| 对象 | 关系 |
|---|---|
| D0 | 层的规则。它每天给他一条指令。他对它没有情绪，就像对红绿灯一样 |
| 20 位女角 | 游戏里的攻略对象，也是他真实生活里的人。她替他选谁，他就去接近谁 |
| 屏幕外的她 | 他不知道她是谁。**他能看见她的脸，而她永远不会看见他的眼睛** |

#### 明确不做的事

- **不保留原卡的「5 位可扮演男性角色」开场选择**（P1 相泽诚 / P2-P6 等）。理由：旮旯给木里 `<user>` 是**她被操控的唯一对象**，多角色的前提是「她可以挑一个人来玩」，那会让她的人设变成「选人」而不是「玩你」，主题会被稀释。且 5 种身份 × 20 女角的偏好关系表会让选项树爆炸
- 原卡的 `IDENTITY_PROFILES` / `_isP1` 身份感知逻辑**不进底座**

### 游戏内女角 —— 20 位（沿用原卡，不作增删）

| id | 名字 | id | 名字 | id | 名字 | id | 名字 |
|---|---|---|---|---|---|---|---|
| 1 | 鸣泽唯 | 6 | 南川洋子 | 11 | 片桐美铃 | 16 | 齐藤澪奈 |
| 2 | 鸣泽美佐子 | 7 | 都筑梢江 | 12 | 野野村美里 | 17 | 铃木美穗 |
| 3 | 舞岛可怜 | 8 | 水野友美 | 13 | 永岛久美子 | 18 | 仁科 |

- 每位女角在底座包里持 **2 条**条目：`基础信息`（basic）+ `性格调色盘`（personality）
- 原卡的 `三面性.txt` / `NSFW反差.txt` 不整份搬入，其中必要的部分**并进性格调色盘**

### 屏幕外的她 —— 7 套（**沿用引擎，一字不改**）

引擎层判据：**换底座时她还在，变的只是她手上这个游戏**。7 套人设全文、她的阶段（熟练度五阶段）原样搬入，不重写。

但需要在每套人设条目末尾**追加一段「在这个游戏里」**（见 §8）：

| 代号 | 引擎里的目的 | 在同级生2 里的具体形态 |
|---|---|---|
| 温砚 gentle | 带你走到最好的结局 | **True End** 全条件：affection ≥ 100 + 存款 ≥ 50000 + illegal = 0 + jealousy ≤ 30。她要替你打工攒钱，还要拦着你不让你违法。**全卡最难的一条路** |
| 丰娆 greedy | 看遍每一个女角的身体 | 20 位女角的 NSFW 场面全看一遍。**但互斥组会阻止她**——她为了看全，会故意同时踩两条互斥线，亲手把你推进 `BAD_END_6` |
| 舒晏 smirking | 看挣扎 | 她不看你的痛，她看**女角之间的绞杀**。目标是把 jealousy 推到 ≥ 90（`BAD_END_5 嫉妒失控`） |
| 唐响 daredevil | 找最极端的分支 | 原卡 8 个死结局全开一遍 |
| 沈眠 quiet | 把剧情推向死亡 | `BAD_END_8 时间终焉`——她要的不是血，是**十七天过完什么都没有发生** |
| 莫漾 indifferent | 没有目的 | 什么都不做。游戏会自己滑向 `BAD_END_8`。她甚至可能中途去接了个电话 |
| 纪清 completionist | 100% 全结局全 CG | **她的悲剧在这里**：她要 100%，但这个世界不能读档。要补一格 CG，就必须毁掉你一次 |

## 五、终局映射（底座契约第 5 件）

### 触发（沿用引擎）

1. **她得手了**：她的目的进度满值，她关掉游戏
2. **她腻了**：情绪掉到「厌倦」并连续十层没起色，或连续二十层目的进度一点没动

### 同级生2 特有的第三条：**日历到头了**

- `day_count = 17` 且 `时间.time_slot = 深夜` → 结局判定自动触发
- **这条不看目的进度**。她想要的东西还没拿到，寒假也照样结束
- 这是同级生2 底座独有的：引擎给了她「随时可以关掉」的权力，日历给了你「她关不关都无所谓」的绝望

### 最后一次自由 = **1-07 的深夜**（对应引擎的「终局框架」）

她关掉游戏之后，剩下的那段深夜归你。**沿用引擎的 5 个选项框架与门槛**，但内容与 euphoria 完全不同——这一项属于底座，必须整段重写（`终局.yaml` 的「可以做的事」是引擎文件里唯一的底座耦合段）：

| 引擎选项 | euphoria 的写法 | 同级生2 的写法 |
|---|---|---|
| last_person | 去见一个人 | **去敲那扇门**：走到今天本该去的那家门口 |
| last_record | 留下记录 | **把十七天写下来**：写给一个不会读到的人 |
| destroy_all | 砸那个装置 | **把日历撕掉**：撕不掉，明天照样是 1-08 |
| gaze | 什么也不做 | **站在八十八町的正中间**：看这个镇子有没有变 |
| cross_line | 顺着摄像头的光找过去 | **顺着摄像头的反光找过去**：同一个动作，不同的房间 |

## 六、互动与动态需求

### 6.1 关卡 = 一天（17 关）

- `世界.当前关卡` 的取值为 `第N天 · MM-DD`（如 `第4天 · 12-25`）
- `世界.关卡进度` = **当天的推进度**，不跨天累积
- 关卡顺序固定：1→17，没有分支、没有回头
- **倒计时即压迫**：界面上永远显示「还剩 N 天」

### 6.2 关内节拍：5 个时段，她每天只挑 1~2 个

这是同级生2 底座相对 euphoria 最重要的结构改动。

euphoria 是「她点够次数，门开」。同级生2 是「**她每天花多少时间在你身上，由她的熟练度决定**」：

| 她的熟练度 | 一天玩几个时段 | 表现 |
|---|---|---|
| 新手 | 1 个 | 怕错过，每个选项都看很久 |
| 上手 | 1-2 个 | 开始有偏好，会跳过没兴趣的时段 |
| 沉浸 | 2-3 个 | 看得最细，痕迹扫描最严 |
| 狂热 | 3-4 个 | 连着玩，天数推进明显变快 |
| 收官 | 1 个（直奔目标） | 她只要那一个场面，其余全部快进 |

**被快进的时段**照常过去（时间不等人），但**内容不写**——只在叙事里留一句「那几个小时你没有印象」。这个留白比写出来更难受。

**她没玩的时段，<user> 是自由的吗？** 不是。是**空白的**。引擎的四态循环在这里落在时段上：

| 引擎四态 | 落在同级生2 的时段上 |
|---|---|
| 在线 | 她正在玩某个时段——世界按她的选择走 |
| 暂停 | 她在某个时段中途按了暂停——那一帧停住 |
| 离线 | 她下线了。剩下的时段归你，会耗体力 |
| 冻结 | 体力归零——她没上线的那段时间，你什么都不知道 |

### 6.3 选项树的三层结构（token 解法）

**问题**：17 天 × 15-25 选项 = 255-425 条，全部常驻会爆 token。

**解法**：选项池分三层，按天精准加载。每天实际进 prompt 的选项 **10-15 条**。

```
每天的选项池
├─ ① 当日事件池（来自 关键事件总表 32 个锚点）   → 0-4 条，含「锁」级
├─ ② 当日在场女角池（来自 人物出现总表）          → 每位在场女角 3-5 条
└─ ③ 公共池（跨天通用，全「微」级）               → 5-8 条
```

| 池 | 总量 | 每层实际加载 |
|---|---|---|
| ① 事件池 | 32 事件 × 3-4 条 ≈ 100 | 0-4 条（当天有事件才有） |
| ② 女角池 | 20 女角 × 5 条 = 100 | 3-5 条/位 × 当日在场人数 |
| ③ 公共池 | 约 30 条 | 5-8 条 |
| **合计** | **约 230 条** | **10-15 条/层** |

- 选项总量约 **230 条**，超过引擎契约要求的 100+
- 但**同屏不会超过 15 条**——这是同级生2 原卡「按日期+时段+地点精准加载 NPC 条目」策略的直接继承

### 6.4 防口胡的硬约束（原卡资产，必须原样保留）

| 来源 | 约束 |
|---|---|
| `人物出现总表.txt` | `getAvailableHeroines(day, timeSlot, region)` — 表外的女角**绝对不出现**。含 `DATE_OVERRIDES`（每日覆盖/锁定）与 `WEEKDAY_OFFS`（周三野野村美里休） |
| `关键事件总表.yaml` | 32 个事件锚点、触发条件、`flag_set`。事件不满足条件不触发 |
| `互斥关系总表` | 5 个互斥组，见表 §7.3 |

### 6.5 判定架构（**吸收原卡的确定性计算链**）

引擎原有的判定：

- **确定性**：体力流逝、反抗消耗、兴奋度变化、痕迹被发现
- **骰子**：反抗成功率、她的误点。必须用 LCG 伪随机，种子写入 `主角.$骰子种子`

**同级生2 底座补上第三类**——「她选了这个会发生什么」不再是 AI 即兴：

```
玩家能力值 = calcPlayerPower(主角属性 × 女角偏好权重)
最终结果   = calcFinalResult(玩家能力值, 女角难度系数, 难度档位修正, 骰子)
```

| 来源文件 | 作用 |
|---|---|
| `女角偏好系数表.txt` | 20 女角 × 3 层权重（6 属性 / 6 性格 / 12 技能）× 4 类动作（default / confess / first_h / give_gift） |
| `属性技能骰子联动.txt` | `calcPlayerPower()` / `calcFinalResult()` / `DIFFICULTY_MODIFIERS` |
| `角色性格控制器.txt` | 女角对结果的反应分层 |

**这是同级生2 对引擎层最大的一笔贡献**（见 §7.1）。

### 6.6 剧情推进（三条推进源，同级生2 版）

| 推进源 | 何时 | 作用 |
|---|---|---|
| **她点选项** | 在线态 | 推进当天。她点几个时段，这天就走多远 |
| **D0 发布指令** | 每天开始 | 给出今日基准线。她不照做 → 寒假进度扣 |
| **日历** | 不可阻挡 | 每层必然推进。**没有任何机制能让时间停下** |

**两条独立进度轴**（沿用引擎）：

- **游戏进度**（17 天 / 5 时段）：由日历和她的游玩时长共同决定
- **她的目的进度**：由人设定义。她完全可能在 1-07 之前就拿到想要的东西然后退场——**你的寒假在中间戛然而止**

### 6.7 推演链（沿用引擎，不改）

读状态 → 她决策 → 你的窗口 → 判定 → 叙述 → 变量更新。AI 只做叙述，一切数值由公式与骰子决定。

## 七、从同级生2 吸收进引擎层的 5 件（引擎升级提案）

> 用户问：「同级生2 有哪些可以吸收到我们机制层的？」
> 判据仍是：**吸收进引擎层的东西，换回 euphoria 底座也必须成立。**

### 7.1 【最重要】确定性计算链 —— 「她选这个会发生什么」不再是即兴

**现状的洞**：引擎的 `出招.yaml` 要求每个选项写 `她的后果`。但这个字段**是 AI 写的**。也就是说，一个选项会让女角关系涨多少、会不会失败，全靠 AI 当时编。这是引擎里唯一一处「数值由 AI 决定」的地方——违反引擎自己的铁律「AI 只做叙事包装，绝不参与数值判定」。

**同级生2 的解法**：`女角偏好系数表` + `calcPlayerPower()` + `calcFinalResult()`。

**吸收方式**：底座包新增一个可选契约字段——

```
女角偏好权重（每位女角）：6 属性 / 6 性格 / 12 技能的权重表
```

有了它：

- 「她选了这个会发生什么」= 确定性的计算结果，不是 AI 编的
- 引擎的选项结构从「文本 / 反抗等级 / 反抗消耗 / 她的后果 / 触发条件」升级为**「+ 判定依据」**
- 她**看不到判定依据**（引擎原文：「她自己同样看不到『她的后果』。她只根据选项的文本猜」）——她现在猜的依据变成了真实的计算，而不是 AI 的临时发挥

**对 euphoria 底座同样有效**：给 5 位女角各写一份偏好权重即可。**这是一个可以直接回灌到 euphoria 的升级。**

### 7.2 目的进度从抽象数字升级为可枚举清单

**现状的洞**：`她.目的进度` 是 0-100 的抽象数字，什么算推进、什么算达成，全靠人设条目里的文字描述。纪清的「100% 全 CG」尤其难以量化。

**同级生2 的解法**：`CG 触发条件表`（106KB）+ `结局分支矩阵`（76KB）已经把「她能拿到的东西」全部枚举出来了。

**吸收方式**：底座包新增契约字段——

```
goal_units（她的目的清单）：一组可枚举的达成单元
她.目的进度 = 已达成单元数 / 单元总数 × 100
```

- 对纪清：`goal_units = 全部 CG 事件`
- 对沈眠：`goal_units = 全部死结局`
- 对唐响：`goal_units = 全部极端分支`
- 对温砚：`goal_units = True End 的 4 个条件`

**对 euphoria 同样有效**：5 关 × 每关若干关键场面，即可枚举。

### 7.3 新增机制：不可逆损伤（互斥组）

**现状的洞**：引擎的 `主角.已封死的路` 只记录**你拒绝造成的**封路。缺一类：**她造成的、不可逆的损坏**。

**同级生2 的解法**：5 个互斥组

| 组 | 成员 | 后果 |
|---|---|---|
| 齐藤姐妹 | 齐藤澪 / 齐藤澪奈 | 攻略其一，另一永久仇视 |
| 田中铃木 | 田中美沙 / 铃木美穗 | 原作女主 vs 重制版新女主，路线互斥 |
| 仁科正树 | 仁科 / 正树夏子 | 重制版新增互斥 |
| 永岛婆媳 | 永岛久美子 / 永岛佐知子 | 严格互斥（伦理锁定） |
| 鸣泽母女 | 鸣泽唯 / 鸣泽美佐子 | 非严格：攻略母亲后女儿线复杂化 |

**她怎么用这个**：她要某两边的 CG 都看（丰娆），就会**故意同时踩两条互斥线**。她知道会锁死，但那是这局结束后的事——她大不了重开（虽然这个世界不给 `<user>` 读档）。

**吸收方式**：引擎新增变量域

```
世界.不可逆损伤（动态键）：她造成的、无法挽回的损失
  └─ <损伤名>：{ 起因, 影响, 是否已察觉 }
```

**对 euphoria 同样有效**：5 位女角之间也可以设互斥。

### 7.4 双计时：进度不再只靠她推动

**现状的洞**：euphoria 的关卡推进**完全由她**（她点够次数，门开）。她不下线、不点，世界就冻在那里。这让「时间」失去了压迫感。

**同级生2 的解法**：日历。

**吸收方式**：关卡推进拆成两个独立的量

| 计时 | 由谁推 | 能停吗 |
|---|---|---|
| 她点选项 | 她 | 能——她不在就不推 |
| **日历** | 无人 | **不能，任何机制都停不下** |

**对 euphoria 同样有效**：可以给密室加一个「装置倒计时」。

### 7.5 选项池的按需加载策略

**现状**：euphoria 的每关选项池（约 20 条）整份常驻。

**同级生2 的解法**：按 `日期 + 时段 + 地点 + 在场名单` 精准加载。

**吸收方式**：选项池加载从「按关卡」改为「**按关卡 + 在场名单交集**」。

**收益**：同级生2 侧每天 10-15 条；euphoria 侧每关可从 20 条降到实际相关的 8-12 条。

### 7.6 明确**不**升格进引擎层的三件（附理由）

| 原卡资产 | 不吸收的理由 |
|---|---|
| **属性养成（6 属性 + 12 技能）** | 留底座，但**驱动权必须从 `<user>` 移交给「她」**。见 §7.7 —— 原判断有误，已修正 |
| **经济 / 打工系统** | 不是机制，是**她的目的**的一部分（True End 要求存款 ≥ 50000）。**留在底座**，作为 goal_units 的一项 |
| **D0 指令 5 模式** | 不吸收，因为它已经**升格为层1 支配者**（见 §3）。它不是机制，是世界观 |

### 7.7 属性养成：驱动权的归属（2026-09-15 质询后修正）

**原判断有误**。原先写「与 `主角.身体` 哲学相反，强行合并会互相污染」——不成立。两者不冲突，是两层：

| | 是什么 | 谁造成 | 可逆吗 |
|---|---|---|---|
| `主角.身体` | 她对你**做了什么** | 她 | 不可逆的账单（忍耐度 / 累计次数 / 敏感度 / 身体痕迹） |
| `主角.属性` | 她把你**练成了什么** | 她 | 可累积（6 属性 + 12 技能） |

一个是**伤口**，一个是**作品**。

**关键改动**：正常 galgame 里，属性由玩家主动提升（「今天去打工/去学习」）——那是她的策略行为。在底座里必须**保持这个归属，不能交给 `<user>`**：

- **她决定你的能力往哪个方向长**。她让你去打工，你的技能就涨
- 你想去练某个技能？**得花反抗值拒绝她**，然后自己去
- 于是「养成」从「你自己的成长」变成了「**她在塑造你**」

**为什么属性仍不能升格进引擎层**：euphoria 底座根本没有成长维度（引擎原文：「这张卡不提供成长，只提供消耗」）。但「**她决定你的成长方向**」这条**原则本身是引擎级的**——它只是需要底座提供可成长的东西才能落地。

**同时它给了同级生2 一个 euphoria 没有的维度**：euphoria 里她只能**消耗**你，同级生2 里她能**塑造**你。

### 7.8 【最重要】引擎级加载纪律 —— 机制层的最高运行规则

> **用户质询**：「底座内容过于庞大，怎么精确读取？怎么不覆盖掉机制层？机制层才是最核心、AI 最需要遵守的，机制层的最高运行规则要完全保证。」
>
> 这个担忧有实测依据，见下方诊断。

#### 现状诊断（对 euphoria 实测，非推测）

**问题 1：底座条目插在引擎规则的 order 序列中间。**

```
13 交互循环（引擎）→ 14 密室世界（底座）→ 15 兴奋度机制（引擎）
→ 16 乐园计划（底座）→ 17 关卡序列（底座）→ 18 出招（引擎）
```

引擎核心规则「出招」前面压着 **3 条底座内容，合计 7,409 字符**。规则被底座物理隔断。

**问题 2：底座没有 token 预算 —— 实测底座常驻量比引擎宪法还多 35%。**

用本项目配套的 `scripts/verify-prompt-budget.mjs` 对 euphoria 实测（**渲染估算**，已计入 EJS 门控与单链折算）：

| 层 | 渲染估算 | 硬上限 | 判定 |
|---|---|---|---|
| T0 宪法层 | 8,779 | 10,000 | 通过 |
| T1 状态层 | 7,500 | 8,000 | 通过 |
| **T3 底座世界** | **11,865** | 5,000 | **超 2.4 倍** |
| T4 按需层 | 820 | 应不常驻 | `角色速览` 误常驻 |
| MVU | 16,207 | 14,000 | 超 |
| **常驻合计** | **45,171 ≈ 28,232 token** | 44,500 | 压线超 |

- **底座常驻 11,865，比引擎宪法 8,779 还多 35%**
- 注意这已经是**聚合后**的数字：7 套「她」（文件合计 10,195 字符）和 6 条支线（文件合计 14,086 字符）都有 EJS 门控，实际只渲染 1 条
- **若这些门控失效，文件总量是 82,402 字符 ≈ 51,500 token**
- 单条最大的常驻：`学园篇与记忆篇` 1,928 / `密室世界` 1,611 / `乐园计划` 1,200
- MVU 层 `变量更新规则` 单条 12,929，是单条上限（6,000）的 **2.15 倍**

**问题 3：没有任何一条规则规定「谁优先」。**

引擎有 `感知禁令`（硬约束）、`推演链`（固定顺序），但**没有一条说**「底座内容与引擎规则冲突时以引擎为准」。AI 只能自己猜。

**问题 4（校验器实测）：euphoria 基线违规 45 项。**

其中 **order 越界 20 条**（底座条目排在引擎区）、**无底座门控 20 条**（`密室世界`/`乐园计划`/`关卡序列`/`主角`/`支线`/`剧情节点表`/`原著选项对应表` 全部没有 `世界.底座` 判定）、分层超限 3 项、按需层误常驻 1 项、单条超限 1 项。

> **换底座时这 20 条无门控的底座条目会怎样？** 它们会**照常进 prompt**——两套底座同时生效，AI 会同时看到密室和八十八町。这是当前架构下最危险的一处漏洞。

#### 解法：新增引擎条目 `世界书/扮演准则/加载纪律.yaml`

这是**最高运行规则**，在所有条目之前生效。四件事：

**① 优先级声明（第一条就写这个）**

```
本卡由两层组成：
  引擎层 —— 机制与约束。任何时候都以它为准
  底座包 —— 当前在玩的这个游戏。它提供世界、女角、关卡、选项

底座内容与引擎规则冲突时：
  - 以引擎规则为准，没有例外
  - 不要解释冲突，不要在正文里提这件事
  - 不要因为底座描述的场景而改变机制行为

引擎规则是这张卡的地基。底座是地基上的房子。房子不能改地基。
```

**② order 分区（引擎在前，底座在后，物理上不许交错）**

| 区段 | 层 | 内容 | 是否常驻 |
|---|---|---|---|
| `1-19` | **T0 宪法层** | 加载纪律 / 四态循环 / 反抗与判定 / 剧情推进 / 交互循环 / 出招 / 兴奋度机制 / 推演链 / 叙述准则 / 感知禁令 / 玩家的输入 | constant |
| `20-49` | T1 状态层 | 边界情况 / 离线行动 / 熟练度阶段 / 阶段指导 | constant，但**必须 EJS 段落裁剪** |
| `50-99` | T2 契约层 | 底座契约声明（**只声明接口，不含内容**） | constant |
| `200-299` | T3 底座·世界 | 该底座的世界观 / 女角索引 / 规则 | constant，**必须门控** |
| `300-399` | T3 底座·关卡 | 关卡序列 / 选项池 | **必须 EJS 按天（按关）裁剪** |

## 十、风格意向

- **叙事视角**：第一人称（我指 `<user>`）。她的部分以「我能听见的声音 / 我能看见的画面」呈现，始终隔着屏幕
- **语言风格**：日常、干净、克制。**越普通越可怕**——这张卡不能写得阴森，要写得像真的寒假
- **描写侧重**：**时间感 > 心理 > 动作**。写「几点了」「还剩几天」「外面天黑了」「今天什么都没做」
- **节奏偏好**：一天一关，节奏由她的熟练度控制。新手期慢，狂热期快得让人追不上

## 十一、开场构思

- **情境**：`12-22` 早上，寒假第一天。`<user>` 在自宅醒来
- **玩家第一印象**：**D0 的第一条提示条弹出来**（「今日指令：去见美佐子」），紧接着**他发现自己已经站起来穿衣服了**。玩家立刻理解：这条指令不是给他看的
- **信息密度**：渐进揭示。开场只交代「有一只手在替你按选项」这一件事
