# Token 预算与加载策略 · 底座_nanpa2

> **本文回答两个问题**：① skills 到底怎么规范 token？② 本底座该怎么优化？
> 所有结论都标了**出处**（skill 文档 + 行号）或**实测数字**，没有"我觉得"。
>
> ⚠️ **本文是工程文档，不进世界书**（不进 prompt，零 token）。

---

## 0. 结论先行（三句）

1. **逐格矩阵不花 token** —— 它是 **T2 契约**，落点是工程文件（`状态表.yaml`），由**代码持有**。
   AI 不需要知道矩阵，AI 只需要知道结果（一个嫉妒值 / 一个封闭 flag）。
   **把规则算给 AI 看，等于让 AI 当运动员又当裁判** —— 那是原卡的病根。
2. **skills 对 token 的正规答案不是「把内容写短」**，是**三条策略**（SKILL.md:12-17 原文）：
   **结构化表达** ＋ **MVU 变量** ＋ **关键词匹配 / EJS 语句**。
3. **本底座最大的 token 风险不是女角，是 `剧情线.md`（27,352 字符）** ——
   它必须按**天**拆 + `@@if` 当前日期，否则一条就吃掉全部预算。

## 1. skills 的权威口径（原文）

### 1.1 三条策略（`SKILL.md` 第 12-17 行，原文）

> 角色卡本质上是一套专门针对角色扮演的 AI 提示词工程。其中蕴含一对矛盾：
> 角色扮演需要丰富的细节设定来维持人设一致性，而 AI 提示词则要求简洁、准确的表述以节省 token。
> 因此采用三种策略解决这一矛盾：
> - **结构化表达**：压缩信息量
> - **MVU 变量**：追踪最新状态
> - **关键词匹配 / EJS 语句**：控制发送给 AI 的内容
> - **规划同步原则**：`创作规划.yaml` 是项目级事实来源

### 1.2 条目的 `scope` 与策略推导（`references/configuration.md`）

| 条文 | 位置 | 含义 |
|---|---|---|
| `scope 最小化`：默认 `specific`（仅相关时激活），只在**角色速览 / 地理速览**等需要全局常驻时用 `catalog` | entries-dynamics-style.md:29 | 索引才常驻 |
| `catalog` → **始终 constant，且不参与同 part 计数** | configuration.md:46 | 速览不会把其他条目推向常驻 |
| 阈值 `Infinity` = 常驻；`0` = 关键词触发；`null` = 禁用；**`>0` = 同 part 条目数 ≥ 阈值则转 selective，否则常驻** | configuration.md:33-38 | **条目越多越省**（反直觉但成立） |
| **EJS 条目（`@@if` 前缀）在同 part 中最多计为 1** | configuration.md:49 | ★ 15 个女角全走 EJS → 只计 1 |
| `rephrase` 条目不参与计数 | configuration.md:49 | — |
| ★ **`group.use_priority`：组内只激活权重最高的条目，其余抑制。规范原文用途写的是「互斥设定变体」** | configuration.md:153-155 | ★ 原生互斥实现 |
| `group.use_scoring`：组内条目评分竞争，最佳匹配被选中 | configuration.md:155 | 备选 |
| `effect.sticky / cooldown / delay`：按楼层控制生命周期 | configuration.md:140-146 | 控制"注入多久" |

| 「信息量足够时才拆为独立条目，判据：独立成段是否更清晰？**是否需要通过条目显隐控制 token？**」 | geography.md:22 | ★ 拆条目的官方理由就是 token |

### 1.3 写作层三条硬约束（`references/rules-check.md`）

| 约束 | 位置 | 对本底座的影响 |

### 5.1 本轮附带修掉的 YAML 缺陷（重要）

`状态表.yaml` / `目的清单.yaml` **此前从未被机器解析过** —— 本轮跑 YAML 解析器，踢出 3 类共 12 处：

| 类 | 例子 | 后果 |
|---|---|---|
| 值以 `**` 开头 | `意义: **机制**……` | YAML 把 `*` 当**别名** → 整份文件解析失败 |
| 值带续行但没写 `\|` | `意义: **X** —— …` + 下一行 | 值被截断 |
| flow map 用全角逗号 | `{鸣泽唯: 3，筱原泉: 12}` | `，` 不是分隔符 → **整串变成一个键** |

**四份工程文件（状态表 / initvar / 目的清单 / 地理速览）现在全部可机器解析** ✅
（每份都加了引号或改成 block scalar，**语义未改**）

> ⚠️ **这是一条通用教训**：**工程文件也要跑解析器**。
> 契约文件是给代码读的，YAML 不合法 = 引擎读不到 = 契约等于不存在。
