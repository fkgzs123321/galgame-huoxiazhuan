# MVU 条目前缀审计 · 欲妈群（2026-09-22）

**规范出处**：`.skills/tavern-cards/references/conventions.md` →「条目名称前缀 / 双 AI 发送路由」

| 前缀 | 发送目标 |
|---|---|
| `[mvu_plot]` | **只**发给剧情 AI |
| `[mvu_update]` | **只**发给变量更新 AI |
| **无前缀** | **发给两个 AI** |
| `[InitVar]` | MVU 检索初始变量；实现是 `comment.toLowerCase().includes('[initvar]')` → **大小写不敏感** |

**MVU 的过滤实现（bundle 原文，额外模型模式下）**

```js
_.remove(t, e => {
  const t = ut.test(e.comment);   // [mvu_update]
  const n = pt.test(e.comment);   // [mvu_plot]
  return (t || n) && r.add(e.world),
    o.is_extra_analysis ? (n && !t) : (!n && t);
})
```

⇒ **`[mvu_plot]` 条目会被从变量模型的上下文里删掉**；**无前缀条目保留**（两个 AI 都收到）。

## 审计结论

| 项 | 判定 |
|---|---|
| `[mvu_plot]` × 19 | ✅ 正确 |
| `[mvu_update]` × 2（变量更新规则／变量输出格式） | ✅ 正确 |
| `[initvar]初始(别开)(勿动)` | ✅ 正确（大小写不敏感） |
| `[文风]` × 6（关灯，不计入） | ✅ 无关紧要 |
| **`[总控]` ×3、`[世界观]` ×1、`[场景]` ×1、`[事件]` ×1、`[规则]` ×1** | ❌ **自造前缀不在规范里 → MVU 视为「无前缀」→ 也发给变量模型** |
| **角色档案 84 条 ＋ `玩家档案`（无前缀）** | ❌ 纯剧情内容，却同样发给变量模型 |
| `MVU变量列表`（无前缀） | ⚠️ 它是**给变量模型**的清单，却无前缀 → 反而白占剧情 AI |

## 建议改法：改 packer 加前缀，**不动条目键名**

在 `pack_yumq.mjs` 的 `buildEntries()` 里只给 `comment` 加前缀，
**state／entryManifest／文件名一律不改** → `classify()`、`parseArchiveType()`、`BLUE_LIGHT_ORDER`、`GREEN_LIGHTS`
的名字匹配全部不受影响：

| 范围 | 改动 |
|---|---|
| 角色档案 84 ＋ `玩家档案` | `comment = '[mvu_plot]' + name` |
| 5 个自造前缀条目 | `comment = '[mvu_plot]' + name`（如 `[mvu_plot][总控]剧情与事件`） |
| `MVU变量列表` | `comment = '[mvu_update]' + name` |
| 已带规范前缀的 22 条 | 原样不动 |

**已验证安全**：全库没有 `getwi` 之类的「按条目名硬引用」（D0 里出现的那两处是注释）。

**依据**：skills 明确要求「分析 schema.ts，识别与追踪内容不相关的条目，**询问用户**是否添加 `[mvu_plot]` 前缀以优化双 AI 发送路由」→ 所以此项待用户拍板。
