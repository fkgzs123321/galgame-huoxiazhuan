**方法**：把面板里的真公式抄进脚本，穷举 `Day1-17 × 24小时 × 10回合 × 5动作` 跑分布。不是印象，是算出来的。

## 一、确定性骰子：**是坏的**（两个数学 bug，已修）

### bug ① 浮点精度丢失
```js
// 原式
function lcg(seed){ var x=(seed*1103515245+12345)%2147483648; ... }
```
`seed = day*1000000 + hour*10000 + …` → day 到 100 时 seed ≈ 1e8 →
`1e8 × 1103515245 = 1.104e17`，**远超 2^53 = 9.007e15** → 双精度丢位 → 结果错乱。

实测：seed 在 1e6 量级（Day≈1）时原式与正确式**完全一致**（所以现在没炸）；
seed 到 1e8 量级（Day≥100，而本卡 `高考日=100` 正是设计终点）时 **1875/2000 结果不一致**。

### bug ② 「三轮骰」其实只有一种结果 ⚠️⚠️
```js
function rollAt(base,kn){ return (lcg(base+kn*97)%20)+1; }
```
LCG 对相邻 seed 的差模 2³¹ 是常数 → `%20` 后几乎不变。

**实测（1997 个 base）**：

| 方案 | 三轮组合种数（理论 8000） | 单轮取值数 |
|---|---|---|
| 原式 `(b+k*97)%20` | **1** | 1/20 |
| imul + 低位 %20 | 15 | 5/20 |
| **imul + murmur3 收尾混合** | **1792** | **20/20** |

⇒ **原实现里三次投掷永远相同** —— "三轮判定"等于只掷了一次。这是最严重的一处。

### 已修（写进面板）
```js
function lcg(seed){ var x=(Math.imul(seed,1103515245)+12345)%2147483648; if(x<0)x+=2147483648; return x; }
function mix32(x){ x=Math.imul(x^(x>>>16),2246822507); x=Math.imul(x^(x>>>13),3266489909); return (x^(x>>>16))>>>0; }
function rollAt(base,kn){ return (mix32(lcg(base)+kn*7919)%20)+1; }
```
仍是**纯函数**（同一个「日数/小时/回合/动作序号」永远同一结果）→ 防 SL 大法这条设计保住了 ✓

## 二、聚合规则：不科学（建议改）

现行：
```js
bad≥2 → 大失败 ；  good≥2 → 大成功 ；  否则取 grades[1]
```
两个毛病：

1. **「大失败」被放大**：每轮失败率本就约 50%，三轮里 ≥2 轮失败 ≈ 50% → **大失败成了常态**。
   实测（开局）：大失败 **75%**。而大失败的后果是 `警觉 +15` → 跑两次就爆表触发暴露。
2. **「成功」这一档永不出现**：要三轮里恰好有值落在 16~19 的窄带 → 实测 0.0% → **5 档退化成 4 档**。

**建议的聚合**：主档取**三轮 (投掷+修正) 的中位**；只有**三轮全差才大失败、三轮全好才大成功**。

实测对比（行动 · DC10）：

| 时期 | 现行：大失败/成功/大成功/不失败 | 建议：大失败/失败/部分/成功/大成功 → 不失败 |
|---|---|---|
| 开局 | 75% / 0% / — | **19.1 / 30.9 / 32.8 / 14.2 / 2.9 → 50.0%** |
| 中期 | 35% / 0% / — | **2.5 / 17.2 / 34.3 / 26.0 / 20.1 → 80.4%** |
| 后期 | 23% / 0% / — | **1.5 / 16.2 / 29.4 / 24.0 / 28.9 → 82.4%** |

✓ 五档齐了 ✓ 大失败回到"罕见事件" ✓ 成长曲线出来了（50% → 80%）

## 三、修正公式：零点没标定

现行（开局代入）：
```
m1 = 勇气/10 − 兴奋/20 − 理智/20        = 5 − 0 − 5   = 0
m2 = 技/5 + 痴迷/10 − DC                = 2 + 0 − 12  = −10   ← 轮2 必败
m3 = 兴奋/10 + 勇气/20 − 意志/5 − 信任/10 = 0 + 3 − 3 − 6 = −6   ← 轮3 恒负
```
- `m2` 里的 `− DC` 量级（12~22）压过了 `技/5`（最大 20）→ 开局 **必然 94.6% 失败**
- `m3` 里 `− 信任/10`（她信任初始 60 → −6）是**固定惩罚** → 轮3 长期为负
- 结果：**开局的「观察」实测 100% 大失败**、「行动/拒绝」97% 大失败

**建议重标**（三项都以 0 为锚，随进度向两边分化）：
```
m1 = round((她的勇气 − 他的观察) / 12)
m2 = round((他的技能 − DC) / 2) + round(她的痴迷 / 20)
m3 = round((她的兴奋 − 他的意志) / 12)
```
开局三项 ≈ 3 / 0 / −1 ✓ 由骰子决定；后期 m2 能到 +30 ✓ 成长有回报。

## 四、难度：**完全没接进判定**

`元数据.难度` 在判定代码里**一次都没被读**（全库只有 `DEFAULT_STAT` 与面板渲染两处）。
玩家在开局表单选的难度，对"我能不能拦住她"**零影响** —— 而这是玩法的核心动作。

**建议**：`m2` 直接吃难度修正 → 普通 `+2` / 困难 `0` / 地狱 `−3`（比改 DC 明显得多）。
（DC × 系数 0.8/1.0/1.3 实测只挪动 3~4 个百分点，手感几乎没有。）

## 五、技能设置与成长

| 项 | 现状 | 问题 |
|---|---|---|
| 三项初值 | 观察 10 / 行动 8 / 意志 15 | 都低于 DC（12/10/12）→ 修正是负的 |
| 成长 | `对应行为 +1~+3`，上限 100 | 17 天内从 10 长到 40 需要 **10~15 次成功判定**，而开局成功率仅 ~17% → **成长形同虚设** |
| 收益传导 | 技能只进 `m2`（轮2） | 若聚合取中位，轮2 的收益会被 m1/m3 **削平**（实测技能 40→100 时"好"率反而从 50% 掉到 32.8%） |

**建议**：
- 成长改 **+2~5 / 次**
- **主档取轮2（他这一下成不成）**，轮1/轮3 决定**代价强度**（警觉增量、是否被撞见、她的反应）→ 技能收益直接、三轮都有用，也符合「侦察/行动/反应」的叙事分工
