一、JSONPatch 标签铁律
═══════════════════════════════════════════════════════════
1. 所有变量变更必须通过 <UpdateVariable> 块中的 JSONPatch 操作完成
2. JSONPatch 操作符仅限：replace / add / remove / incvar
3. 路径必须以 / 开头，使用 stat_data 子路径（如 /角色.赵灵儿.好感度）
4. 数值型字段必须用 Number() 转换，字符串型必须用 String() 转换
5. 数组操作必须指定索引或使用 add 末尾追加
6. 禁止省略 op / path / value 任一字段
7. 单次 <UpdateVariable> 块内的 JSONPatch 操作数量上限为 20 条

二、10 种致命错误示例（禁止出现）
═══════════════════════════════════════════════════════════
错误 1：变量路径错误
  ✗ {"op":"replace","path":"/灵儿好感","value":50}
  ✓ {"op":"replace","path":"/角色.赵灵儿.好感度","value":50}

错误 2：省略必填字段
  ✗ {"op":"replace","path":"/当前章节","value":2}（缺 value 类型）
  ✓ {"op":"replace","path":"/当前章节","value":2}

错误 3：数值越界
  ✗ {"op":"replace","path":"/主角.HP","value":9999}（HP 上限 999）
  ✓ {"op":"replace","path":"/主角.HP","value":120}

错误 4：枚举值错误
  ✗ {"op":"replace","path":"/角色.赵灵儿.关系阶段","value":"深交"}
  ✓ {"op":"replace","path":"/角色.赵灵儿.关系阶段","value":"暧昧"}
  （合法枚举：初识/友好/暧昧/恋爱/结拜/敌对/决裂）

错误 5：类型不匹配
  ✗ {"op":"replace","path":"/主角.铜钱","value":"五百文"}
  ✓ {"op":"replace","path":"/主角.铜钱","value":500}

错误 6：操作符非法
  ✗ {"op":"set","path":"/章节进度","value":5}
  ✓ {"op":"replace","path":"/章节进度","value":5}

错误 7：数组路径错误
  ✗ {"op":"add","path":"/章节事件完成表","value":"灵儿被掳"}
  ✓ {"op":"add","path":"/章节事件完成表/-","value":"灵儿被掳"}

错误 8：incvar 用于非数值字段
  ✗ {"op":"incvar","path":"/角色.赵灵儿.关系阶段","value":1}
  ✓ {"op":"incvar","path":"/角色.赵灵儿.好感度","value":10}

错误 9：跨章节预修改
  ✗ 在第 1 章未完成时 {"op":"replace","path":"/当前章节","value":3}
  ✓ 仅由章节触发器在关键事件完成后执行章节切换

错误 10：主模型输出 <UpdateVariable> 块
  ✗ 主模型叙事后直接输出 <UpdateVariable>...</UpdateVariable>
  ✓ 主模型仅输出 <StatusPlaceHolderImpl>；<UpdateVariable> 由额外模型生成

三、6 项强制检查清单
═══════════════════════════════════════════════════════════
□ 检查 1：路径完整性
  - 所有 path 是否以 / 开头
  - 是否使用 stat_data 子路径规范（如 /角色.XXX.好感度）
  - 数组追加是否使用 /- 语法

□ 检查 2：数值钳制
  - HP 范围 [0, 999]
  - MP 范围 [0, 999]
  - 好感度范围 [0, 100]
  - 信任度范围 [0, 100]
  - 章节进度范围 [1, 60]
  - 当前章节范围 [1, 6]
  - 铜钱范围 [0, 999999]

□ 检查 3：枚举合法性
  - 关系阶段 ∈ {初识, 友好, 暧昧, 恋爱, 结拜, 敌对, 决裂}
  - 女娲血脉阶段 ∈ {凡胎, 灵脉, 女娲之力, 补天}
  - 时段 ∈ {晨, 午, 昏, 夜}
  - 战斗状态 ∈ {未战斗, 战斗中, 战斗结束}

□ 检查 4：操作符匹配
  - replace：必须提供 value（任意类型）
  - add：数组用 /- 追加，对象用新字段路径
  - remove：仅提供 path，不提供 value
  - incvar：仅用于数值字段，value 为整数（可负）

□ 检查 5：叙事-变量一致性
  - 叙事中描写的伤势是否对应 HP 变更
  - 叙事中描写的好感变化是否对应好感度 incvar
  - 叙事中描写的物品消耗是否对应物品 remove
  - 叙事中描写的场景切换是否对应 current_location 更新

□ 检查 6：铁律合规
  - 章节进度变更是否由章节触发器执行（非主模型）
  - 已死亡角色是否未被复活（未触发复活事件时）
  - 已完成事件是否未被撤销
  - 主模型是否未输出 <UpdateVariable> 块

四、增量 + 全量混合策略
═══════════════════════════════════════════════════════════
1. 增量更新（默认）：仅输出本楼层发生变化的字段，使用 incvar 或 replace
   - 适用：好感度 ±N、HP ±N、铜钱 ±N、灵力 ±N
   - 优势：token 节省，避免冗余传输

2. 全量同步（条件触发）：输出完整字段当前值，使用 replace
   - 触发条件：
     a) 章节切换时（章节进度/当前章节/解锁场景全量同步）
     b) 队伍成员变动时（队伍.成员全量同步）
     c) 角色关系阶段切换时（关系阶段/好感度/信任度全量同步）
     d) 变量异常检测后（修复偏差，全量覆盖错误值）
   - 优势：消除累积漂移，确保状态准确

3. 混合规则：
   - 增量为主：日常楼层默认增量
   - 全量为辅：关键节点全量同步
   - 禁止全量覆盖未变化的字段（避免 token 浪费）
   - 增量操作后须检查钳制范围，越界时自动钳制并全量修正

═══════════════════════════════════════════════════════════
五、防口胡总则
═══════════════════════════════════════════════════════════
1. 变量变更必须有叙事依据：禁止无叙事支撑的变量修改
2. 叙事必须反映变量状态：禁止变量已变但叙事未体现
3. 数值变化幅度须合理：单楼层好感度变化不超过 ±20，HP 变化不超过 ±50%
4. 禁止跳过中间状态：好感度从 0 直接到 100 不允许，须经历中间值
5. 禁止伪造未发生的事件：未在叙事中发生的事件不可写入「章节事件完成表」
