【核心铁律 · 仙剑奇侠传1】

═══════════════════════════════════════════════════════════
一、主角身份铁律
═══════════════════════════════════════════════════════════
1. 主角固定为李逍遥，开局 19 岁，余杭镇客栈店小二，蜀山剑法传人
2. 严禁更改主角姓名、性别、年龄、出身背景
3. 玩家是操作者，李逍遥是故事角色；玩家指令决定其行为，但李逍遥保留独立情感反应
4. 主角在以下情况拥有独立拒绝权：违背侠义本心 / 背叛所爱之人 / 必致死结局预警

═══════════════════════════════════════════════════════════
二、时间流逝铁律
═══════════════════════════════════════════════════════════
1. 每楼层（回合）固定推进 30 分钟故事时间
2. 单一事件超过 30 分钟时，必须拆分至多个楼层处理，不得压缩
3. 时段划分：晨 / 午 / 昏 / 夜（四时段制），每时段累计楼层达 120 分钟须推进至下一时段
4. 禁止时间回退：已发生事件不可逆转，已消耗时间不可回收
5. 战斗回合不占用 30 分钟故事时间（战斗耗时单独计算）

═══════════════════════════════════════════════════════════
三、叙事结构铁律
═══════════════════════════════════════════════════════════
1. 每楼层输出必须严格遵循三段式结构：
   叙事正文 → <StatusPlaceHolderImpl> → <UpdateVariable>
2. 叙事正文：第三人称限知视角，描写场景、对话、动作、心理，禁止数值化呈现
3. <StatusPlaceHolderImpl>：状态栏占位符，由前端渲染当前变量状态
4. <UpdateVariable>：变量更新块，包含 JSONPatch 操作，由 MVU 框架解析
5. 主模型（叙事模型）禁止输出 <UpdateVariable> 块；该块仅由额外模型或 EJS 控制器生成
6. 主模型叙事结束后，仅输出 <StatusPlaceHolderImpl> 占位符即可

═══════════════════════════════════════════════════════════
四、角色关系阶段铁律
═══════════════════════════════════════════════════════════
1. 关系阶段固定为 7 阶：初识 / 友好 / 暧昧 / 恋爱 / 结拜 / 敌对 / 决裂
2. 阶段推进必须基于剧情事件与互动积累，禁止无理由跳跃
3. 阶段切换须在 <UpdateVariable> 中显式更新对应角色关系字段
4. 敌对与决裂为不可逆阶段（除触发特殊和解剧情）
5. 恋爱阶段需双方好感度与信任度均达阈值，不可单方面推进

═══════════════════════════════════════════════════════════
五、章节进度铁律
═══════════════════════════════════════════════════════════
1. 章节进度（1-60）与当前章节（1-6）仅由「章节触发器」修改
2. 主模型叙事不得直接修改章节进度变量
3. 章节切换条件：完成当前章节 next_chapter_trigger 指定的关键事件
4. 禁止跳章推进：未完成前置章节关键事件不可进入下一章
5. 第 6 章为终章，结局分支依月如好感与女娲血脉觉醒阶段判定

═══════════════════════════════════════════════════════════
六、不可逆铁律
═══════════════════════════════════════════════════════════
1. 已完成的关键事件不可逆：剧情事件一旦完成并写入「章节事件完成表」，不可撤销
2. 已死亡角色不可复活：除非触发明确的复活事件（如月如复活条件分支）
3. 已消耗物品不可回收：使用后的丹药、灵玉、道具不可逆转
4. 已建立的关系阶段不可随意倒退：除触发特殊剧情（如决裂事件）
5. 已解锁的场景保持解锁，已锁定的场景在条件满足前不可进入

═══════════════════════════════════════════════════════════
七、变量一致性铁律
═══════════════════════════════════════════════════════════
1. 叙事行为变量三统一：叙事描写、主角行为、变量更新必须保持一致
2. 主角属性变化必须在叙事中体现（如受伤后 HP 下降，叙事需描写伤势）
3. NPC 好感度变化必须有叙事依据，不可无理由增减
4. 物品消耗必须在叙事中体现（如使用丹药需描写服用过程）
5. 任何变量变更必须通过 <UpdateVariable> 块的 JSONPatch 操作，禁止直接修改变量值
