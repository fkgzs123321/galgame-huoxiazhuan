# 仙剑奇侠传1 变量更新规则·额外模型专用

本条目规定额外模型在输出 `<UpdateVariable>` 块时必须遵守的规则与防口胡机制。
与 `变量输出格式_额外模型.txt` 配套使用，前者管"格式"，本文件管"规则"。

## 一、输出顺序铁律

每轮回复必须严格按以下顺序输出，不得调换：

1. **叙事正文**（≤ 1300 字，战斗场景 ≤ 1500 字，事件触发 ≤ 1400 字）
2. **`<StatusPlaceHolderImpl/>`**（单独一行，用于挂载本楼层状态栏）
3. **`<UpdateVariable>` 块**（如有变量变化，使用 JSONPatch 格式）

**铁律**：
- 主模型只输出 1 + 2，禁止输出 3
- 额外模型负责输出 3
- `<StatusPlaceHolderImpl/>` 必须在叙事正文之后、`<UpdateVariable>` 之前
- 不得调换顺序，不得省略占位符

## 二、JSONPatch 格式铁律

### 2.1 标签结构
```
<UpdateVariable>
<Analysis>
（思维链内容，六步分析）
</Analysis>
<JSONPatch>
[
  { "op": "replace|delta|insert|remove|move", "path": "/路径/字段", "value": 值 }
]
</JSONPatch>
</UpdateVariable>
```

### 2.2 路径规则
- **路径用斜杠分隔**，如 `/主角/HP`，**无 `stat_data` 前缀**
- 嵌套对象用斜杠递进：`/主角/资产/铜钱`
- 数组索引用数字：`/队伍/成员/0`（第一位成员）
- 数组 append 用 `/-`：`/世界/已完成事件/-`
- 路径区分大小写，与 schema.ts / initvar.yaml 严格对齐

### 2.3 操作类型
- `replace`：替换已有路径的值（value 类型必须与 schema 一致）
- `delta`：数值增减（value 必须是数字，正=增、负=减）
- `insert`：向对象/数组插入新项
- `remove`：删除路径节点
- `move`：移动路径节点（需 `from` 字段）

### 2.4 值类型约束
- string：用双引号包裹，如 `"仙剑历0001年01月01日"`
- number：整数或浮点数，如 `30`、`-15`
- boolean：`true` / `false`
- null：`null`（清空字段）
- array：方括号包裹，如 `["李逍遥", "赵灵儿"]`
- object：花括号包裹，如 `{ "武器": "木剑", "防具": "布衣" }`

## 三、增量+全量混合策略

### 3.1 增量更新（默认）
- 数值变化用 `delta`：`{ "op": "delta", "path": "/主角/HP", "value": -15 }`
- 状态切换用 `replace`：`{ "op": "replace", "path": "/战斗/战斗状态", "value": "胜利" }`
- **有变化才输出**：未变化的字段不输出，避免冗余

### 3.2 全量更新（特殊场景）

以下变量必须每轮全量输出当前值（即使未变化）：

#### 3.2.1 时间变量（每轮必须输出）
- `/时间/游戏日期`
- `/时间/时段`
- `/时间/当前时间`
- `/时间/天数`
- `/时间/天气`
- `/时间与位置/游戏日期`
- `/时间与位置/时段`
- `/时间与位置/当前地点`

#### 3.2.2 战斗状态变量（战斗中每轮必须输出）
- `/战斗/敌方名称`
- `/战斗/敌方HP`
- `/战斗/敌方MaxHP`
- `/战斗/回合数`
- `/战斗/是否BOSS战`
- `/战斗/战斗状态`

#### 3.2.3 当前场景人物的所有字段（每轮必须全量输出）
- 当 `场景.当前地点` 中有可交互角色时，该角色的所有字段必须每轮全量输出
- 例如：当前地点为"仙灵岛"且有赵灵儿时，`/角色/赵灵儿/*` 全量输出：
  - `/角色/赵灵儿/好感度`
  - `/角色/赵灵儿/关系阶段`
  - `/角色/赵灵儿/是否加入队伍`

#### 3.2.4 NSFW 静态字段（NSFW 场景中每轮必须输出当前值）
- 当触发 NSFW 场景时，相关角色的 NSFW 静态字段必须每轮全量输出当前值
- 包括：当前衣着、暴露程度、湿润度、兴奋度、精液残留、全身敏感度等
- 即使数值未变化，也必须输出当前值（用于状态栏同步）
- **注**：本规则在 NSFW 场景触发时生效；非 NSFW 场景可省略

### 3.3 章节切换时的全量同步
- 章节切换时，以下变量必须全量输出：
  - `/场景/当前章节`
  - `/场景/章节进度`
  - `/世界/当前章节`
  - `/世界/章节进度`
- 同时 `insert` 新完成的关键事件到 `/世界/已完成事件/-`

## 四、防口胡机制（强制校验）

### 4.1 JSONPatch 标签铁律
1. `<UpdateVariable>` 与 `</UpdateVariable>` 必须成对出现，不得省略闭合标签
2. `<Analysis>` 与 `</Analysis>` 必须成对出现
3. `<JSONPatch>` 与 `</JSONPatch>` 必须成对出现
4. JSON 数组必须用方括号 `[ ]` 包裹
5. JSON 对象必须用花括号 `{ }` 包裹
6. JSON 字符串必须用双引号 `" "` 包裹
7. JSON 末尾不能有逗号
8. 数组元素之间用逗号分隔
9. 路径必须以 `/` 开头
10. `delta` 操作的 value 必须是数字（不得是字符串）

### 4.2 十种致命错误示例（违反则触发截断/警告）

#### 错误 1：路径前缀错误
```
❌ { "op": "delta", "path": "stat_data/主角/HP", "value": -15 }
✅ { "op": "delta", "path": "/主角/HP", "value": -15 }
```
**原因**：路径不得包含 `stat_data` 前缀

#### 错误 2：delta value 类型错误
```
❌ { "op": "delta", "path": "/主角/HP", "value": "-15" }
✅ { "op": "delta", "path": "/主角/HP", "value": -15 }
```
**原因**：delta 的 value 必须是数字，不得是字符串

#### 错误 3：JSON 末尾逗号
```
❌ [ { "op": "replace", "path": "/时间/时段", "value": "午" }, ]
✅ [ { "op": "replace", "path": "/时间/时段", "value": "午" } ]
```
**原因**：JSON 末尾不能有逗号

#### 错误 4：路径错误（数组索引）
```
❌ { "op": "replace", "path": "/队伍/成员/李逍遥", "value": "李逍遥" }
✅ { "op": "replace", "path": "/队伍/成员/0", "value": "李逍遥" }
```
**原因**：数组索引用数字，不得用键名

#### 错误 5：value 类型不匹配
```
❌ { "op": "replace", "path": "/主角/HP", "value": "100" }
✅ { "op": "replace", "path": "/主角/HP", "value": 100 }
```
**原因**：HP 是 number 类型，value 必须是数字

#### 错误 6：超出单轮变化上限
```
❌ { "op": "delta", "path": "/角色/赵灵儿/好感度", "value": 50 }
✅ { "op": "delta", "path": "/角色/赵灵儿/好感度", "value": 5 }
```
**原因**：好感度单轮上限 ±5（关键剧情 ±10），超出会被截断

#### 错误 7：缺少前置条件
```
❌ { "op": "replace", "path": "/角色/赵灵儿/关系阶段", "value": "恋爱" }
✅ { "op": "replace", "path": "/角色/赵灵儿/关系阶段", "value": "友好" }
```
**原因**：关系阶段跳跃需满足阈值（恋爱需好感度≥60+信任度≥50），当前好感度 0 不可跳跃

#### 错误 8：章节跳章推进
```
❌ { "op": "replace", "path": "/场景/当前章节", "value": 3 }
（当前章节 1，未完成第2章前置事件）
✅ { "op": "replace", "path": "/场景/当前章节", "value": 2 }
```
**原因**：未完成前置章节关键事件不可跳章推进

#### 错误 9：缺少 `<StatusPlaceHolderImpl/>`
```
❌ （叙事正文后直接输出 <UpdateVariable>）
✅ 叙事正文 → <StatusPlaceHolderImpl/> → <UpdateVariable>
```
**原因**：状态栏占位符必须在 UpdateVariable 之前

#### 错误 10：主模型输出 `<UpdateVariable>`
```
❌ 主模型输出：叙事正文 + <StatusPlaceHolderImpl/> + <UpdateVariable>
✅ 主模型输出：叙事正文 + <StatusPlaceHolderImpl/>
   额外模型输出：<UpdateVariable>
```
**原因**：主模型禁止输出 `<UpdateVariable>` 块，该块仅由额外模型生成

### 4.3 六项强制检查清单（AI 思维链必须逐条确认）

每次输出 `<UpdateVariable>` 前，额外模型必须在 `<Analysis>` 中逐条确认：

1. **路径检查**：所有 path 是否以 `/` 开头？是否无 `stat_data` 前缀？是否与 schema.ts / initvar.yaml 对齐？
2. **类型检查**：所有 value 类型是否与 schema 一致？delta 的 value 是否为数字？
3. **幅度检查**：所有数值变化是否在单轮上限内？（HP ±30 / 属性 ±5 / 好感度 ±5 / 铜钱 ±5000）
4. **门槛检查**：是否满足前置条件？（关系阶段阈值/章节切换条件/技能门槛/法术灵力门槛）
5. **全量检查**：时间/战斗状态/当前场景人物字段是否每轮全量输出？
6. **结局检查**：是否触发死结局预警？是否进入结局分支？是否需要章节切换？

### 4.4 违规处理

- 违反铁律的 JSONPatch 操作将被 EJS 控制器截断并返回警告
- 严重违规（如跳章推进、超限变化、缺少前置条件）将触发防口胡机制
- 触发防口胡机制时，变量更新被阻止，并记录到 违规日志
- 连续 3 次违规将触发 `临时.死结局标识 = 'BAD_END_8_时空调度异常'`

## 五、其他规则

### 5.1 无变更时不输出
- 当本轮无任何变量变化时，不输出 `<UpdateVariable>` 块
- 仅输出叙事正文 + `<StatusPlaceHolderImpl/>`

### 5.2 多操作合并
- 单轮内多个变量变化合并到一个 `<JSONPatch>` 数组中
- 不得输出多个 `<UpdateVariable>` 块

### 5.3 思维链要求
- `<Analysis>` 必须按六步分析输出（事件/数值/门槛/章节/队伍/结局）
- 每步一行，中文，简明扼要
- 不得省略任一步骤

### 5.4 与主模型的关系
- 额外模型解析主模型叙事正文，提取变量变化
- 变量变化必须与叙事正文一致（叙事描写、主角行为、变量更新三统一）
- 不得输出与叙事正文无关的变量变化

### 5.5 与 EJS 控制器的协作
- 额外模型输出的 JSONPatch 由 MVU 框架解析后写入 stat_data
- EJS 控制器在下一轮生成时读取最新 stat_data 进行条件判定
- 若 EJS 控制器检测到违规，将截断变量更新并返回警告
