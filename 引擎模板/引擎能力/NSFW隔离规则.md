# NSFW 引擎的隔离规则

> 用户定的：**NSFW 应该是一个单独的通用引擎，跟其他的要分开**。
>
> 这一条不是风格偏好，是**架构约束** —— 混起来的后果是具体的：
> NSFW 的词会渗进判定/成长/物品引擎，于是那些引擎就不能给一张清水卡用了。

---

## 一、隔离的四条

### ① 文件隔离
**`NSFW引擎.txt` 是单独一份，别的引擎里不许出现 NSFW 专属词。**

判据词表（改引擎后复跑 `node scripts/audit-engine-isolation.mjs`）：
```
怀孕 罩杯 三围 乳房 乳头 阴 性爱 做爱 插入 精液 射精 高潮 勃起
湿润度 敏感度 后庭 脱衣 全裸 暴露 发情 腿交 口交 下体 情色 色情 裸
```

### ② 依赖隔离 —— **它是自包含的**

```
      判定引擎    成长引擎    战斗引擎    物品引擎    状态引擎    任务引擎
           \          |          |          |          |          /
            \         |          |          |          |         /
             └────────┴──────────┴────┬─────┴──────────┴────────┘
                                      │
                            【变量层 / 契约层】  ← 汇合点
                                      │
                                NSFW引擎
                            （不依赖任何其他引擎）
```

★ **两种做法里，我们选了后者**：
- ✗ 让 NSFW 引擎 import 判定引擎（「兴奋度影响成功率」）→ 它就得知道判定怎么算
- ✓ **两个引擎都自包含，在变量层汇合** —— 判定引擎读「某个值」，NSFW 引擎写「某个值」，
  **谁都不知道对方是谁**

★ 这样做的额外好处：**摘掉 NSFW 引擎，其余六个照常运行**（清水卡直接删这一个文件就行）。

### ③ 变量隔离 —— 变量分块，不交叉

```
stat_data:
  ...
  她: {...}          角色状态
  局面: {...}        判定/战斗的交接台
  NSFW:              ★ 单独一块
    穿着: {}
    身体: { 基线: {}, 即时: {} }
    兴奋度: 0
    周期: {}
```

★ **别的块里不出现 NSFW 字段**。特别是：
- `她.兴奋度` 属 NSFW 块 → 移进 `NSFW.兴奋度`
- 判定引擎要读兴奋度时，**从 `NSFW.兴奋度` 读**（读得到的，但那是它的输入参数，不是它的内部）

### ④ 条目隔离 —— NSFW 条目单独归类

**关键词要能一眼分开**：
| | 触发词 |
|---|---|
| 普通条目 | 门派/地点/人物/功法 |
| **NSFW 条目** | 只在 NSFW 场景才出现的词 |

★ **别让普通条目里夹 NSFW 内容** —— 那会让一张清水卡也在上下文里带着这些字。

---

## 二、例外：契约层的「接口声明」是允许的

引擎之间**完全不知道对方**，但**契约层要知道**。所以：
- `NSFW契约表.yaml` 里可以有 `接口:` 一节，写明
  「她兴奋度高会降低判定成功率 —— 但那件事在判定引擎里算，这里只管她现在什么状态」
- ★ 这是**声明**，不是**耦合**：契约层是给人和 AI 看的，不是给引擎读的

---

## 三、复跑检查

```bash
node scripts/audit-engine-isolation.mjs
```
五项：
1. NSFW 引擎存在且独立
2. 其他六个引擎**零 NSFW 词**
3. NSFW 引擎**不引用其他引擎的函数名**（自包含）
4. 变量块 `NSFW` 独立存在，且其他块不含 NSFW 字段
5. 引擎清单与契约清单对得上

★ **改任何一个引擎之后都要跑一遍** —— 这条和「改 initvar 要重跑 gen-schema」是同一类纪律：
**动了一处，要回头验另一处。**
