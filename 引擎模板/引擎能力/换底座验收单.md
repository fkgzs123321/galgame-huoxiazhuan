# 换底座验收单

> 用户问：**引擎和机制层齐了？以后换其他游戏的底座，也能不用动机制层了？**
>
> 不能拍胸脯回答。这份是**拿别的题材逐个填一遍**，看填不进去的地方在哪。

---

## 一、先分清「换底座要动什么」——三类，性质不同

| 层 | 换底座要不要动 | 为什么 |
|---|---|---|
| **机制层（7 个引擎 + 引擎.js）** | ❌ **不用动** | 纯算法，全部参数化 |
| **契约层**（底座_xxx 的表） | ✅ **必须重填** | 它的职责就是「这个世界的值」 |
| **基线层**（schema / initvar / 开场白 / 结局 / 关卡序列） | ✅ **要改** | 每张卡自己的骨架 |

★ 提醒：**契约层和基线层要动，不是缺陷，是它们的本职。**
真正的验收标准只有一条：**机制层一个字都不用改。**

---

## 二、机制层现状实测

拿 40 个底座专属词（门派名 / 地名 / 人角名 / 属性名 / 衣物名）扫七个引擎：

```
✅ 判定引擎.txt   零底座内容
✅ 战斗引擎.txt   零底座内容
✅ 物品引擎.txt   零底座内容
✅ 状态引擎.txt   零底座内容
⚠️ 成长引擎.txt   注释里提了「英雄坛说」（说明为什么加 C5）
⚠️ 任务引擎.txt   注释里提了「英雄坛说」（说明为什么加 E9）
⚠️ NSFW引擎.txt   注释里举例「武侠看里衣」（说明参数可换）
```

**三处全在注释里，不在代码里。** 判断：
- **代码里的底座词** = 真耦合，必须改
- **注释里的底座词** = **设计依据的出处**，有保留价值（后人知道为什么这么设计）

→ **保留**，但在审计脚本里把「代码」和「注释」分开算，别混为一谈。

## 三、★ 拿五个题材逐个填（真正的验收）

把机制层需要的参数，用各题材填一遍，看**能不能填进去**：

| 机制层能力 | 仙侠 | 火影 | 哈利波特 | 魔兽 | 海贼 |

### ★ 结论：**14 项能直接填，2 项填不进去**

| 缺口 | 谁需要 | 状态 |
|---|---|---|
| **① 关系网（E15）** | 五个题材**全都要** | ❌ **没做** |
| **② 多单位战斗** | 火影（影分身）・魔兽（副本）・海贼（船战） | ❌ **没做** |

**其余 14 项，机制层一个字都不用改** —— 只换契约层的值。

## 四、所以诚实的答案是

**「齐了，但差两样」**：

| | 状态 |
|---|---|
| 机制层 7 引擎 + 引擎.js 的**算法** | ✅ 零底座内容，换题材不用动 |
| 14 项能力的**参数化** | ✅ 全部可由契约覆盖 |
| **E15 关系网**（人物之间成对关系） | ❌ **缺 —— 五个题材全都要** |
| **多单位战斗**（1vN / NvN） | ❌ **缺 —— 三个题材要** |

★ 还有个**必须说清的前提**：
「不用动机制层」成立的前提是**表结构够用**。表结构不够时，就要动机制层。
上面这张表就是**逐个题材查表结构**的结果 —— 查出来差两个。

## 五、下次换底座的操作清单（照这个做就不会漏）

```
1. 复制 引擎模板/引擎能力/*.txt → 新项目 机制/
2. 引擎.js 不用改（CDN 共用一份）
3. 改 schema.ts 的 世界.底座 enum
4. 重填 契约层（底座_xxx/），照表的字段要求填
5. 重写 基线层（initvar / 开场白 / 结局 / 关卡序列）
6. 复跑 6 份引擎测试 → 应全绿（它们测的是机制层，与底座无关）
7. 跑 scripts/audit-engine-isolation.mjs + audit-engines.mjs
```

★ 第 6 条是关键验收：**引擎测试全绿 = 机制层没被底座污染**。
如果某个测试因为换了底座而挂，那个测试本身就写耦合了。
