# 引擎层 · 分层判定书

> 用户问：**功法/技能、属性成长、物品、品质等级**，这四个通用框架能不能升级到通用层？
>
> 判断依据是那三条判据（逐级收紧），**不是感觉**：
> 1. **换底座还成立吗？** 不成立 → 底座层
> 2. **含不含「具体内容」？** 含 → 要素（契约层/底座层）
> 3. **是否为别的功能提供能力？** 是 → 引擎层
>
> ⚠️ **判据 2 最容易错** —— 很多「听起来很通用」的东西裹着具体内容。
> 记过的例子：**怀孕系统不是机制**。机制层只提供「带周期的可累加状态」，机制层里不该出现「怀孕」二字。

---

## 一句话结论

| 框架 | 判据1 换底座成立 | 判据2 含具体内容 | 判据3 为别的功能提供能力 | **判定** | 现状 |
|---|---|---|---|---|---|
| **功法/技能** | ✅ | 能力通用，**清单**是要素 | ✅ 供判定与战斗读 | **引擎层（已有）** | ✅ C1/C2 在，**缺「解锁条件」** |
| **属性成长** | ✅ | 同上 | ✅ 供判定读 | **引擎层（已有）** | ✅ C1/C2 在 |
| **物品** | ✅ | 能力通用，**物品**是要素 | ✅ 供战斗/交易/任务读 | **引擎层（该有但没有）** | ❌ 缺 |
| **品质等级** | ✅ | 能力通用，**档位名**是要素 | ✅ 供掉落/强化读 | **引擎层（该有但没有）** | ❌ 缺 |

---

## 逐个拆解

### 一、功法 / 技能

**拆成三件，看各自落在哪一层：**

| 拆出来的东西 | 判据 | 落哪层 |
|---|---|---|
| 「等级 + 递增成本 + 上限」这种状态形状 | 换底座成立、不含内容 | ✅ **引擎层**（C1，已有） |
| 「甲每涨 N 档，乙 +1」这种跨状态级联 | 换底座成立、不含内容 | ✅ **引擎层**（C2，已有） |
| 「A 与 B 同时到某级 → 解锁 C」 | 换底座成立、不含内容 | ✅ **引擎层**（**缺，本轮补 C5**） |
| 具体是哪十种基本武功、哪派给哪招 | 含内容 | 契约层 `门派表.yaml` |
| 练到多少级解锁什么 | 含内容 | 契约层 `成长公式表.yaml` |

★ **判据 3 的关键**：绝招不是独立等级 —— 它是「两门武功同时到某个级数之后自动可用」。
**这个形状是通用的**（任何底座都能用「双条件解锁」），值才是要填的。
→ 所以补 **C5 解锁条件**。

### 二、属性成长

和技能同一套骨架：**离散状态 + 反哺 + 上限 + 派生**。
- 「反哺」是 C2 的实例（技能 → 属性）
- 「派生」是 C4 的实例（属性 → 攻击/命中/闪避）
- **已经在引擎层了** ✅

★ 需要注意的是：**属性本身也含内容**（哪四个属性、初始值多少）→ 那些在 `状态表.yaml` 与 `成长公式表.yaml`。

### 三、物品

**拆：**

| 拆出来的东西 | 判据 | 落哪层 |
|---|---|---|
| 「装备槽 + 加成叠加 + 上限夹紧」 | 换底座成立、不含内容 | ✅ **引擎层**（**缺，本轮补 E7**） |
| 「消耗品用完即减，减到 0 触发后果」 | 同上 | ✅ **引擎层**（E7） |
| 「背包是容量有限的集合」 | 同上 | ✅ **引擎层**（E7） |
| 具体是哪把刀、几点攻击、几文钱 | 含内容 | 契约层（物品表） |

★ 判据 3：物品为**战斗**（装备加成进派生）、**经济**（买卖）、**任务**（交东西）提供能力。
→ 它**不是**某一个玩法的私产，所以该进引擎层。

### 四、品质等级

**拆：**

| 拆出来的东西 | 判据 | 落哪层 |
|---|---|---|
| 「同一个东西按品质分档，档位越高越好」 | 换底座成立、不含内容 | ✅ **引擎层**（**缺，本轮补 E8**） |
| 「掉落按权重随机，权重受某状态修正」 | 同上 | ✅ **引擎层**（E8） |
| 「强化是在同一件东西上累加」 | 同上 | ✅ **引擎层**（E8） |
| 具体几档、各叫什么名（凡品/良品/珍宝…） | 含内容 | 契约层（品质表） |

★ **品质和「她开挂」的接口**：福缘影响掉落概率 —— 那是 E8 的输入参数，
而「她改数值」是 E6 的手段。两者在**变量层**相遇，引擎层不互相知道。

---

## 补的方式（和 C1-C4 一样）

1. 引擎层：`引擎模板/引擎能力/` 下新增两个模块（不含任何内容）
2. 契约层：英雄坛说在 `底座_yingxiong/` 下填三张表（物品表 / 品质表 / 解锁表）
3. 面板：把新能力接进 UI（装备、强化、掉落显示）
4. 测试：`test-items.mjs` 断言

★ 铁律不变：**引擎层不出现任何游戏专有名词**（不出现「刀」「符文」「福缘」这类词，它们全走 cfg 参数）。
