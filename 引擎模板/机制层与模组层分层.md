# 机制层与模组层 · 分层判据

> 用户的直觉：「机制层做通用的（时间地点事件推进、NSFW、怀孕系统、技能、属性），
> 模组层填要素就好。」
>
> **方向对。但列举的 5 个例子全是「半成品」——每个都要切一刀。**
> 本文给判据、逐例判断、并按 skills 验证。

---

## 一、判据（三条，逐级收紧）

| # | 判据 | 说明 |
|---|---|---|
| **1** | **换一个底座，它还成立吗？** | 成立 → 候选机制层；不成立 → 要素 |
| **2** | **它含不含「具体内容」？** | 含（「怀孕」「密室」「八十八町」）→ **要素**；不含（「状态机」「判定引擎」）→ 机制层 |
| **3** | **它是不是给别的功能提供能力？** | 是（被多处复用）→ 机制层；只服务一个功能 → 回到判据 1 |

**这三条里，判据 2 是最容易做错的一条。** 很多听起来「很通用」的东西，其实裹着具体内容。

## 二、你举的 5 个例子 · 逐个判断

### 2.1 时间 / 地点 / 事件推进 → **切一刀**

| 部分 | 归属 | 为什么 |
|---|---|---|
| **时间推进器**（谁在推、能不能停、推一步消耗什么） | **机制层** | 任何叙事卡都要时间前进；`round / 时段 / 天` 只是参数 |
| 「时间切成几段」（回合？5 时段？17 天？） | **要素**（契约里声明） | euphoria 用「层」，同级生2 用「5 时段 × 17 天」 |
| **地点容器**（区域 → 场景的两级结构、在场名单查询） | **机制层** | `getAvailableHeroines(day, slot, region)` 是**能力** |
| 「有哪些地点、谁在哪里」 | **要素** | 八十八町的 7 个区域是同级生2 的内容 |
| **事件触发器**（条件 → 触发 → 后果 → flag） | **机制层** | 这是个通用结构 |
| 「32 个事件具体是什么」 | **要素** | |

### 2.2 NSFW → **切一刀**

| 部分 | 归属 | 为什么 |
|---|---|---|
| **门槛框架**（阶段 → 允许什么行为 → 不满足时怎么办） | **机制层** | 这是「权限判定」这个通用能力 |
| 「分几个阶段、每阶段允许什么、阈値多少」 | **要素** | euphoria 是「密室强度」，同级生2 是「关系 10 档」 |
| **身体状态容器**（可累加、可衰减、能触发描写） | **机制层** | |
| 「哪些部位、写什么反应」 | **要素** | 这就是我们刚审的 D2 组（敏感带等） |

### 2.3 怀孕系统 → **不是机制，是要素** ⚠️

**这是最需要纠的一个例子。**

- ❌ 「怀孕系统」进机制层 = **机制层裹了具体内容**。euphoria 底座（密室、无怀孕设定）就得带着一个用不上的系统 → **违反判据 1**
- ✅ 机制层提供的是 **「生理状态机」**：
  ```
  一个有周期的、可累加的状态
    ├─ 累加条件（什么行为会推进它）
    ├─ 周期（多少步结算一次）
    ├─ 阈值（到什么值触发什么）
    └─ 不可逆性（触发后能否清除）
  ```
  然后：
  - **同级生2 底座**填：`怀孕 = { 推进: 无保护性行为, 周期: 月, 阈值: 触发怀孕线, 不可逆: 是 }`
  - **euphoria 底座**可以不填这个实例，或填别的（如 `伤痕累积 = { 推进: 被装置使用, 阈值: 触发身体崩溃 }`）

> **判据 2 的原话**：含「怀孕」这个词 → 要素。
> 机制层里不该出现「怀孕」两个字，只该出现「带周期的可累加状态」。

### 2.4 技能 → **切一刀**

| 部分 | 归属 |
|---|---|
| **判定引擎**（能力值 vs 要求值 → 分档 → 结果） | **机制层** |
| 「有哪些技能、默认值多少、哪些动作需要哪个技能」 | **要素** |

### 2.5 属性 → **切一刀**

| 部分 | 归属 |
|---|---|
| **数值容器 + 分档 + 阈值触发 + 更新幅度约束** | **机制层**（同级生2 的 `变量变化幅度控制` 就是这个） |
| 「有哪些属性、0-100 还是 -100~100、多少算高」 | **要素**（同级生2 的 6 属性是它的实例） |

## 三、机制层的真实形态 —— 不是「一堆规则」，是「可填的表」

这是最关键的一层认知，也是最容易做错的地方：

```
机制层 = 引擎能力 + 契约声明（schema）

┌─ 引擎能力（EJS 函数 / 代码，不含内容）
│   ├─ 时间推进器
│   ├─ 状态机（可累加 / 有周期 / 阈值触发 / 可不可逆）
│   ├─ 判定引擎（LCG 骰子 + 能力值 vs 要求值 + 分档）
│   ├─ 加载纪律（prompt 预算 + 底座门控 + EJS 裁剪）
│   └─ 护栏（防口胡校验 + 变量幅度控制）
│
└─ 契约声明（表，强制底座填）
    ├─ 表1 · 时间怎么切
    ├─ 表2 · 要追踪哪些状态（初值 / 增长条件 / 阈值 / 含义）
    ├─ 表3 · 有哪些判定动作（需要什么能力 / 什么门槛）
    └─ 表4 · NSFW 阶段表（阶段 → 允许行为 → 拦不住时怎么办）

底座 = 填这四张表 + 提供内容条目（女角 / 地点 / 事件 / CG）
```

**「模组层填要素就好」这句话要补一个前提：机制层得先给出「表」。**
没有表的机制层 = 一堆散文规则，填的时候只能靠 AI 猜 → 就会长出同级生2 现状那种东西
（70 字段镜像、24 维属性、1400 个变量位）。

## 四、按 skills 验证这个分层

**skills 本身就是这个分层的实例**，而且是现成的范例：

| skills 里的东西 | 对应本文的哪一层 |
|---|---|
| `tavern-cards/scripts/*.mjs`（configure / forge / 校验） | **引擎能力** |
| `references/requirements/`（需求对齐表） | **契约声明** |
| `references/type/state.ts`（`part` / `strategyThresholds` / typeLists 的 schema） | **契约声明** |
| `references/contents-creation/character/basic-info.md` | **「要素该怎么填」的规范**（规定外貌只写「能认出她」的特征，不规定写什么） |
| `references/contents-creation/character/tri-faceted.md` | 同上（规定三面性要「触发条件/能量/语料/身体/功能」五部件） |
| `创作规划.yaml` 的 `characters` / `entries` / `mvu` | **表** —— 填表就是「填要素」 |
| `references/configuration.md`（`configure` 从 entryManifest 自动推导所有运行时字段） | **引擎能力**（自动推导 = 不需要人填细节） |

**skills 的做法本身就是答案**：
- 它**不写内容**（不告诉你女角叫什么）
- 它**只规定「要素怎么填」**（外貌怎么算合格、三面性要有几部件）
- 并**自动推导能推导的部分**（position / strategy / order 由 `configure` 算，不用人填）

> 所以「机制层做通用、模组层填要素」在 skills 里的对应说法是：
> **机制层 = 推导规则 + 校验规则；模组层 = 填 `创作规划.yaml`。**
> 这正好解释了我们发现的所有问题的共同病根 ——
> 原卡**绕过了推导**（手工填 `index.yaml` 的投放字段），**也没有校验**，
> 所以长出了 12 条 depth 违规和 1400 个变量位。

## 六、四张表的具体形态（待细化）

按这个框架，机制层要交付的是四张表。以下是草案骨架，具体字段待细化：

### 表1 · 时间
```
时间单位:     <回 / 层 / 时段 / 天>       ── 推进的最小单位
单位上限:     <每单位最多几层>
大单位:       <几天一轮 / 一关几段>
推进者:       [她, 日历, 系统]           ── 谁能推动时间
不可阻挡:     <哪个角色会无视一切推进时间>
```

### 表2 · 状态
```
状态名:       <如 好感度 / 反抗值 / 怀孕>
初值 / 范围:
增长条件:     <什么行为推进它>
衰减条件:
周期:         <多久结算一次，没有则不填>
阈值:         <到什么值触发什么>
不可逆:       <触发后能否清除>
玩家可见:     <显示在哪 / 不显示>
它的意义:     <改变了玩家的什么体验>   ← 用户定的第三问，必填
```

### 表3 · 判定动作
```
动作名:       <如 牵手 / 告白 / 潜行>
需要的能力:   <来自表2 的哪些状态>
要求值:       <阈值>
门槛:         <关系阶段 / flag>
失败后果:
```

### 表4 · NSFW 阶段
```
阶段名 / 递进条件:
允许的行为:
拦不住时:     <强制推进 → 什么后果>
```
